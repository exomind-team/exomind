## 先假设当前方案错误：最强反对意见与反证

| 反对意见 | 实际证据/反例 | 本轮选择与边界 |
|---|---|---|
| 增加合同只会增加“绿色表演” | 把三个合同场景删至一个，CLI 1.4.0 plan 仍退出 0/ready，需求与 work unit 各报 3；旧接纳器不比较该缺口 | 增加单叶试点数量一致检查，真实 JSON 及两条先红后绿回归；数量不等于语义覆盖，不能泛化为全部意图完整性 |
| 一次任务白名单变成永久架构政策 | 初版 CI 无条件把任意 Beta diff 交给同一任务 Allowed Changes；合法的新文档/模块需要不断扩白名单 | 默认只跑持续行为约束并记录来源，任务边界显式 `--check-boundaries`；未检查状态外显，不静默冒充通过 |
| 报告的提交身份并非实际测试来源 | 初版 `--base` 只取提交 diff，仍执行共享工作区代码 | clean commit 模式拒绝 staged/unstaged/untracked；临时 Git fixture 和公开入口拒绝证据均保留 |
| 工作区会在运行中变化 | 本轮初验执行期间主代理编辑了合同，初验仍绿且记录较旧 hash | 初验不算最终证明；增加开始/结束来源指纹，受控新增文件后 29 项业务回归仍过、最终以 source-stability 拒绝；不能检测改后又原样恢复的所有竞态 |
| 新检查会诱导反复构建并占满磁盘 | 多个冷 target/staging、长命令重复启动与本机资源压力已有记录 | 共享外部 cache、单重任务、自有 Job、增占用前空间检查；不加巡检守护，不把遥测/面板变成额外空闲负担 |
| 几条测试的名称会被当成整套验收 | 当前试点不测全部 peer/original/Android/energy；原件 UI 测试不能验证实际字节 | 保留 source-regressions-only 与 notAssessed；未确认 branch protection，不宣称 CI 红灯阻止所有 push |
| 删历史代码最快降低复杂性 | Alpha仍有配置入口，Beta仍显式恢复旧草稿，wire generation仍严格解析；旧Main模型仅历史测试使用 | 保留活跃边界；只移出历史模型、删无消费者转发循环并保留拒绝语义测试，不重写或删除旧数据 |

更小的方案：已确认要求 → 明确所有者 → 有效失败反例 → 按风险分层验证 → 绑定输入/候选的证据。
每增加一条自动规则都要能说明捕捉哪类错误、误报边界和维护成本。不扩成全仓常驻控制平台。

## 二阶与三阶影响

| 改动 | 直接效果 | 二阶影响 | 三阶风险/维护选择 |
|---|---|---|---|
| Native持业务生命周期 | 主窗离场仍可操作 | 多窗口状态协调更清楚，UI不能自行取消业务 | 不能靠永不停止观察实现；区分绘制观察和服务任务，保留明确退出/撤销 |
| 持久 intent / CAS / 固定回执 | 迟到结果不覆盖新稿 | 重试先查证、输入失败可恢复，用户更少重复点击 | 增加私有状态/迁移义务；限定 owner、字节和保留策略，不让所有状态跨端同步 |
| 多来源证明与游标 | 跨端块父节点可解释 | 载体与作者分开，撤销和中转更可信 | 协议状态更多；UI渐进披露且分层说明，不能为“丝滑”代签/降级授权 |
| 自动原件获取 | 减少猜设备的操作 | 更多网络/磁盘、持有端可用性变成体验因素 | 有界队列、每原件资格和策略，不用整档案健康误阻断独立原件；自动下载不自动执行 |
| 更细的任务反馈 | 用户能判断等待/恢复路径 | 可能减少重复提交与误操作，需实测 | 文案/刷新噪声和采样成本可能增加；固定槽位、事件驱动、按注意范围披露 |
| 合同与CI | 固定回归可重复运行 | 新人能循证接手，失败可定位 | 过度白名单/同数异义/契约变更游戏化；人审语义，机器只报其能证明的部分 |
| 测试与源码指纹 | 减少错版本证明 | 本地边改边测会明确失效 | 失效结果须保留而非丢弃；不自造隔离平台，不把未完成/陈旧计为产品失败 |
| 两版本产物保留 | 释放重型历史产物 | 后续复现依赖精确源码、锁、配置、签名来源 | 不承诺字节重现；保留小型索引，未知归属/运行中产物不删 |

## 跨领域对照与取舍

这是一轮方法适用性分析，不把外部行业流程或认证要求引入日常开发。

- **实验设计**：多来源 memo 测试曾被 discovery 强制同步掩盖。撤掉混杂因素、固定同一问题的
  合成反例，比加更多随机集成操作更能区分根因。默认不把测试重试变成产品重发。
- **系统控制/STPA**：检查“哪一个控制者，在什么上下文，过早/过晚/持续提供或撤回了动作”。
  对应隐藏视图停观察、列表行取消原生导出、迟到 ACK 清新稿。借用控制关系和时序检查，
  不宣称外心取得安全认证。[MIT STPA/CAST 手册](https://www.mit.stamp-institute.com/handbooks)
- **SRE/CAPA**：一次修复须关联贡献因素、可执行改进和后续验证；复盘也有成本，只对重复或高风险
  边界启动完整闭环，避免报告本身成为 toil。[Google SRE 复盘实践](https://sre.google/workbook/postmortem-culture/)
- **级联故障/资源准入**：重试、观测和后台并行都可能放大负载。复用已有有界重试与准入；
  网络认证拒绝不当成普通可重试 EOF，不照搬服务端每分钟重试数字。
  [Google SRE 级联故障](https://sre.google/sre-book/addressing-cascading-failures/)
- **渐进迁移**：旧/新并存的过渡结构可以是降低风险的有意代价；要有退出条件，不能只为目录整洁
  一次性重写。外心按配置和数据隔离而非新建代理层照搬模式。
  [Strangler Fig](https://martinfowler.com/bliki/StranglerFigApplication.html)

## 执行与审视记录

- 原定目标：追踪0.6历史/失败共因，反证现方案，降低接手成本，把可预防问题落成最小规则/检查。
- 已完成：三路只读调查，主代理核对关键来源，当前文档/历史夹具整理，门禁反例与补强。
- 未作为本轮承诺：物理设备、能耗根因、旧来源签名补齐、全库重构或发布。

| 严重程度 | 具体问题/方法失误 | 修正与证据 |
|---|---|---|
| 必须改正 | 原适配器把ready当成场景覆盖完整，少看 requirement/work unit/contract 的关系 | 真实CLI删减计划仍ready；现接纳器明确拒绝；同数异义仍需人审 |
| 必须改正 | `--base`记录提交范围却执行可变化工作树，来源与结论脱节 | 三类脏输入回归和公开入口失败；本地默认保留worktree范围 |
| 必须改正 | 主代理本轮初验时继续编辑合同，混合输入却绿 | 初验降级为调查记录；受控新增文件后最终检查拒绝，标记陈旧而非产品失败 |
| 应当改正 | 一次任务的允许范围被长期套给所有CI，增加无关合同维护 | 显式opt-in且notAssessed外显；不靠放宽 `**` 解决 |
| 应当改正 | 架构和B1 README仍声明失效的唯一真源/Main-only | 更新现有入口，历史由Git保留，旧执行模型迁为历史夹具 |
| 保留限制 | 分支保护、语义完整性、执行中改后恢复竞态、设备/能源等未由这些检查证明 | 明示边界，不增加一个更大“总绿灯”掩盖 |
