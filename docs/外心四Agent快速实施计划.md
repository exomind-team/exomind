## 1. 一、四个Agent职责定义

### 1.1. 外心 (ExoMind Core/Governor)
**角色**: 系统调控中枢,方向盘+刹车

**核心职责**:
- 🌅 开机调度: 决定今天偏推进/修复/学习/校准
- 🚦 输出治理: 拦截副作用(羞耻、控制感、负担)
- 🌙 关机校准: 总结有效/无效建议,调整明天策略
- 🧱 防膨胀: 保持主循环极简

**关键接口**:
- 接收各Agent的输出并评估副作用
- 调度其他Agent的优先级和活跃度
- 维护系统整体"可持续性"

---

### 1.2. 任务系统 (Task Recommendation Agent)
**角色**: 状态×需求×项目×兴趣的智能匹配引擎

**核心职责**:
- 推荐此刻最值得做的1个任务 + 1个备选
- 解释取舍: 为什么适合你现在的状态与长期方向
- 🧭 用户主导: 建议可拒绝,你做最终选择
- 与Governor配合: 低状态时自动收缩任务强度

**数据依赖**:
- 当前状态(能量、焦虑度、时间可用性)
- 项目列表(来自PARA/Projects)
- 历史偏好(从Review Agent获取)
- 目标优先级(从Growth Coach获取)

**产出物**:
- 正计时/倒计时记录
- 任务执行EventLog
- 能量变化跟踪

---

### 1.3. 目标身心觉察 (Growth Coach)
**角色**: 意识×潜意识的成长教练

**核心职责**:
- 🪞 证据三角: 行为证据+感受证据+叙事证据
- 🌊 潜意识模式识别: 回避、完美主义、拖延、羞耻循环
- 🔧 最小改写练习: 3-5分钟,可拒绝
- 📍 插槽位置: 任务选择时、复盘之后

**输出形式**:
- 成长洞察(基于证据,不贴标签)
- 练习建议(短、低风险、可坚持)
- 状态匹配(帮助任务系统做推荐)

---

### 1.4. 行动反馈Agent (Review Agent)
**角色**: 极简复盘,沉淀可复用策略

**核心职责**:
- 每次尝试后只产出四行:
  - ✅ 哪里有效
  - 🧱 哪里卡住
  - 🔧 下次改一条策略
  - 🚫 避免一条做法

**数据流向**:
- → Governor: 提供有效性反馈
- → 任务系统: 提供任务偏好数据
- → Growth Coach: 提供行为证据

## 2. 二、技术方案选择: 混合架构

### 2.1. 方案对比

| 维度 | Obsidian插件 | 独立软件 | 推荐 |
|------|-------------|---------|------|
| **开发速度** | 快(7天MVP) | 慢(2-3周) | ✅ 插件 |
| **数据集成** | 原生Markdown | 需适配 | ✅ 插件 |
| **手机支持** | Obsidian Mobile | 需独立开发 | ❌ 插件 |
| **离线能力** | 完全离线 | 完全离线 | ⚖️ 平手 |
| **扩展性** | 受限于Obsidian API | 完全自主 | ✅ 软件 |
| **维护成本** | 低(Obsidian生态) | 高(全栈) | ✅ 插件 |

### 2.2. **推荐方案: 分阶段混合架构**

#### 2.2.1. 阶段1: Obsidian插件 (第1周,立即可用)
**实现范围**:
- ✅ 正计时/倒计时功能
- ✅ 数据自动保存为Markdown(EventLog格式)计划
- ✅ 桌面端完整可用
- ✅ 简易仪式模板(开机/关机)

**技术栈**:
- TypeScript + Obsidian Plugin API
- 数据格式: YAML frontmatter + Markdown

**为什么先做插件**:
1. **7天内可交付MVP** - 验证闭环有效性
2. **数据天然集成** - 直接写入笔记库,无需适配
3. **利用Obsidian Mobile** - 手机端基础可用

#### 2.2.2. 阶段2: 手机外部缓冲区 (第2-3周)
**实现范围**:
- 📱 手机端独立App(React Native)
- 📤 本地存储 + 定时推送到Git仓库
- 🔗 与Obsidian笔记库自动同步

**技术栈**:
- React Native (一次开发跨iOS/Android)
- 本地数据库: SQLite
- Git同步: libgit2 或简易HTTP推送

**为什么需要独立App**:
1. **替代微信外部缓冲区** - 微信分享直接保存
2. **离线优先** - 无网络也能捕获信息
3. **后台自动同步** - 无需手动操作

## 3. 三、快速可用实施计划

### 3.1. 核心原则(来自外心Spec)
- ✅ 默认短: 仪式不超过10分钟
- ✅ 默认可跳过: 不做强制
- ✅ 失败不羞辱: 失败不记录为"失败",只记录"未执行"
- ✅ 只改一条: 每次复盘只改一条
- ✅ 建议可拒绝: 推荐只是建议
- ✅ 最小干预: 宁可少做,不制造负担

---

### 3.2. **第1周: 手动模拟验证闭环 (Wizard-of-Oz)**

**目标**: 不写代码,先验证闭环是否有效

| 日期          | 任务       | Agent        | 输出物                                                    | 验收标准           |
| ----------- | -------- | ------------ | ------------------------------------------------------ | -------------- |
| **Day 1**   | 恢复仪式模板   | Governor     | `template-boot-morning.md`<br>`template-boot-night.md` | 开机5分钟内,关机10分钟内 |
| **Day 2**   | 手动跑一次主循环 | 任务系统+Review  | 今日任务选择记录<br>极简复盘(4行)                                   | 能推荐1个任务+1个备选   |
| **Day 3**   | 证据三角练习   | Growth Coach | 行为/感受/叙事记录<br>1条洞察+1个练习                                | 基于真实数据,不空话     |
| **Day 4**   | 整合仪式闭环   | 全部           | 完整一天的闭环记录                                              | 开机→主循环→关机无中断   |
| **Day 5-7** | 连续3天验证   | 全部           | 3天日记记录                                                 | 每天执行,记录体感      |

#### 3.2.1. Day 7验证问题 (只问6题,来自外心Spec)
1. ✅ 我更少无谓点开了吗?
2. ✅ 我更快开始做事了吗?
3. ✅ 我更容易恢复上下文了吗?
4. ✅ 我开始复用下次方案/避免项了吗?
5. ✅ 我更清楚自己的状态/触发器/模式,并更快回到可行动了吗?
6. ✅ 我睡前更能放下,手机更可控了吗?

**决策点**:
- **如果体感变好** → 进入第2周(插件化)
- **如果变负担** → 立刻减法:删步骤,不加功能

---

### 3.3. **第2周: Obsidian插件MVP (核心功能)**

**前提**: 第1周验证通过

#### 3.3.1. Agent 1: 任务系统插件

**功能范围**:
- 正计时/倒计时功能
- 自动保存为EventLog格式
- 简易任务推荐(基于当前状态)

**数据格式**:
```yaml
---
type: task-session
id: evt-2026-01-13-001
ts: 2026-01-13 10:00:00
task: "外心任务系统开发"
status: in-progress
timer_type: focus  # focus/break
duration: 25m
energy_before: 7/10
---

## 任务记录
开始时间: 10:00
结束时间: 10:25
实际时长: 25分钟

## 行动记录
- [x] 完成插件骨架搭建
- [ ] 实现计时器UI
```

**技术要点**:
- 插件类型: Obsidian Editor Plugin
- UI库: Svelte (Obsidian推荐)
- 数据持久化: 直接写入Markdown文件到`2-个人状态与历史记录/任务记录/`

---

#### 3.3.2. Agent 2: Review Agent (复盘助手)

**功能范围**:
- 极简复盘模板(4行)
- 自动插入到任务记录末尾
- 汇总到日记文件

**模板格式**:
```markdown
## 🔁 今日复盘
✅ **有效**: [一句话]
🧱 **卡住**: [一句话]
🔧 **下次改**: [一条策略]
🚫 **避免**: [一条做法]
```

---

#### 3.3.3. Agent 3: Growth Coach (成长助手)

**功能范围**:
- 证据三角模板
- 插槽位置: 关机仪式时触发
- 可选模式(默认关闭)

**模板格式**:
```markdown
## 🧘 成长总结
**行为证据**: [我实际做了什么/没做什么]
**感受证据**: [情绪、身体感受、能量变化]
**叙事证据**: [我如何解释今天的经历]

**假设**: [可能的模式,用假设语气]
**练习**: [3-5分钟的练习建议,可拒绝]
```

---

#### 3.3.4. Agent 4: Governor (系统调控)

**功能范围**:
- 检查仪式完成情况
- 拦截过长输出(超过200字提醒)
- 失败不羞辱记录

**实现方式**:
- 状态栏提示
- 每日报告(可选)

---

### 3.4. **第3周: 手机外部缓冲区App**

**前提**: 第2周插件基本可用

#### 3.4.1. 核心功能
1. **信息捕获**
   - 微信分享接入
   - 快速笔记
   - 语音转文字(可选)

2. **本地存储**
   - SQLite数据库
   - Markdown预览

3. **Git同步**
   - 定时推送到个人仓库
   - 增量同步
   - 冲突提示(手动解决)

#### 3.4.2. 数据流向
```
手机App → 本地SQLite → Markdown导出
  → Git Push → 个人仓库 → Obsidian同步
  → Scout Agent处理
```

## 4. 四、数据格式规范 (EventLog标准)

### 4.1. 事件类型定义

#### 4.1.1. 任务事件
```yaml
---
type: task
id: evt-YYYYMMDD-NNN
ts: YYYY-MM-DD HH:mm:ss
task_id: "任务名称"
status: pending/in-progress/completed/cancelled
duration: Xm
energy_before: X/10
energy_after: X/10
---
```

#### 4.1.2. 复盘事件
```yaml
---
type: review
id: evt-YYYYMMDD-NNN
ts: YYYY-MM-DD HH:mm:ss
linked_task: evt-YYYYMMDD-NNN
effective: "有效点"
stuck: "卡住点"
improve: "改进策略"
avoid: "避免做法"
---
```

#### 4.1.3. 成长事件
```yaml
---
type: growth
id: evt-YYYYMMDD-NNN
ts: YYYY-MM-DD HH:mm:ss
behavior: "行为证据"
feeling: "感受证据"
narrative: "叙事证据"
hypothesis: "模式假设"
exercise: "练习建议"
---
```

## 7. 七、风险与应对

### 7.1. 风险清单

| 风险 | 严重程度 | 应对策略 |
|------|----------|----------|
| 仪式再次中断 | 高 | 模板极简化,默认5分钟内完成 |
| 模板变成负担 | 高 | Governor原则: 默认短、可跳过、失败不羞辱 |
| 插件开发延期 | 中 | 手动模拟验证通过后再开发,避免过早优化 |
| 手机App过于复杂 | 中 | 第一版只做捕获+Git推送,不做花哨功能 |
| 数据格式不一致 | 中 | 制定EventLog标准,所有Agent遵守统一格式 |

### 7.2. 核心治理原则 (Governor)

来自外心规格书:

```
✅ 默认短: 仪式不超过10分钟
✅ 默认可跳过: 不做强制
✅ 失败不羞辱: 失败不记录为"失败",只记录"未执行"
✅ 只改一条: 每次复盘只改一条
✅ 建议可拒绝: 推荐只是建议
✅ 最小干预: 宁可少做,不制造负担
```
