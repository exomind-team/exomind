# Issue #73 冥想场景：倒计时结束提示音（前端）计划

Issue: https://github.com/exomind-team/exomind/issues/73  
关键评论（实现依据）: https://github.com/exomind-team/exomind/issues/73#issuecomment-3896523791

## 背景与问题

- 当前 `TimeBlockWidget` 倒计时结束时会弹出反馈框，但没有「结束提示音」。
- Issue 诉求强调：倒计时结束播放特定提示音；可“延长计时”；只要没按结束不会自动结束，需要用户确认才会真正结束。
- 评论将需求拆为两部分：
  1) 倒计时结束提示音（一次性、偏长）
  2) “软结束”：倒计时到 0 后不立刻停止计时，而是继续计时直到用户确认结束（并在 0 点弹出反馈框）

## 范围与非目标

### 本次范围（纯前端）

- 在倒计时结束时播放提示音（可开关、可选预设）。
- 增加「倒计时结束后是否继续计时（软结束）」的前端选项，并按选项改变结束行为。
- 提供一组内置提示音素材（来自给定路径），统一以 kebab-case 英文命名，放入项目素材目录并以“预设列表”形式使用。

### 明确不做（本 Issue 后续/拆分）

- 用户上传自定义提示音（评论说明后续单独 issue，本 issue 仅预设）。
- 任何服务端/同步/存储结构变更（不新增持久化字段，不改 `ActiveBlockData`/存储 schema）。

## 交互与行为设计

### 新增配置项（仅组件内状态，不持久化）

在 `TimeBlockWidget` 的展开面板中（且仅倒计时模式显示）新增：

1. **提示音**：开/关
2. **提示音预设**：下拉选择（仅当提示音开启可选）
3. **倒计时结束后继续计时（软结束）**：开/关  
   - 说明：对应评论中的“软结束”。评论里「立即结束计时」的开关描述存在语义反转，本实现以“是否继续计时”做直观命名。

### 倒计时到 0 的行为（两种模式）

共同点：
- 当倒计时从 `>0` 跨过 `<=0` 的瞬间触发（避免刷新时 `0` 误触发重复提示音）
- 若「提示音」开启：播放所选预设音频（一次性，不循环）
- 打开反馈对话框

差异点：
- **硬结束（继续计时=关）**：计时循环停止，显示固定 `0:00`，强制停留在反馈流程（沿用当前 `ended` 行为）。
- **软结束（继续计时=开）**：计时继续运行，倒计时显示变为超时正计时（例如 `+0:12`），直到用户点击“确认结束/跳过”才真正 `endBlock`。

> 备注：软结束下计时的持续以 `endBlock()` 发生时刻为准，因此最终完成的时间块 `endTime` 自然包含延长时间；不依赖存储结构扩展。

## 素材准备（统一命名）

把用户给的音频复制到项目素材库目录（拟定：`src/assets/sounds/timer-end/`），并重命名为 kebab-case 英文文件名：

- `G:\\Downloads\\dang.wav` → `timer-end-dang.wav`
- `...\\Ring10.wav` → `timer-end-ring-10.wav`
- `...\\--sound-cow-mooing.wav` → `timer-end-cow-mooing.wav`
- `...\\passRound.wav` → `timer-end-pass-round.wav`
- `...\\levelup.ogg` → `timer-end-level-up.ogg`
- `...\\潜入北京航天中心 提示音.wav` → `timer-end-space-center-alert.wav`

并在前端维护一个预设表（`id/label/url`），供下拉选择与播放使用。

  - 倒计时结束分支：增加提示音播放、软结束超时计时逻辑

  - 新增 `TimeBlockWidget` 单测：倒计时结束时在开关开启情况下调用 `Audio.play()`；关闭时不播放；软结束时不进入 `ended` 且会继续累积超时显示（最小可测断言）

## 验收标准（可操作）

1. 倒计时模式开始后，时间归零时会自动弹出反馈框。
2. 若提示音开：归零瞬间播放一次所选提示音；提示音关则不播放。
3. 软结束关：归零后计时停止并保持 `0:00`，直到用户确认结束/跳过。
4. 软结束开：归零后计时继续，界面显示 `+m:ss` 形式的超时计时；用户确认结束/跳过后停止并结束时间块。
5. `bun test` 通过；`bun run build` 通过。
