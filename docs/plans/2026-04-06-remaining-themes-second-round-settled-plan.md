## 2. 统一语义基线

### 2.1 `node / actor / Agent`

后续文档统一按以下原则表述：

- `node`、`actor`、`Agent` 都是**方法论概念**
- 它们都不是对底层程序本体的硬分类
- 同一底层运行体可以同时被多个视角解释

其中：

- `node` 强调：
  - 网络位置
  - 连边
  - 工作台中的承载点
- `actor` 强调：
  - 消息收发
  - 输出传播
- `Agent` 强调：
  - 记忆
  - 提案
  - 调度
  - 资源治理

### 2.2 文档默认写法

后续文档默认写法收口为：

- **节点优先**
- **按需补充 actor / Agent 视角**

也就是说：

- 可以先按 `node` 看状态与连边
- 再按 `actor` 看消息参与
- 再按 `Agent` 看治理责任

不再使用以下旧写法：

- “`Agent` 在 `actor` 之上”
- “`actor` 是程序本体类型”
- “`Agent` 是程序本体子类”

### 2.3 信号网络文档措辞

在信号网络 `v1` 文档中，默认改用：

- **内建领域节点**
- **黑板节点**

只在需要强调消息传播时，再补充：

- 它在该处按 `actor` 视角理解

## 3. 独立集体记账系统第一阶段

### 3.1 权威账本形态

第一阶段的权威数据模型收口为：

- **事件账本 + 投影**

即：

- 原始层使用追加友好的文本格式
- 当前默认方向是 `JSONL`
- 账单表 / 平账表 / 统计视图是投影层，不是权威源

### 3.2 Git 协作语义

第一阶段默认采用：

- **一集体一私有仓库**
- 成员各自持有本地克隆

冲突处理顺序固定为：

1. 自动拉取
2. 自动重放 / 重试
3. 仍失败时再提示人工处理

### 3.3 仓库存储边界

Git 仓库中默认只保存：

- 权威事件层
- 少量必要元数据

进一步收口为：

- 权威事件文件按**年-月**分区
- 账单 / 平账 / 统计投影默认在本地派生
- 本地投影缓存**不写回权威仓库**

### 3.4 改账语义

第一阶段默认规则为：

- **未平账可改**
- **已平账只允许冲正 / 补记**

### 3.5 第一版功能收口

第一版优先承接：

- 手工快速记账
- 受控分类 + 自由备注
- 余额计算
- 人工确认平账

后置到下一阶段：

- 自动建议转账方案
- OCR / 附件识别
- 更复杂的审批式结算

### 3.6 UI / Agent 双入口

第一阶段保留双入口方向：

- 人类可在 UI 录入
- Agent 也可通过 API 协助录入

但边界固定为：

- Agent 默认只创建**入账草稿**
- 正式入账仍需人类确认

### 3.7 最小 API 面

第一阶段最小 API 面收口为：

- 查分类
- 建记录 / 建草稿
- 查余额 / 待平关系
- 记平账

### 3.8 最低审计字段

每条记账 / 改账记录至少带：

- 操作者
- 设备
- 时间

## 4. 多 Agent 第一阶段

### 4.1 总体定位

第一阶段仍然只做：

- **任务治理**

后续阶段再做：

- 面向人的服务员体系

### 4.2 固定角色编制

第一阶段固定为：

- `coordinator`
- `proposer`
- `reviewer`
- `retrospector`

其中：

- `coordinator` 常驻
- 其余角色按需唤起

### 4.3 协作介质

四角色之间默认主要通过以下中介协作：

- 任务
- 提案
- 黑板
- 事件日志
- 时间块

### 4.4 职责合同

`coordinator`：

- 分派与门禁优先
- 控节奏
- 先承担争议裁决
- 无法决断时再升级给人类

`proposer`：

- 起草和修订提案
- 负责形成 `pending proposal`

`reviewer`：

- 评论
- 批准或退回
- **不重写提案**

`retrospector`：

- 在执行完成后复盘
- 第一阶段优先读 `eventlog + timeblocks + tasks`
- 输出结构化复盘记录
- 暂时只给建议，不自动生成任务 / 提案

### 4.5 人类入口

第一阶段默认：

- **任务 / 提案表面优先**

而不是先做统一服务员入口。

- 先观测
- 先告警
- 不立即做硬门禁

### 5.3 人工干预策略

第一阶段默认采用：

- **人工手动补能**
- **人工手动唤醒**

### 5.4 记账粒度

模型资源账本第一阶段默认：

- **按 invocation 记主账**
- **按 turn 做主要聚合**

## 6. 对外文档与宣传生成

### 6.1 首要受众

第一阶段优先服务：

- **贡献者与技术早期用户**

而不是优先面向：

- 泛个人效率用户
- 组织级试点叙事

### 6.2 触发机制

对外文档 / 宣传草案默认只在以下条件下触发：

- **某个里程碑已经验证通过**

也就是说，需要至少具备：

- 对应 issue
- 测试证据或人工验收闭环
- 明确的 covered / not-covered 边界

### 6.3 第一批产物

第一阶段最优先的产物组合是：

- 里程碑说明
- README 更新草案
- Release / build 说明草案

### 6.4 发布门禁

第一阶段默认流程为：

1. Agent 生成草案
2. 草案附带证据引用
3. 人工审阅
4. 再发布到真实对外表面

### 6.5 发布落点与语言策略

第一阶段优先落点：

- issue 评论
- README
- Release 说明

网站更新后置到下一阶段。
