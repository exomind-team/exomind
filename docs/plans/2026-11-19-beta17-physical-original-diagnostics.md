## 升级与复测

1. 复核精确构建的来源、版本、ABI、Core schema、配置／锁文件 hash 与 Android 签名。
   保留 Beta16，下载后最多保留最新与上一候选。构建全部在 CI，避免本机完整链接压力。
2. 同签名保留数据更新平板，电脑使用同版候选及既有隔离 Host 根；不清库、不重新配对
   来遮盖失败。Core8→9 为受保护迁移；旧 Core8 peer 的严格 schema 拒绝是预期兼容边界，
   需要相应对端更新，不能降级身份检查或用旧二进制打开新 schema。
3. 沿用 Beta16 新建的合成联调档案及 8 KiB／9 MiB 两件原件。先读取并保留诊断快照，
   再复现一次获取；新进程可能没有旧内存错误，须标为新候选事件，不能从 SQLite 编造旧码。
4. 分别确认文字、typed timeline、可解释时间块、原件本机校验；取得原件后还须独立导出
   对 hash 和验证系统打开，不能以队列为空或按钮可点冒充字节到达。
5. 同版重跑断连／重启／已存在历史。Wi-Fi、EasyTier、ADB 转发、模拟器、物理设备和
   人审证据单列；辅助 TCP 或普通 TLS 预探测不能代替产品 pinned TLS／RPK 协议。
