## 1. 需求评审

### 1.1 用户需求确认

| 需求 | 解读 |
|------|------|
| **网页端** | 浏览器访问，无需安装客户端 |
| **多端适配** | 同一功能在不同端体验一致 |

### 1.2 合理性分析

| 维度 | 评估 | 说明 |
|------|------|------|
| **价值** | ⭐⭐⭐⭐⭐ | 降低使用门槛，扩大用户群体 |
| **技术** | ⭐⭐⭐⭐☆ | Tauri 支持导出 Web，已有基础 |
| **成本** | ⭐⭐⭐☆☆ | 需要额外开发 Web 适配层 |
| **优先级** | ⭐⭐⭐⭐☆ | 建议核心功能完成后实现 |

**结论**: ✅ 合理且有价值的需求，建议纳入路线图

### 2.2 各端差异分析

| 维度 | Tauri Desktop | Web Browser | Android |

| **离线能力** | 完全离线 | 需要 PWA | 完全离线 |
| **系统集成** | 高 (Tauri API) | 低 (Web API) | 中 (Android API) |
| **推送能力** | 系统通知 | Service Worker | 系统通知 |
| **存储** | 本地文件 | IndexedDB | 本地文件 |
| **语音** | WASM API | Web Speech API | Native API |
| **窗口** | 原生窗口 | 浏览器标签 | Activity |

## 3. 架构影响

### 3.1 现有架构适配

```
原架构：
┌─────────────────┐
│  Tauri Desktop  │  ← 仅桌面端
└─────────────────┘

扩展后架构：
┌─────────────────────────────────────┐
│           共享逻辑层                 │
│  ┌─────────────────────────────────┐│
│  │  API Gateway (Rust/Axum)       ││
│  └─────────────────────────────────┘│
│           │                         │
│  ┌────────┼────────┐                │
│  ▼        ▼        ▼                │
│ ┌─────┐ ┌─────┐ ┌─────┐           │
│ │Web  │ │ Tauri│ │Android│          │
│ │SPA  │ │Desktop│ │ App  │          │
│ └─────┘ └─────┘ └─────┘           │
└─────────────────────────────────────┘
```

### 3.2 新增组件

| 组件 | 说明 | 负责端 |
|------|------|--------|
| **API Gateway** | 统一入口，认证、路由 | 共享 |
| **Web SPA** | React 单页应用 | Web |
| **Tauri Desktop** | 桌面客户端 | Desktop |
| **Tauri Android** | Android 客户端 | Android |
| **同步服务** | 多端数据同步 | 共享 |

### 3.3 数据同步策略

| 场景 | Desktop | Web | Android |
|------|---------|-----|---------|
| **在线** | 直连 API | 直连 API | 直连 API |
| **离线** | 本地存储 | IndexedDB | 本地存储 |
| **同步时机** | 实时 | 页面活跃时 | 后台时 |
| **冲突解决** | LWW (Last Write Wins) | 提示用户 | 提示用户 |
