用户允许迁移式重写，但尚未授权删除日用数据或改变未决迁移/清理语义。保持现有改动，不自动reset、clean、stash或切换有未提交内容的分支。不要复用/移动已失败的v0.5.2标签，不向main发布，不擅自打新正式标签。

## 应用方式

交付物中的补丁只新增 `next/`，不修改根package、Rust workspace、原生签名、旧数据库或版本号。先确认当前开发工作区以及 `next/` 不存在；若已存在，不强制覆盖，按文件差异合并。

```sh
git status --short
git branch --show-current
git rev-parse HEAD
git apply --check /path/to/exomind-0.6.0-rebuild.1-dev.patch
git apply /path/to/exomind-0.6.0-rebuild.1-dev.patch
cd next
npm run verify
python -m unittest discover -s integrations/wincraft -p 'test_*.py' -v
```

`git apply --check`失败时先定位现有路径，不使用reject/强制覆盖作为默认做法。也可将repo-overlay/next复制到明确不存在的目标。校验交付根目录SHA256SUMS，避免把另一个包当本轮候选。

## G0：本机可运行与窗口交互

使用全新合成目录，不能把旧AppData路径传给候选：

```sh
node runtime/cli.mjs --data-dir .local/acceptance-a --name "验证A" --port 19490 --open
```

先用实际浏览器完成：记录→刷新→重启读取，中文输入法/粘贴截图/多文件，时间块开始/备注/结束/追加反馈，当前状态与数据库一致，搜索与加载历史后不跳动，窄屏动作完整。输入/请求/关闭面板之间的迟到回执不可覆盖新状态。

可选自动化脚本：

```sh
# 仅在隔离的开发环境安装可选验收依赖；它不是产品运行依赖。
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tools/browser-acceptance.mjs
```

也可使用已有受管理的Playwright环境，通过允许的浏览器执行。不要绕过浏览器/组织安全策略。制作环境导航被`ERR_BLOCKED_BY_ADMINISTRATOR`阻止，所以本包没有已通过的真实浏览器E2E证据。修UI必须更新脚本并在这里实跑；语法检查不够。

## G1：身份、重试与本机恢复

两个独立Runtime，分别独立目录；UI关闭也能运行。测试新装配对、已配对重启、配对响应丢失重试、端点换IP、暂停/恢复/撤销。观测身份、凭据、cursor和记录，不只看“已配对”。

同时输入一条记录、回执丢失、重复请求、同ID异内容、同时间块离线两次结束，以及关进程后的重开。比对精确操作ID与payload/附件哈希。若只测SIGKILL，报告为进程崩溃测试，不写成掉电安全。

源码进程测试可在没有UI时复跑。Windows须额外测实际文件锁、持久化权限、rename/fsync、杀进程与PID复用。并发启动同一目录、目录放网络盘均不是受支持的日用方式。

## G2：LAN／EasyTier／Android

先原生LAN，再EasyTier直连，再中继和切网。记录连接可达、认证、页补齐、附件完整、页面显示分别耗时。未经校准跨机时钟不可直接相减宣称单程延迟；测本机单调时间到对端落盘回执。

至少：两端在线、B离线A写100条、B返回、传附件时新文字写入、双方改状态、IP更换、VPN冲突、Android熄屏/唤醒/切网。输出median/P95/P99/失败比例、语料大小、设备、网络路径和版本；不能把本包loopback功能测试当真实网络基准。

**当前无APK。** 不要为了出现“手机已验证”的字样，把手机浏览器访问PC服务等同手机本地离线实例。那只是远程客户端。必须决定真实移动端Runtime部署与后台生命周期后，才能验收手机独立记录和断网补齐。

## G3：总结与外部组合

用合成记录接实际Magpie/模型，核对URL、模型、密钥、请求格式、代理是否生效与计费。验证等待模型、读取失败、超过100条、部分上下文、休息/生活时间块、无成果、取消迟到结果与结束分叉。

结构化引用通过不等于内容正确。人工逐句核对事实/推断/缺口。附件当前只送元数据，不能写“已读图”。模型调用失败必须可见且有预算，不循环无上限重试。

WinCraft只读提供者先按INTEGRATIONS启动，核对真实悬浮窗、来源断开、Host重启和租约。当前没有可写卡片，不把它误写成“已迁走全部工作台”。Obsidian自动写入尚未实现，不在这轮未经边界决策直接扩展双向同步。

## 原生落地决策：不要并行养两份真相

本候选可以作为可运行规范与测试基座，但不因本轮选择Node就默认最终架构。两条可裁路径：

A. 保留Node作桌面sidecar：先验证安装体积、进程托管、启动/退出、资源、凭据和更新；Android另需可行运行方案。若仅解决桌面不能声称全平台完成。

B. 将已验证核心移回Rust：保持协议与不变量，用本包数据夹具/跨进程测试验证新实现。优先Store/Blob/Sync/Harness的责任边界，不把整个旧RT的任务/PTY/Archive OS搬回来。阶段内不能让两套Runtime同时写一个库或拥有同一设备身份。

这一步需维护者明确技术取舍。无论选哪条，先保留新候选独立运行，再逐项接回托盘/快捷唤起/平台壳；不要立刻替换用户日用程序。

## 旧数据与发布

旧版数据库只读盘点先行，确认空间映射、原ID冲突、时间单位、来源与摘要是否完整。用户尚未决定导入范围，本包不提供猜测型迁移。新快照restore只适用于本协议，与旧数据搬迁是两件事。

完成G0–G3之后再讨论dev默认入口切换、精确候选Windows/Android/macOS/Linux构建及发布。真实升级与新装分开验收，不凭成功编译代替用户故事。初期只提交next/及必要引用，不把临时db、token、截图缓存、pycache、node_modules加入Git。
