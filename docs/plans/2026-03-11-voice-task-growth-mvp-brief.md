# ExoMind 周五可发布版本需求摘要

> 状态：需求收束稿  
> 日期：2026-03-11  
> 目标：在本周五前收敛出一个能真实帮助用户、可分享、可演示的最小闭环版本

---

## 1. 问题定义

ExoMind 这周不应该发布成“更复杂的看板”或“更多的 Agent”。

它要解决的核心问题是：

1. 用户脑子里有很多想法、任务、担忧和计划，但来不及整理。
2. 用户不知道自己现在有多少时间、多少精力，以及“此刻适合做什么”。
3. 用户进入专注前不清楚目标，结束后也不知道如何验收成果。
4. 用户和 Agent 协作时，不知道哪些应该自己做，哪些可以交给 Agent 在后台处理。
5. 用户需要一个始终以“人”为中心、但能持续接住输入并帮助整理的系统。

一句话说：

> 用户真正缺的不是更多功能，而是一个能把“脑中的混乱”快速收束成“现在能做什么”的系统。

---

## 2. 外部痛点依据

当前知识工作者的典型痛点，与 ExoMind 想解决的问题高度一致：

1. 工作极度碎片化，连续专注时间被大量打断。
   参考：Microsoft Work Trend Index 2025 指出，工作日被会议、消息和上下文切换不断切碎，用户很难保有完整注意力。
   来源：
   - https://www.microsoft.com/en-us/worklab/work-trend-index/breaking-down-infinite-workday

2. 决策疲劳会让人越来越难安排优先级、越来越容易拖延。
   来源：
   - https://www.ama-assn.org/public-health/behavioral-health/what-doctors-wish-patients-knew-about-decision-fatigue

3. 拖延很多时候不是懒，而是任务太模糊、情绪摩擦太高、启动成本太大。
   来源：
   - https://www.family-institute.org/behavioral-health-resources/how-make-sense-procrastination

这意味着，ExoMind 的首发价值不该强调“自治”，而该强调：

> 它能帮用户降低焦虑、降低启动成本、降低决策疲劳，并让用户重新聚焦于当下。

---

## 3. 产品定位

本周五可分享版本的定位建议：

> ExoMind 是一个语音驱动、以人为中心、由 Agent 在后台辅助整理和执行的生命成长工作流系统。

它不是：

- 通用任务管理软件
- 通用 AI 看板
- 纯自动化 Agent 平台

它是：

- 一个接住用户输入的系统
- 一个帮助用户理清“现在能做什么”的系统
- 一个把任务、专注、复盘和 Agent 协作串起来的系统

---

## 4. 周五版本的唯一主场景

### 主场景

> 我只管说话，ExoMind 帮我记住、整理、分类、给出当下建议，并在我做完后帮我复盘。

### 场景故事

用户半夜焦虑，脑子里很多事：

- 明天要推进哪个项目
- 哪些任务必须自己做
- 哪些可以交给 Agent
- 哪些只是想法，不是任务

用户不想再手动打开一堆软件整理。

他只需要对 ExoMind 说：

> “这周我要把 Phase 3 做出来，明天上午我大概有两个小时，另外还得准备周五的分享。”  
> “这个任务我自己做核心设计，整理材料和背景梳理可以让 Agent 帮我。”  
> “今天先做最重要的一个。”

然后系统完成：

1. 接住这段输入并落到事件日志。
2. 在后台把内容整理成结构化信息。
3. 识别哪些是任务、哪些是备忘、哪些是复盘线索。
4. 给出“现在能做的事项建议”。
5. 让用户选择一个或多个任务进入专注时间块。
6. 在结束时帮助用户验收、总结，并给出下一步。

---

## 5. 用户价值

这个版本对用户的价值，不是“AI 很聪明”，而是以下几点：

### 5.1 想法被接住

用户说的内容不会丢。

- 先记下来
- 再整理
- 再分类

这会直接降低“我脑子里东西很多但怕忘”的压力。

### 5.2 当下更清楚

系统不强调“今天所有能做的事”，而强调：

> 现在能做什么。

这是更符合真实执行体验的，因为用户当下的：

- 时间
- 精力
- 情绪
- 上下文

都在变化。

### 5.3 专注更容易开始

用户不需要自己先把任务完全规划好，才开始行动。

系统会帮用户从混乱输入中得到一个足够清晰的起点：

- 现在做什么
- 为什么是它
- 哪些部分可以让 Agent 先做

### 5.4 做完之后不空心

很多人完成事情后没有沉淀，第二天又重新焦虑。

ExoMind 要让一次行动结束后自动留下：

- 做了什么
- 没做什么
- 遇到什么阻碍
- 下一步是什么

这才是“生命成长系统”的价值，而不只是任务勾选。

## 6. 需求总结

### 6.1 输入原则

用户的默认交互方式是“说话”。

要求：

1. 用户只管说，不强迫用户先结构化思考。
2. 所有输入先进入事件日志。
3. 结构化整理、分类、任务化都在后台完成。

### 6.2 任务原则

任务系统必须以人为中心。

要求：

1. 任务是统一管理的，但要明确区分哪些由人主导、哪些由 Agent 辅助、哪些可由 Agent 后台执行。
2. Agent 不应替代用户做最终判断。
3. Agent 的输出在真正进入用户主任务前，应有一个可验收、可调整的回流过程。

### 6.3 建议原则

系统要给建议，但不能替用户决定一切。

要求：

1. 建议重点是“现在能做的事项”。
2. 建议要考虑时间、精力、身体状态、当前上下文。
3. 用户始终拥有最高调整权。

### 6.4 时间块原则

时间块是从“整理”进入“执行”的桥。

要求：

1. 用户可以从建议中选择一个或多个任务进入专注时间块。
2. 时间块结束后，系统自动触发验收和复盘。
3. 验收结果能重新影响任务状态和下一步建议。

### 6.5 Agent 协作原则

Agent 是后台协作者，不是替代人类的主人。

要求：

1. Agent 可以长期在后台处理任务。
2. Agent 处理结果要回流成用户可理解、可验收的内容。
3. 用户可以否决、修改、覆盖 Agent 的判断。
4. Agent 也应保持一定独立性，能明确指出自己的判断依据。

---

## 7. 本周五 MVP 边界

### 必须做到

1. 语音输入后，内容能稳定落到事件日志。
2. 后台能把输入整理成结构化内容。
3. 至少能识别出任务类输入，并形成任务。
4. 系统能给出“现在能做的事项建议”。
5. 用户能选择任务进入专注时间块。
6. 时间块结束后有可见的复盘/验收结果。

### 可以弱化

1. 不需要一开始就有复杂的多 Agent 自治。
2. 不需要先做通用看板。
3. 不需要复杂优先级算法。
4. 不需要一次性做完整人生管理系统。

### 不应该做

1. 不要让用户面对太多配置。
2. 不要让 Agent 逻辑压过人的理解。
3. 不要先追求“系统很复杂”，而忽略“用户今天能不能用”。

---

## 8. 现阶段最关键的后端闭环

根据当前代码库现状，周五版本最值得收敛的不是 UI，而是这条闭环：

`语音输入 -> 事件日志 -> 分类 -> 任务创建/更新 -> 现在能做的事项建议 -> 时间块 -> 复盘`

当前最关键的缺口是：

1. 统一输入归一化入口
2. 稳定的分类结果协议
3. 任务与时间块之间的统一状态流

---

## 9. 最终结论

本周五可发布版本，不该强调“我们有很多 Agent”，而应该强调：

> ExoMind 能通过语音，把用户脑子里混乱的想法接住，整理成当下可执行的事情，并在完成后帮助用户复盘和成长。

这是当前最强、最真实、也最容易被外部用户感知的价值。
