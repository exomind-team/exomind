# Beta 核心接缝与提交合同

## 责任与版本

正式本机核心为 `crates/exomind-core`，不依赖 HTTP、Tauri、旧 Mesh/Signal 或任务域。Node `next/` 只提供参考语义与反例。文字首单元数据库 schema 为1，原件单元升级为2；已知1→2先做一致备份，未知版本拒绝打开，不自动降级、清库或采用旧库。

宿主 `exomind-beta-host` 持有一个 Core；IPC 与 HTTP 共享同一个 `Arc<BetaHost>`。两种入口都经宿主检查当前会话资格后调用同一个 `Core::submit`，不得自己落库或回退旧 JSON/EventLog upsert。Tauri 本机提交直接经 IPC 进入该核心，不能经过系统代理、远端配对或网络可达性判断；Web API 是该提交边界的另一适配器。

## 已实施的首组类型与事务

| 对象 | 合同 |
|---|---|
| ProfileId / DeviceId / EventId / CommandId / AgentId | 区分的新类型，生成随机 UUID，拒绝 nil；名称不推导 ID。 |
| WriterContext | 受信宿主在本机创建，不反序列化；绑定当前 Core 生命周期、设备、档案、作者 ID/类别。载荷不能声明作者或把 Agent 冒充 human。 |
| CaptureCommand | `command_id,event_id,profile_id,occurred_at_ms,text,tags,originals`；原件组默认空，未知字段拒绝。非空原件组必须整组已验证，不悄悄丢项。 |
| 规范化事实 | 无原件保留原 `capture/1` 字节与摘要；有序原件组使用 `capture/2`。标签排序去重，正文逐字保留；摘要由 Rust 权威计算，不依赖前端自报。 |
| Receipt | command/event/profile、local_seq、事实摘要、`local_committed` 与重放状态；只证明本机提交，不证明对端已收到。 |

写入在 SQLite `BEGIN IMMEDIATE` 中完成：检查命令 ID 绑定 → 校验/追加事件 → 写回执 → 提交。返回后不再执行会把“已提交”变成“失败”的第二次文件写入。通知失败不能让调用者重新生成 ID。

同 command ID、同作用域/作者/事实重试返回原结果；任何绑定变化明确冲突。同 event ID 同事实可复用序号，异内容不可覆盖。local_seq 是入库顺序，与源端实际时间分离。SQLite 事务和唯一约束负责不同连接的并发，连接内 Mutex 只保护该连接。

本机管理工厂 `local_human/local_agent/create_profile` 不是外部鉴权 API，不得直接映射成匿名或普通 writer HTTP 端点。外部能力由宿主授予，设备间邀请/成员密钥与同步授权仍待 B2。

## 正在接入的宿主与平台边界

- Host 根只包含自己的锁库、鉴权库、私有连接描述和 `core/`；Core 仍只打开后者。未知文件、版本、损坏凭据不触发旧版回退。持有 SQLite 独立锁事务代表当前根所有权，不靠 PID 文件或杀其他实例抢占。
- 私有连接描述先原子持久化管理凭据，再将其摘要提交鉴权库；已有摘要但描述丢失/损坏时明确失败。Windows 使用当前用户受保护 DACL，Unix 使用目录0700/文件0600；不能将 Windows chmod 当作权限验证。
- 管理 Session 与档案 Session 分开。owner 只能管理档案和能力，不能直接提交；它可显式授予 observer、human、agent_note。普通会话不能自授 human，载荷不能声明作者。所有会话绑定 Host 生命周期；最终读写在同一宿主 gate 内重新检查授权、档案及撤销，停止后旧队列不能继续提交。
- HTTP `/beta/v1` 只监听 loopback；严格检查 Host，默认仅同源 Origin。Web 开发另行显式配置精确 loopback 前端 origin，预检只允许支持的方法/请求头，无通配或任意反射。正文有界；错误不包含凭据、原始正文或私有路径。
- Native Beta 使用 `com.exomind.app.v06.beta`、`beta.html` 和独立 builder，在构造旧 RuntimeProcessState 及加载旧配置前分流。仅注册 Beta 接口与所需平台显示命令，不暴露旧文件/事件覆盖、任务、提案或终端管理入口。本机主窗口私有会话不向 JS 发放 raw token；HTTP 监听失败与 IPC 记录资格分开。
- 原生默认数据位置为独立应用数据目录中的 `beta-host`；开发可用绝对路径 `EXOMIND_BETA_DATA_DIR` 覆盖，非法值拒绝。默认 HTTP 端口0由系统分配；显式 `EXOMIND_BETA_PORT` 格式错误不回落默认。退出先撤销本生命周期资格，再等待自身 listener 关闭；不得全局结束同名进程。

上述接入仍在验证；不能据此宣称 Android 后台、完整旧 UI 或正式 Beta 候选已验收。

## 档案资源和分页

`provision_profile(profileId,name)` 允许请求方在首次请求前保留 UUID，同 ID/同名重试幂等，异名明确冲突。同名不同 ID 始终是不同档案。档案清单属于 owner 管理能力，不能作为匿名发现接口。

事件页按 `local_seq DESC` 排序，`before` 为排他游标，首屏返回 `highwater`；后续页用 `through=highwater` 固定同一快照。页上限100，使用额外一条 lookahead 决定下一游标；不使用墙钟或正文排序。`search` 是大小写敏感的字面正文子串，SQL 通配符没有特殊含义。读取失败不能返回空集合。新增 query 测试比较250条同时间戳事实的完整 ID/payload、跨档案稀疏序号与分页中新事实隔离。

## 原件暂存、验证与事实引用

原始字节与进度使用同一 Core SQLite 保存，不增加 Windows 文件 rename 与数据库登记的第二套提交协议。`StageId/OriginalId` 为 UUID；begin 绑定档案、作者、预期完整 SHA-256、长度、名称和 MIME。名称和 hash 均不是读取凭据。未知格式及空文件保留原始字节，不执行、不递归抓引用资源。

单次写最多256 KiB，任意小 append 保持可用，但物理合并到固定256 KiB block。只允许未冻结尾块保留已确认前缀的增长；hash、字节与下一偏移同事务更新。单次范围读取最多256 KiB、至多涉及两行，并检查整块 SHA-256；坏字节保留，不能误称读取成功。

`uploading → frozen → verified / hash_mismatch` 是 operational state，不占事件序号。freeze 产生私有生命周期/generation ticket；独立只读连接在 Host gate 外逐批计算整件 hash，可取消；最终 seal 重新经过当前授权/generation 检查。撤销/停止不以已算好的 proof 自动豁免资格。stop 在 gate 外有界等待自有读连接退出，超时保留 root 所有权。

所有暂存状态/字节接口要求创建者 writer 与同档案。正式原件范围读取要求已有该档案事实引用；observer 不能读取私有暂存，即使底层 human principal 相同。capture 同一事务检查固定整组、追加事件/引用/receipt；任一未就绪则全部拒绝。已验证但未引用的原件仍保留，物理释放属于 B4.3 显式整理。

升级备份从独立只读连接读取已锁定的 schema1（包含 live WAL），转成自足 DELETE 模式单库并核验完整 payload，然后事务升级。已知初始化证据下主库丢失/空白、auth 丢失或绑定 device 不符均返回 `recovery_required`，不建新身份/空档案。当前未发布 schema2 的旧实验布局也明确拒开，不自动重排或清空；备份恢复是另一个显式流程。

浏览器先保留 preparing 选择意图，再由 strict IndexedDB 事务复制源 Blob、增量 hash、固定 descriptor，随后分块入 Core。提交冻结 text/tags/有序原件组和原 command/event/time/profile；下一稿增删不改变旧请求。结果未知先查原回执；未完成源丢失要求按 hash 重选，不能转纯文字漏件。Core verified 后仅释放已验证的浏览器临时重复源。基本 Blob 下载暂限64 MiB并核验整件 hash；这不是大文件流式导出或多GB吞吐已通过。

## 后续必须冻结的合同

- 成员与邀请：`profileId + deviceId`、密钥证明、一次性邀请、撤销与在途资格；同名档案不合并，非空 Q 不改 ID 加入 P。
- 原件：暂存/完成/引用分开，真实长度与 hash，固定整组提交；本机回执与对端原件回执不同。文件与数据库的崩溃恢复先于“已保存”。
- 复制：每成员有序流/epoch 与每 peer 游标；页和游标同事务，身份/代次/前缀不匹配拒绝；事件顺序不依赖墙钟。
- 时间块：全部开始/暂停/恢复/轮转/结束/反馈节点保留，确定性投影保留冲突原因；不恢复任务域。
- 模型：稳定任务、ownerDeviceId、来源快照、run 资格、取消/宿主停止围栏、迟到覆盖提示与按需更新；未授权原件正文不外发。
- 回收/清理：追加状态事实，本机释放与共享清理分开，显式清理保留最小来源痕迹；旧分页不复活已释放副本。

这些项仍按完整 Beta 计划的 B0→B5 推进，不以第一组类型或 SQLite 测试代替全部合同冻结、HTTP/UI 或真机验收。

## 首单元验证

`crates/exomind-core/tests/local_commit.rs` 通过公开 API 检查持久重试、ID 冲突、跨档案/生命周期、故障回滚、独立连接竞争、坏库/未知版本/只读拒绝与根隔离。真实 SQLite trigger 用于回执写入失败；进程恢复单独记证据，不将正常 Drop 回滚或文件占位当成崩溃验证。

```powershell
cargo test -p exomind-core --locked -j 1
cargo fmt --package exomind-core -- --check
```
