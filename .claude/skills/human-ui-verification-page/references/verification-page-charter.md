# 验收页生成章程

本章程规定“如何从一个计划或功能集合，生成一个可供人类逐项勾选的 HTML 验收页”。

## 目标

把“实现是否完成”转化为人类可以直接执行的 UI 检查流程。

最终产物不是抽象总结，而是：

1. 有标题
2. 有操作步骤
3. 有期望结果
4. 有“已验证”复选框
5. 有证据记录区
6. 有备注区
7. 有进度统计
8. 能在浏览器里直接打开使用

## 输入来源优先级

按下列顺序恢复验收范围：

1. 当前用户消息中明确列出的验收目标
2. 当前会话里已经完成的功能总结
3. 当前批次计划文档
4. 对应 issue / follow-up prompt / 设计文档
5. 现有 HTML 验收页或近似页面

如果范围仍不清楚，优先生成“可覆盖核心风险”的验收页，而不是停在分析阶段。

## 页面结构规范

推荐按以下结构组织：

1. Hero 区
   - 明确主题
   - 写清“这是一份人工验收页”
   - 提供进度条和全局按钮
2. 使用说明区
   - 告诉人类如何使用这份页
   - 说明如何记录证据
3. 准备项
   - 数据准备
   - 页面入口准备
   - 环境准备
4. 分组验收区
   - 按批次/模块/问题域分组
   - 每个验收项都要可勾选
5. 专项反馈区
   - 用于承接最新的人类反馈
   - 例如视觉、交互、边界条件

## 单个验收项必须包含什么

每一项至少包含以下 5 个部分：

1. 标题
   - 最好带 issue 编号或功能标识
2. 操作步骤
   - 明确到“点哪里、切到哪里、刷新吗、再看哪里”
3. 期望结果
   - 用于判断通过/失败
4. 证据区
   - 至少 2~3 个输入框
   - 可填写截图、录屏、对照页、结论
5. 备注区
   - 用于记录偏差、复现条件、下一轮修改建议

不要只写“测试这个功能”，那不是可执行验收项。

## 文案规则

### 标题

标题要直接体现目的，例如：

- 用人类 UI 系统性手把手检验核实计划实现程度的手段
- #640 模式切换人工验收页
- FH 批次人工验收清单

### 操作步骤

操作步骤要用第二人称隐含指令风格，让人一看就能做：

- 进入执行模式，单击任意节点，再点击画布空白处
- 把窗口缩到窄宽度，观察右上角工具栏
- 打开时间块详情页并向下滚动

### 期望结果

期望结果要可判定，不要写空话：

- 选中态立即消失
- 工具栏默认折叠为图标
- 反馈对话框只换行，不提交

## 交互要求

默认应实现以下页面行为：

1. 勾选框可切换
2. 输入框和备注区可编辑
3. 状态自动保存到 `localStorage`
4. 有总进度统计
5. 最好提供：
   - 展开全部
   - 收起说明
   - 清空勾选
   - 清空备注

## 技术实现要求

默认使用单文件 HTML：

- 内联 CSS
- 内联 JavaScript
- 不依赖构建工具
- 可直接双击打开

默认写入项目内 `temp/` 目录。

如果用户要求“打开给我看”，则写完后直接用系统浏览器打开。

## 视觉要求

验收页本身应满足：

1. 清晰可扫读
2. 不要像后台管理表格
3. 不要像 AI 生成的空洞卡片堆砌
4. 适合长时间打勾、填备注

建议风格：

- 暖灰/米白底
- 柔和玻璃卡片
- 低对比边框
- 强调色仅用于进度和勾选状态

## 模板使用规则

如需快速起稿，直接参考：

- [../assets/verification-page-template.html](../assets/verification-page-template.html)

使用模板时：

1. 保留页面骨架和本地持久化逻辑
2. 替换标题、副标题、分组标题、验收项内容
3. 根据当前批次增删区块
4. 不要机械复制模板里的示例文本

## 从计划到验收项的转换方法

把计划里的每一条功能点转成下面这个句式：

- 标题：`#编号 + 功能名`
- 操作步骤：用户如何触发
- 期望结果：用户看到什么
- 证据输入：截图/录屏/结论
- 备注：偏差和复现条件

### 示例

计划项：

> 执行模式空白点击取消选中

转成验收项：

- 标题：`#643 执行模式空白点击取消选中`
- 操作步骤：进入执行模式，先点节点，再点空白
- 期望结果：选中态消失
- 证据：前/后截图
- 备注：若 connect 模式受影响则记录

## 完成前自查

生成后逐项检查：

1. 没有遗漏准备项
2. 每个验收项都能独立操作
3. 每个验收项都能判断通过/失败
4. 页面打开后不依赖上下文解释
5. 即使换一个无上下文 Agent，也能看懂如何继续生成或修改同类页面
