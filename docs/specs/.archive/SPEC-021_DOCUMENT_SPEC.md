## 1. 文件命名规范

### 1.1 pm/ 目录文档命名

| 原文件名 | 新文件名 | 职责 |
|----------|----------|------|
| `PRD.md` | `PRD.md` | 详细需求 + 技术规格（保持大写，PRD 是标准术语） |
| `PRODUCT.md` | `roadmap.md` | 产品定义 + 路线图 |
| `CLAUDE.md` | `development.md` | 开发流程规范 |

### 1.2 命名原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **小写优先** | 尽量使用小写文件名 | `roadmap.md` |
| **标准术语** | PRD、API 等标准术语可大写 | `PRD.md` |
| **职责清晰** | 文件名反映文档职责 | `roadmap.md` = 路线图 |

## 2. 文档职责划分

### 2.1 PRD.md（产品需求文档）

**职责**: 详细需求 + 技术规格

**包含内容**:
- Phase 清单（已完成/进行中/待规划）
- 详细需求（信号类型、能量模型、命令列表）
- API 接口文档
- 非功能需求（性能、可靠性）
- 技术细节（文件结构、数据文件）
- 踩坑记录

**不包含**:
- 产品愿景（→ roadmap.md）
- 系统架构概览（→ roadmap.md）
- 成功指标（→ roadmap.md）

### 2.2 roadmap.md（路线图文档）

**职责**: 产品定义 + 路线图 + 里程碑

**包含内容**:
- 产品愿景（一句话描述、核心价值）
- 核心功能列表（必做/后续）
- 系统架构概览
- 用户故事
- 成功指标
- 里程碑（时间节点、预期交付）
- 约束与风险
- 版本历史

**不包含**:
- 详细需求细节（→ PRD.md）
- API 接口细节（→ PRD.md）
- 技术实现细节（→ PRD.md）

### 2.3 development.md（开发规范文档）

**职责**: 开发流程规范

**包含内容**:
- 标准化开发流程（10 步）
- SPEC 文档模板
- 架构设计模板
- 代码编写规范
- 测试规范
- Git 提交规范
- 对话风格指南
- Life OS 集成说明

**不包含**:
- 产品需求（→ PRD.md / roadmap.md）
- 具体功能实现（→ 代码文件）
