# 📖 ExoMind 使用指南

> 生命成长助手 - 记录、思考、成长

---

## 🚀 快速开始

只需 3 步即可开始使用：

1. 📝 **记录想法** - 在事件日志中输入你的想法、任务或灵感
2. 🎤 **语音输入** - 点击麦克风按钮，用语音快速记录
3. 📊 **回顾成长** - 随时查看历史记录，反思你的成长轨迹

## ✨ 功能介绍

### 📋 事件日志

> 记录你的思想、任务和灵感

| 特性 | 说明 |
|------|------|
| **文本输入** | 支持 Markdown 格式，包括加粗、斜体、列表等 |
| **语音输入** | 点击麦克风按钮开始录音，自动转换为文字 |
| **标签管理** | 为事件添加标签，便于分类和检索 |
| **时间线视图** | 按时间顺序展示你的记录历史 |

### 🎤 语音输入

> 解放双手，用声音快速记录

**使用方法：**
- 🔘 点击麦克风按钮开始录音
- ⏹️ 再次点击停止录音
- ⏳ 等待语音识别完成
- ✏️ 识别结果会自动填入输入框

**状态指示：**

| 状态 | 图标 | 说明 |
|------|------|------|
| 空闲 | 🎤 | 准备开始录音 |
| 录音中 | 🔴 | 麦克风正在工作 |
| 识别中 | ⏳ | 正在处理语音 |
| 完成 | ✅ | 识别结果已生成 |

### 🌐 设备配对与多端互联

> 让桌面、手机等设备彼此发现、配对并验证链路

**推荐主路径：**

- 每台设备都运行自己的 **embedded RT（内嵌运行时）**
- 在 `网络 -> 设备` 页面把设备切到 **局域网（LAN）**
- 通过 **设备配对（device pairing，设备配对）** 建立可信连接
- 配对完成后，等待系统自动完成 **互通验证（link proof，互通验证）**

**配对前准备：**

1. 两台设备都打开 ExoMind
2. 两台设备都进入 `网络 -> 设备`
3. 确认 `当前运行` 为 `running`
4. 确认 `节点可达性（Bind mode）` 为 `局域网`

**推荐操作步骤：**

1. 在任意一台设备点击 `设备配对`
2. 选择 `发起配对`，记下 6 位 PIN
3. 在另一台设备点击 `设备配对 -> 响应配对`
4. 选择发现到的目标设备，输入 PIN
5. 等待状态变成：
   - `已确认节点`
   - `已验证互通`

**什么才算真正成功：**

- 对方出现在 `已确认节点`
- 卡片显示 `已验证互通`
- 能看到 `本端 RTT / 对端 RTT`
- 点击 `测试互联` 后仍然成功

**不推荐的做法：**

- 正常使用时，不要先去手工填写 `host:port`
- `高级 / 兼容模式` 更适合旧链路、调试或外部 RT
- 日常多设备互联，优先走 `发现 -> 配对 -> 验证` 主路径

## ❓ 常见问题

### 🌐 看不到待配对设备？

请按顺序检查：

1. 两台设备是否在同一个 Wi-Fi / 局域网
2. 两台设备的 `当前运行` 是否为 `running`
3. 两台设备的 `节点可达性（Bind mode）` 是否都切到 `局域网`
4. 是否误用了 `仅本机`
5. 设备页是否还残留旧的手工地址或旧 peer

如果你已经确认以上都正确，先尝试：

- 关闭并重新打开 `设备配对`
- 在设备页点击 `重试`
- 重新启动当前设备的 embedded RT

### 🔐 PIN 输入成功，但还是“未验证互通”？

这说明 **PIN 已通过，但链路验证还没有完成**。正常成功应该同时满足：

- 配对成功
- 自动互通验证成功
- 设备卡片显示 `已验证互通`

如果还停留在 `未验证互通` 或 `在线，但互通验证失败`：

- 先点击一次 `测试互联`
- 等待几秒钟看状态是否恢复
- 如果仍失败，再检查两端是否都在线、是否仍处于同一局域网

### 🤖 Android 模拟器（Android Emulator）为什么有时行为和真机不一样？

Android 模拟器不是严格意义上的同一二层网络设备，因此它和桌面之间常常会同时出现三种地址：

- 模拟器对外广播地址：例如 `10.0.2.15:9124`
- 桌面实际拨号地址：例如 `127.0.0.1:39124`
- 模拟器访问宿主机地址：例如 `10.0.2.2:11240`

这属于开发环境的桥接特性，不代表产品给真实用户的正常体验。

如果你在做最终用户体验验证，优先使用：

- 一台真实 Android 手机 + 一台桌面端
- 或两台同局域网桌面端

### 🧭 什么时候才需要“高级 / 兼容模式”？

只有以下场景才建议进入：

- 你需要连接 `external RT（外部运行时）`
- 你明确知道要手工填写 `host:port`
- 你在做兼容旧链路或开发调试

普通用户的推荐路径仍然是：

- `网络 -> 设备 -> 设备配对 -> 已确认节点 -> 测试互联`

### 🎤 麦克风权限被拒绝？

**Chrome 桌面版：**
1. 点击地址栏左侧的 🔒 锁图标
2. 选择「权限」→「麦克风」
3. 选择「允许」
4. 刷新页面重试

**Android Chrome：**
1. 打开系统「设置」→「应用」
2. 找到「Chrome」→「权限」
3. 允许「麦克风」权限
4. 或者在 Chrome 地址栏输入 `chrome://flags`
5. 启用 `unsafely-treat-insecure-origin-as-secure`
6. 添加你的本地地址（如 `http://192.168.x.x:1420`）
7. 重启浏览器

### 🔇 语音无法识别？

**请检查以下几点：**

- 🌐 **网络连接** - 语音识别需要联网
- 🎙️ **麦克风位置** - 确保麦克风未被遮挡
- 🗣️ **说话方式** - 语速适中，发音清晰
- 🔊 **环境噪音** - 尽量在安静环境中使用
- 📶 **网络质量** - 良好的网络连接有助于识别准确率

### 📱 移动端使用注意事项

1. **HTTPS 要求** - 语音功能需要安全上下文
2. **权限设置** - 确保已授予麦克风权限
3. **浏览器选择** - 推荐使用 Chrome
4. **省电模式** - 关闭省电模式以确保录音正常

## 💡 使用技巧

> 最大化你的使用效率

### 📝 记录技巧

- ✨ 使用 **加粗** 强调重要事项
- 📝 创建 **待办列表** 追踪任务进度
- 🏷️ 添加 **标签** 便于后续检索

- 🏠 找一个安静的环境
- 🎯 说话清晰，语速适中
- 📏 距离麦克风 15-30cm
- ⏸️ 适当停顿，让系统识别完整句子
