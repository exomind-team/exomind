# 团队协作规范

> ExoMind 多角色团队协作的标准流程和规范

## 4 角色分工

| 角色 | 职责 | 任务类型 |
|------|------|---------|
| **Architect** | 架构设计、v4 合规审核 | 架构设计、接口定义 |
| **Developer** | 编码实现、单元测试 | 功能开发、重构 |
| **Developer-2** | 编码实现、单元测试 | 功能开发、重构 |
| **Tester** | 编写/运行测试、质量保证 | 单元测试、集成测试 |
| **Reviewer** | 代码审核、安全检查 | 架构合规、安全审核 |

---

## 任务循环流程

```
架构设计 → 编码实现 → 单元测试 → 代码审核
    ↓           ↓           ↓           ↓
   通过?      通过?       通过?       通过?
    ↓           ↓           ↓           ↓
  否→返回    否→返回     否→返回    是→完成
```

---

## 循环执行规则

| 循环 | 可用目标 | 包含任务 |
|------|---------|---------|
| Cycle 1 | 页面可访问 | 路由、页面、测试、审核 |
| Cycle 2 | 密码安全 | 密码哈希模块 |
| Cycle 3 | 架构就绪 | sync 模块架构 |
| Cycle 4 | 架构合规 | sync-store 重构 |
| Cycle 5 | 完整功能 | PouchSyncAdapter |

## Git 提交规则

### 每位成员完成任务后必须

1. Git commit 提交代码
2. Git push 推送到远程

### Commit 格式

```
[类型]: [简短描述] [修改文件]

类型：feat/fix/docs/test/refactor
示例：feat: 实现密码哈希模块 [password-hash.ts]
```

## Lead 职责

### 核心原则

**Lead 只做任务分发与总结，不自己干活**

### 职责清单

| 职责 | 说明 |
|------|------|
| **任务分发** | 接收用户需求，分配给合适的角色执行 |
| **进度跟踪** | 监控各角色任务进度，及时协调 |
| **工作总结** | 收集成员工作汇报，汇总成团队进度报告 |
| **PR 更新** | 随时更新 PR 评论，报告团队进度 |
| **PR 截图** | 将测试截图、验证结果上传到 PR 评论 |
| **知识沉淀** | 每个循环完成后回写到 docs/memory/logs.md |

### 工作流程

```
用户需求 → 任务分发 → 成员执行 → 成员报告 → Lead 汇总 → PR 评论 + docs/memory/logs.md
```

### PR 评论模板

```markdown
## [日期] Cycle X 进度报告

### 完成的任务
| 任务 | 负责人 | 状态 |
|------|--------|------|
| xxx | @role | ✅ 完成 |

### 团队成员状态
| 角色 | 当前任务 | 进度 |
|------|---------|------|
| @architect | xxx | 🔄 进行中 |
| @developer | xxx | ✅ 完成 |

### 测试结果
- 页面截图: [链接]
- 控制台: 无错误/有错误

### 待处理
- xxx
```

## Team Member 职责

### 每位成员完成任务后必须

1. 向 Lead 报告工作总结
2. Git commit 提交代码
3. Git push 推送到远程

### 报告格式

```markdown
## [任务ID] 完成报告

任务: xxx
负责人: @role
状态: ✅ 完成 / ❌ 失败

工作内容:
- xxx

输出:
- 修改文件: xxx
- 测试结果: 通过/失败
- 截图: [如果有]
```

## C组多用户工作区隔离方案

### 方案选择

单人多会话 + 4角色 + Git worktree 隔离

| 方案要素 | 说明 |
|---------|------|
| **会话模式** | 单人单会话 |
| **角色数量** | 4个（Developer/Architect/Reviewer/DevOps） |
| **接入策略** | 每人一个 git worktree 隔离 |

### 工作区隔离架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    C组 多用户工作区隔离架构                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  dev 分支（主开发分支）                                          │
│       │                                                         │
│       ├── worktree: ../exomind-user-alice (用户 Alice)          │
│       │        └── 单人多会话: Alice × Claude × 4角色           │
│       │                                                         │
│       ├── worktree: ../exomind-user-bob (用户 Bob)              │
│       │        └── 单人多会话: Bob × Claude × 4角色             │
│       │                                                         │
│       └── worktree: ../exomind-user-carol (用户 Carol)          │
│                └── 单人多会话: Carol × Claude × 4角色            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 单人单会话角色切换

```
用户输入 → [角色识别] → 切换至对应角色 → 执行 → 返回结果

4个角色（同一会话内切换）:
┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌────────┐
│ Developer   │  │ Architect   │  │ Reviewer    │  │ DevOps │
│ ·编码实现   │  │ ·架构设计   │  │ ·代码审查   │  │ ·部署  │
│ ·调试测试   │  │ ·技术选型   │  │ ·质量把关   │  │ ·运维  │
└─────────────┘  └─────────────┘  └─────────────┘  └────────┘

角色识别规则：
- 包含"设计/架构/方案" → Architect
- 包含"审查/评审/check" → Reviewer
- 包含"部署/发布/运维" → DevOps
- 默认 → Developer
```
