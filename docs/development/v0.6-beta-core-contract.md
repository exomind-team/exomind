# Beta 核心接缝与提交合同

## 责任与版本

正式本机核心为 `crates/exomind-core`，不依赖 HTTP、Tauri、旧 Mesh/Signal 或任务域。Node `next/` 只提供参考语义与反例。第一单元的数据库 schema 为 1；未知版本拒绝打开，不自动降级、清库或采用旧库。

后续宿主创建一个 `Arc<Core>` 并持有其生命周期。IPC 与 HTTP 都完成身份/当前档案能力校验后调用同一个 `Core::submit`，不得自己落库或回退旧 JSON/EventLog upsert。Tauri 本机提交直接经 IPC 进入该核心，不能经过系统代理、远端配对或网络可达性判断；Web API 是该提交边界的另一适配器。

## 已实施的首组类型与事务

| 对象 | 合同 |
|---|---|
| ProfileId / DeviceId / EventId / CommandId / AgentId | 区分的新类型，生成随机 UUID，拒绝 nil；名称不推导 ID。 |
| WriterContext | 受信宿主在本机创建，不反序列化；绑定当前 Core 生命周期、设备、档案、作者 ID/类别。载荷不能声明作者或把 Agent 冒充 human。 |
| CaptureCommand | `command_id,event_id,profile_id,occurred_at_ms,text,tags`；未知字段拒绝。首单元不支持附件，不悄悄丢弃附件字段。 |
| 规范化事实 | `capture/1` 固定字段顺序，标签排序去重，正文逐字保留；摘要由 Rust 权威计算，不依赖前端自报。通用 JSON/媒体规范化仍待后续冻结。 |
| Receipt | command/event/profile、local_seq、事实摘要、`local_committed` 与重放状态；只证明本机提交，不证明对端已收到。 |

写入在 SQLite `BEGIN IMMEDIATE` 中完成：检查命令 ID 绑定 → 校验/追加事件 → 写回执 → 提交。返回后不再执行会把“已提交”变成“失败”的第二次文件写入。通知失败不能让调用者重新生成 ID。

同 command ID、同作用域/作者/事实重试返回原结果；任何绑定变化明确冲突。同 event ID 同事实可复用序号，异内容不可覆盖。local_seq 是入库顺序，与源端实际时间分离。SQLite 事务和唯一约束负责不同连接的并发，连接内 Mutex 只保护该连接。

本机管理工厂 `local_human/local_agent/create_profile` 不是外部鉴权 API，不得直接映射成匿名或普通 writer HTTP 端点。当前能力不等于外部成员/令牌权限已实现。

## 后续必须冻结的合同

- 成员与邀请：`profileId + deviceId`、密钥证明、一次性邀请、撤销与在途资格；同名档案不合并，非空 Q 不改 ID 加入 P。
- 原件：暂存/完成/引用分开，真实长度与 hash，固定整组提交；本机回执与对端原件回执不同。文件与数据库的崩溃恢复先于“已保存”。
- 复制：每成员有序流/epoch 与每 peer 游标；页和游标同事务，身份/代次/前缀不匹配拒绝；事件顺序不依赖墙钟。
- 时间块：全部开始/暂停/恢复/轮转/结束/反馈节点保留，确定性投影保留冲突原因；不恢复任务域。
- 模型：稳定任务、ownerDeviceId、来源快照、run 资格、取消/宿主停止围栏、迟到覆盖提示与按需更新；未授权原件正文不外发。
- 回收/清理：追加状态事实，本机释放与共享清理分开，显式清理保留最小来源痕迹；旧分页不复活已释放副本。

这些项仍按完整 Beta 计划的 B0→B5 推进，不以第一组类型或 SQLite 测试代替全部合同冻结、HTTP/UI 或真机验收。

## 首单元验证

`crates/exomind-core/tests/local_commit.rs` 通过公开 API 检查持久重试、ID 冲突、跨档案/生命周期、故障回滚、独立连接竞争、坏库/未知版本/只读拒绝与根隔离。真实 SQLite trigger 用于回执写入失败；进程恢复单独记证据，不将正常 Drop 回滚或文件占位当成崩溃验证。

```powershell
cargo test -p exomind-core --locked -j 1
cargo fmt --package exomind-core -- --check
```
