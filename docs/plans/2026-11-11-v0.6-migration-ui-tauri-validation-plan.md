## 1. 目标与已确认方向

本轮以**旧版外心的 UI、UX、交互和动效为产品体验基准**，借助 Pro 交付的 MVP 中可验证的语义、代码与测试，实施真正的搬迁式重构。不是将新候选的静态 Web 界面直接视为旧版体验，也不是把旧的全部业务系统原样搬回。

用户明确的最终方向：

1. **Tauri App 是正式产品宿主**：承担桌面独立窗口、全局快捷键、托盘及相应窗口生命周期；Android 有自己的原生承载和运行约束。
2. **Rust RT 是可扩展核心**：拥有运行时能力及本机最终 apply 权威；Web 是灵活组织的前端，不承担长期同步调度或业务真相主权。
3. **先找回旧版风格与日用路径**：复刻布局、主题、状态、手势、动效、窗口交互和失败反馈；以真实旧版和同数据的可复验基线为准，不凭候选截图臆造旧版。
4. **按当前用途精简**：新版不再自建任务管理；保留时间块开始、结束、状态、备注与反馈、自动总结及悬浮显示。文字、图片、文件在已配对设备间自动同步，离线后补齐；原件默认保留至用户主动清理。
5. **协议允许断代，但配套必须可用**：同版本设备互通并实测；新 RT 交付匹配的 Agent skill，现有消费者逐项核对。旧任务及其他旧数据先保留；历史查看、导入范围、清理与删除传播另行决定。

WinCraft 可以承担悬浮窗主要 UI，外心提供状态接口或 provider 抽象；这是用户认可的可行方向，具体分工与真实宿主验证尚未完成。正式 Tauri App 的主窗口、快捷键和托盘不能因 WinCraft 未就绪而被默认省略。

## 3. MVP 实际交付与缺口

下表区分**包内存在/文档声称**与本轮独立验证；不能将“有实现”直接写成“产品可用”。详细合同见 ZIP 内 `repo-overlay/next/docs/API.md`、`DECISIONS.md`、`SECURITY.md` 和 `evidence/VALIDATION.md`。

| 领域 | 候选包已有内容 | 差距与本机验证重点 |
|---|---|---|
| 记录 | SQLite 追加事实、稳定命令 ID、事务回执、timeline/search、分页；当前一实例一个空间 | 重启、重复提交、异常、附件未完成及真实 UI 的回执仍需逐层验证；并非旧 RT API 的别名 |

| 同版本同步 | 邀请、身份、游标、历史前缀检查、补齐、冲突隔离、暂停/撤销和改地址接口 | 候选界面仍需可达地址和复制/粘贴邀请；无自动发现/二维码。空实例加入限制、已有空间冲突、EasyTier 与 Android 后台均待真实验证 |

| 前端 / 宿主 | Web 页面、静态合成桌面/窄屏预览、Windows 命令启动器 | 真实浏览器 E2E 未完成；无 Tauri 原生 EXE/APK、托盘、原生快捷唤起或 Android 本地运行时 |

## 5. 旧版 UI / UX 复刻基准

用户要保留的是日用体验及视觉语言，而非恢复已经决定移出的任务管理。先做**同场景基线**，再逐项连接新 RT；任务关联入口需有明确去向，不能通过恢复任务系统掩盖迁移缺口。

### G3：Tauri App 真窗与系统能力

Web 及核心链路通过相应基础验证后，再进入原生构建与真窗联调。遵循 [Windows Tauri MCP playbook](../development/tauri-mcp-windows-playbook.md) 的隔离与资源门：开发实例、AppData、RT、Web/HMR 和 bridge 各自隔离；资源密集步骤串行，低于 8 GiB 或总内存 25% 可用时不启动；本机 Tauri 链接采用规定的低内存模式。正式多平台构建按仓库发布治理执行。

- [ ] **独立窗口**：主窗口与悬浮窗各自建立、关闭/隐藏、置顶、拖拽、尺寸、位置恢复、多屏/DPI、焦点；主窗关闭、托盘隐藏和真正退出有可区分结果。

- [ ] **托盘和生命周期**：图标与菜单可用，隐藏后 RT 按设计继续工作，恢复主窗/悬浮窗状态一致；用户明确退出后进程和资源有可核对的结束结果。托盘为目标能力，不以 issue 存在冒充实现。
- [ ] **多 WebView / 状态**：同一测试空间下主窗口与悬浮窗的开始、暂停、恢复、结束和反馈一致；窗口重建、RT 重启、断连及旧状态标记覆盖 #702。
- [ ] **WinCraft 边界**：若采用外部悬浮 UI，验证 provider 契约、宿主重启、租约、陈旧状态和断连恢复；未验证前不移除独立悬浮工作台的日用途径。
