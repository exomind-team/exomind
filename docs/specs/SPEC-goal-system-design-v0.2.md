## 1. 立意 — 不同目标合力塑人

（继承 v0.1 §1，修订：删除天理/人欲/深渊等具体词汇，改为通用表述）

目标系统不是 TODO 的高级版本，而是回答一个根本问题：**人要往哪里去？**

### 1.1 核心命题

不同目标合力塑造一个人的轨迹。有时二者不可得兼，这是价值选择问题，需要图形化呈现给人。

### 1.2 动机链条

```
生存动机 → 自驱力（维持生存状态）→ 内驱力（计算方向）→ 方向选择
```

心理学介入的起点就是目标系统。

### 1.3 理论展望

当目标网络足够复杂时，相互关联的目标可能自然聚集成群，在宏观上呈现区域与类型的分化。这一现象暂不纳入设计范围。

## 2. 核心定义 — 目标、任务、时间块

（继承 v0.1 §2，补充"共享部分行为"表述）

### 2.1 三层聚焦模型

| 概念 | 定义 | 聚焦 |
|------|------|------|
| **目标** | 我想要达到的状态，可验收，以自己为中心 | 最终状态 |
| **任务** | 要做的事，限定时段，是连接两个节点的边 | 行动 |
| **时间块** | 限定在一块时间内的事情 | 时段 |

### 2.2 关键区分

- **目标 ≠ 长期任务**：功能相似，关注点不同
- **只有经由任务，目标方可达**
- 目标与任务是**不同实体**，共享部分行为（待命名、不可删除）

### 2.3 理论来源

王培（pwang）智能论——「目标是系统自身所倾向于/希望/想要达到的状态」。补充工程要求：**可验收**。

## 3. 数据建模

> **v0.2 新增**

### 3.1 目标实体

```typescript
interface GoalNode {
  id: string
  title: string           // 空字符串 = 待命名
  description: string
  status: GoalStatus      // 'pending' | 'completed' | 'cancelled'
  achieveMode: 'AND' | 'OR'
  createdAt: number       // UTC timestamp ms
  updatedAt: number
}
```

目标**没有** `in_progress` / `suspended` 状态。推进状态从关联任务**派生**。

### 3.2 任务边实体

```typescript
interface TaskEdge {
  id: string
  title: string           // 空字符串 = 待命名
  description: string
  source: string          // 源节点 ID（GoalNode 或 MeNode）
  target: string          // 目标节点 ID（GoalNode）
  status: TaskEdgeStatus  // 'pending' | 'in_progress' | 'suspended' | 'completed' | 'cancelled'
  taskNodeRef?: string    // 后续集成：关联的现有 TaskNode ID
  createdAt: number
  updatedAt: number
}
```

- TaskEdge 是**独立实体**，原型阶段不引用现有 TaskNode
- `taskNodeRef` 为空时 = 匿名边（尚未关联真实任务）

### 3.3 Me 实体

```typescript
interface MeNode {
  id: string
  name: string
  // 后续扩展：knowledge, mindSet 等
}
```

Me **不是** GoalNode 的特殊实例（不用 `isMe` 标记），是**独立实体**。

### 3.4 图数据结构

```typescript
interface GoalGraphData {
  me: MeNode
  goals: GoalNode[]
  edges: TaskEdge[]
}
```

存储：localStorage key `exomind:goal-graph`

### 3.5 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Me 建模 | 独立实体 MeNode | Me 有自己的 schema |
| 字段命名 | `title`（非 `name`） | 与现有 TaskNode 一致 |
| TaskEdge 独立 | 不引用现有 TaskNode | 全新模块，后续集成 |
| 存储方式 | localStorage | 原型阶段简化 |

## 4. 图约束规则

> **v0.2 新增**

### 4.1 硬约束

| 编号 | 不变量（开发者） | 用户行为语义（用户） |
|------|----------------|-------------------|
| **C1** | 已完成不可逆：`completed` 是终态 | 完成了就是完成了 |
| **C2** | 已取消不可逆：`cancelled` 是终态 | 放弃了就是放弃了 |
| **C3** | 不可删除：不提供 delete 操作 | 放弃目标 = 取消 |
| **C4** | Me 永远存在：不可取消不可删除 | 自我是起点 |
| **C5** | 无孤立目标：新建时自动创建 Me→目标 匿名边 | 每个目标都有路可达 |
| **C6** | DAG 约束：禁止循环 | 目标网络不能回到原点 |
| **C7** | 有向边：source→target = 贡献于达成 target | 任务指向它要达成的目标 |
| **C8** | 目标完成纯推导：不可手动标记 completed | 目标不能手动完成 |
| **C9** | 匿名边不可完成：taskNodeRef 为空时不可 completed | 没做具体事不算达成 |

### 4.2 图结构约束

- Me 是有效端点（任务边可连 Me↔目标）
- 允许平行边（两节点间可有多条任务边）
- 边必须有两个端点（不允许悬空边）
- 新建目标自动创建 Me→目标 匿名边

### 4.3 原型阶段放宽

| 约束 | 原型行为 | 完整设计行为 |
|------|---------|------------|
| C5 自动匿名边 | 不强制 | 自动创建 |
| C6 DAG 检测 | 不检测 | 创建边时检测 |
| C8 完成纯推导 | 用户可直接改状态 | completed 只能推导 |
| C9 匿名边限制 | 不限制 | 限制 |

原型中放开的约束标注为「prototype-only」。

## 5. 生命周期

（继承 v0.1 §3，大幅扩充）

### 5.1 任务边状态机

```
  ┌──────┐      ┌──────────┐      ┌──────────┐
  │ 待办 │─────→│  进行中  │←────→│  已挂起  │
  └──────┘      └────┬─────┘      └────┬─────┘
                     │                  │
                     ├──→ 已完成 ←──────┘
                     └──→ 已取消 ←── 已挂起
```

已完成和已取消都是**终态**，不可转出。

### 5.2 目标状态

```
  ┌──────┐      ┌─────────────────────┐
  │ 待办 │─────→│ AND/OR 推导判定结果 │──→ 已完成（被 Me 吸纳）
  └──┬───┘      └─────────────────────┘
     └──→ 已取消（用户主动放弃）
```

| 状态 | 谁设置 | 规则 |
|------|-------|------|
| 待办 | 系统默认 | 新建即为待办 |
| 已完成 | **纯推导** | 用户不可手动设置 |
| 已取消 | 用户手动 | 不能取消已完成的目标 |

### 5.3 达成方式

| 属性值 | 含义 |
|-------|------|
| **AND** | 所有**入边**完成 → 目标完成 |
| **OR** | 任一**入边**完成 → 目标完成 |

AND/OR 只看**入边**（target 为该目标的边）。

### 5.4 完成级联

- **边完成 → 触发目标重算**：target 目标的 AND/OR 重新计算
- **目标完成 → 边不联动**：关联边保持各自状态
- **级联传播**：目标 A 完成后，以 A 为 source 的边的 target 目标也重算（沿 DAG 向下游传播）

### 5.5 取消联动

目标取消时弹窗让用户选择：同步取消关联任务边 / 保留不动。

### 5.6 待命名机制

目标与任务共享：title 为空时界面展示「待命名」。

## 7. 目标网络 — 力导向图

（继承 v0.1 §5，补充图约束和拆解精确定义）

### 7.1 图的结构

- 节点：Me（固定中心）+ 目标（外围）
- 边：任务（有向，source→target）
- 允许平行边、DAG 约束、Me 是有效端点

### 7.2 物理模拟

目标间排斥力 + 任务链约束距离。类似「链条拴着互相排斥的球体」。

### 7.3 距离语义

距离从拓扑涌现：Me 到目标的最短有向路径任务跳数。近=近期，远=长期。

### 7.4 目标间操作

#### 拆解（第二版功能）

将边 A→B 拆为 A→C→B：
1. 创建待命名中间目标 C
2. 保留原边，用户选择分配到 A→C 或 C→B
3. 另一段创建匿名边
4. 支持用已有目标作为中间节点

### 7.5 交互模型

点击添加目标 + 拖拽连线添加任务 + 画布操作
