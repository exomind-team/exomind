## 1. 立意 — 不同目标合力塑人

目标系统不是 TODO 的高级版本，而是回答一个根本问题：**人要往哪里去？**

### 1.1 核心命题

不同目标合力塑造一个人的轨迹。有时二者不可得兼，这是价值选择问题，需要图形化呈现给人。

### 1.2 动机链条

```
生存动机 → 自驱力（维持生存状态）→ 内驱力（计算方向）→ 方向选择
```

心理学介入的起点就是目标系统。越往后越涉及心理学，从目标开始就触达心理层面——为什么你想要这个、不想要那个。

### 1.3 理论展望

当目标网络足够复杂时，相互关联的目标可能自然聚集成群，在宏观上呈现区域与类型的分化。这一现象暂不纳入设计范围。

> **溯源**
> - 设计图：标题框「不同目标合力塑人」、Z1 三方牵引示意图（天理/人欲/深渊仅为举例）
> - 文字讨论 #7：动机链条；#8：价值选择「二者不可得兼」；#9：心理学起点

## 2. 核心定义 — 目标、任务、时间块

### 2.1 三层聚焦模型

| 概念 | 定义 | 聚焦 |
|------|------|------|
| **目标** | 我想要达到的状态，可验收，以自己为中心 | 最终状态 |
| **任务** | 要做的事，限定时段，是连接两个目标的边 | 行动 |
| **时间块** | 限定在一块时间内的事情 | 时段 |

### 2.2 关键区分

- **目标 ≠ 长期任务**：功能相似，关注点不同。目标聚焦于「我想要得到什么」，任务聚焦于「我要做什么」。
- **只有经由任务，目标方可达**。
- 目标与任务是**不同实体**。

### 2.3 理论来源

> 王培（pwang）智能论——「目标是系统自身所倾向于/希望/想要达到的状态」。
>
> 原文补充工程要求：**可验收**。

> **溯源**
> - 设计图：Z3 Goal 注释（完成≈被 Me 吸收 + pwang 引用）、宣言文字「点变自创目标 / 行变任务 / 只有经由任务 / 目标方可达」
> - 文字讨论 #2：目标≠长期任务；#3：可验收、以自己为中心；#6：三层聚焦

## 3. 生命周期

### 3.1 任务状态机（用户直接操作）

```
  ┌──────┐      ┌──────────┐      ┌──────────┐
  │ 待办 │─────→│  进行中  │←────→│  已挂起  │
  └──────┘      └────┬─────┘      └────┬─────┘
                     │                  │
                     ├──→ 已完成 ←──────┘
                     │
                     └──→ 已取消 ←── 已挂起
```

转换规则：待办→进行中，进行中⇔已挂起，进行中→已完成，已挂起→已完成，进行中→已取消，已挂起→已取消。

### 3.2 目标状态（由关联任务推导）

```
  ┌──────┐      ┌────────────────────────────┐
  │ 待办 │─────→│ 达成方式(AND/OR) 判定结果  │
  └──────┘      └─────┬──────────────────────┘
                      │
                      ├──→ 已完成（被 Me 吸纳）
                      │
                      └──→ 已取消（用户主动放弃）
```

- 目标**没有**"进行中/已挂起"状态——其推进状态从关联任务**派生**
- 目标是否"在推进"是一个派生视图：看关联任务中有无进行中的即可
- **待讨论**：目标是否需要独立的进行中语义（与任务的"需要时间块推进"可能不同）

### 3.3 待命名机制

目标与任务共享「待命名」展示性名称：

| 场景 | 状态 | 界面展示 |
|------|------|---------|
| 系统自动创建，尚未命名 | 待办 | 「待命名」 |
| 用户已命名 | 待办 | 显示名称 |

### 3.4 达成方式属性

目标拥有「达成方式」属性，决定关联任务如何组合判定目标完成：

| 属性值 | 含义 | 阶段 |
|-------|------|------|
| **AND** | 所有关联任务完成 → 目标完成 | 原型实现 |
| **OR** | 任一关联任务完成 → 目标完成 | 原型实现 |
| 组合逻辑 | 与门/或门自由组合 | 后续扩展 |

> **溯源**
> - 设计图：Z2 统一状态机图、Z3「任务（可匿名占位）」、底部红色区域（达成条件探索，已解决）
> - 文字讨论：交互式确认——状态列表、转换规则、匿名等同待办
> - 设计图底部红色连边（G3=G1+G2, T1+T2→T3）为达成条件关系的设计探索痕迹，结论已纳入达成方式属性

## 4. Me 中心与宇宙模型

### 4.1 Me 中心

Me（自我）是图的中心节点，具备两个维度：

- **知识 Knowledge**：我知道什么、理解什么
- **心智模式 MindSet**：我的心理状态、思维方式

目标把知识与心智模式串联起来，在科技树两侧作为相互融合的两支。

### 4.2 吸纳意象

> 「众星向我聚，万事皆我梯」

- 自我是一颗星球（地表），目标是外围的宇宙碎片
- 通过任务（攀登的阶梯）向外攀升
- **吸纳目标 = 达成目标 = 目标归于自身状态**
- 完成后：视觉上合并进 Me 圆 + Me 属性更新（知识、心智模式等）

### 4.3 星图视图（概念参考）

设计图右侧的「另一种视图」展示了一个纵向意象：

```
     ☆ Star（愿景）
     │
    (G3)
    / \
 (G1) (G2)    ← 目标节点
   \  |  /
   Task(阶梯纹连线)
     │
  ═══════
  Me (Ground)
```

连线用阶梯纹表示（任务 = 攀登的梯子）。此视图为概念图，可在后续阶段用 SVG 或绘图模型参考实现。

> **溯源**
> - 设计图：Me 大圆（知识/心智模式）、Z5 对联「众星向我聚 万事皆我梯」、Z5/Z6 星图（阶梯纹连线）
> - 文字讨论 #4：星球吸纳意象；#5：Me + 心智模式 + 知识

## 5. 目标网络 — 力导向图

### 5.1 图的结构

- **节点**：Me（中心）+ 各目标（外围）
- **边**：任务（连接两个目标的路径，也连接 Me 与目标）
- 目标与 Me 之间直接或间接相连，连边经任务到达目标

### 5.2 物理模拟

```
力学规则：
  - 目标之间有排斥力（太近则相互推开）
  - 任务链条在一定距离外产生吸引力
  - 类似「用链条拴着彼此要远离的球体」的物理效果
  - 距离 = 两节点之间的任务跳数涌现
```

### 5.3 距离语义

距离不是用户手动设置的标签，而是从图拓扑**涌现**的：

| 距离 | 含义 | 由什么决定 |
|------|------|----------|
| 近 | 近期目标 | Me 到该目标的任务跳数少 |
| 中 | 中期目标 | 任务跳数中等 |
| 远 | 长期目标 | 任务跳数多 |

标尺方向：中心（Me）向外，越来越远 = 越长期。

### 5.4 目标间操作

#### 连边

目标之间经任务连接。若两目标间无连边 → 系统创建待命名任务占位 → 引导用户拆解与命名。

#### 拆解

一条任务边可从中间一拆两半，引入待命名中间目标，1 个任务拆成 ≥ 2 个任务。

#### 复合

目标可复合（目标C = 目标A + 目标B），但其成分本身不是任务。

#### 多层级

靠任务跳跃在目标间移动（多层级，靠任务跳）。

### 5.5 交互模型

- 点击空白处添加目标
- 拖拽连线添加任务
- 画布式操作

> **溯源**
> - 设计图：Z4 距离标尺（近期/中期/长期）、Z7 连边注解（引入匿名中间目标、任务拆解）、底部复合公式（G3=G1+G2）、Z6 阶梯纹连线
> - 文字讨论 #4：星球吸纳；交互式确认：物理模拟（排斥力+任务链条约束）、点击+连线

## 6. 待讨论事项

| 议题 | 当前状态 | 优先级 |
|------|---------|-------|
| **习惯（来来回回）** | 周期性目标。靠近 Me = 达成但非终止，远离 Me = 许久未做（中断）。需更上层处理方式 | 目标系统建成后再议 |
| **目标的"进行中"语义** | 与任务的"需要时间块推进"语义可能不同。当前方案：从任务状态派生 | 原型中验证 |
| **反馈/自评/回顾** | 需要，但非原型范围 | 后续阶段 |
| **Agent 主动参与** | 建议目标、发现冲突、提醒久未推进的目标 | 后续阶段 |
| **星图视图** | 概念图，可用 SVG 或绘图模型实现 | 后续参考实现 |
| **达成方式组合逻辑** | AND/OR 先行，与门/或门组合后续扩展 | 后续扩展 |

> **溯源**
> - 设计图：Z8 Habit 气泡（来来回回 + 靠近/远离动态）

## 7. 落地策略 — 原型先行

> 「先把功能叠出来，看到可操作、可验证的原型后，用实践反哺对理论的理解。整体策略是快速迭代。」
> — 文字讨论 #10

### 7.1 原型范围

| 功能 | 优先级 | 说明 |
|------|-------|------|
| 目标网络图可视化 | **核心** | 力导向图，Me 为中心，目标为节点，任务为边 |
| 目标状态机 | **核心** | 待办 → 达成方式判定 → 已完成/已取消 |
| 拆解与占位 | **核心** | 待命名任务占位，拆解引入中间目标 |
| 距离标尺视图 | **核心** | 近期/中期/长期从拓扑涌现 |
| 达成方式 AND/OR | **核心** | 目标属性，控制任务完成如何推导目标完成 |
| 任务状态机升级 | 次要 | 需结合现有源码和架构 issue |
| 吸纳动画 | 次要 | 目标完成后合并进 Me 圆 |

### 7.2 技术定位

- **全新模块**，独立于现有任务/时间块系统，后续集成
- 交互方式：画布式（点击添加 + 连线）
- 图布局：力导向算法（排斥力 + 任务链约束）

> **溯源**
> - 文字讨论 #1：出原型；#10：快速迭代、实践反哺、架构不阻塞则不动
> - 交互式确认：全新模块、原型范围四项核心功能
