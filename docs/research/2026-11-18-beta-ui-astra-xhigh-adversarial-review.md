## 需要返修的 20 项

P0 优先保护实际操作、数据和资源。P1 影响常用任务或产生错误判断。P2 有替代路径，仍有明确的输入、识别或管理成本。以下「验收」均为待走路径。

### 01 · P0 · 主窗隐藏专注会让浮窗失去控制

**证据与代价。** 用户已实测。基线 `BetaApp.tsx:503` 将面板展开态传给计时视图，`BetaFocusTimer.tsx:31–38` 据此启停快照获取。`timeblocks-controller.ts:194–200` 将超过 2 秒的样本标为陈旧，`overlay/BetaOverlayPage.tsx:59–75` 由此禁用操作。桥仍在轮询，发布的却可以是陈旧快照。用户把主窗腾给记录，回浮窗暂停时反而得先刷新或恢复主窗。证据指向控制失效，不能据此断言 Host 的计时停止。

**修复与验收（P04/P05/P08/P10）。** 由业务所有者维护可查询状态，主窗和浮窗各自订阅。工作区已将定期读取移到 controller，新增测试用假时钟和替代桥检查六种显隐路径。用同候选 Windows 真浮窗，主窗分别折叠、隐藏、进入简洁记录、切同步、切设置、最小化，跨过陈旧阈值后暂停、继续、结束、提交反馈。对照 Host 的档案、块 ID、事件数和回执。再断开恢复，陈旧时给出依据，重连后只出现一次结果。

### 02 · P0 · 搜索另一条消息可能取消正在写盘的导出

**证据与代价。** 基线 `OriginalDownloads.tsx:23–35` 在行组件卸载时对本行原生导出调用 `cancel(requestId)`。`BetaApp.tsx:388–394,533–543` 切换搜索查询会清页，再按结果挂附件。即使只是找另一句话，也可能向 Native 发出真实取消，且原行已经离场，用户看不到部分文件提示。获取远端原件有另一条耐久传输路径，此发现针对原生导出。基线与本轮差异均未提供该场景的实机结果。

**修复与验收（P04/P08/P09）。** 让档案范围的导出任务持有请求与回执，行只订阅并提供显式取消。用合成大文件在选定位置导出，写入期间搜索不命中该行的词、清空查询、回到该行。核对任务身份相同、输出长度及哈希正确。再显式取消，检查部分输出提示、终态及可恢复操作。单独验证会话关闭和权限撤销的领域合同。

### 03 · P0 · 设备状态不能回答「手机能否解释这个时间块」

**证据与代价。** B 图可见用户记录了手机缺少时间块的问题。基线 `BetaPeersPage.tsx:19–29,163–172` 将连接、记录补齐、原件状态压成一句话。`BetaFocusTimer.tsx:115–122` 在本地缺历史时已有提示。设备卡没有给出目标设备上该块投影、缺父或许可范围的独立结论。用户读到已补齐的提示后，仍需跑向另一台机器逐条核对。协议工程进展与这条用户路径须分别取证。

**修复与验收（P05/P06/P08）。** 设备详情对同一档案分别展示文字已确认范围、指定时间块能否重建、原件字节与校验状态，注明方向和最后确认时间。用两台同版本设备加第三方来源构造「文字到了、缺一个父节点、原件仅有元数据」，再补齐父节点和原件。每步对照接收端 typed timeline、投影与原件摘要。即使一项未知，另外两项也应保留各自证据。

### 04 · P0 · 修浮窗的新轮询把空闲成本带到了隐藏表面

**证据与代价。** 基线 `overlay/main-owner.ts:85–104` 每轮发布快照、取票据，结束后约 250 ms 再轮询。`MainOverlayBridge.tsx:23–35` 建桥取决于桌面环境与作用域，开启偏好只控制显示。主计时视图原先每 250 ms 重绘，记录页具备回顾能力时约 3 秒再读。工作区 `timeblocks-controller.ts` 的 `observe` 在打开所有者后持续约每秒一轮，成功路径依次读取身份、快照、身份。用户即使看不到钟、浮窗也关闭，仍可能支付观察成本。这是可定位的工作量，没有本轮电流或掉电归因。

**修复与验收（P04/P05/P08，能源 P0）。** 让 Host 保持业务运行，实际消费者按需取得快照。空闲与失败时退避，可见秒数局部插值，到点和恢复立即重取。比较同候选、同合成档案、相同电源和亮屏条件下的空闲、仅记录、浮窗可见、双窗隐藏、断网与诊断开关。分别量 CPU、唤醒、IPC、读取次数、输入延迟及可实测的能耗，列出采样自成本。必须同时满足 01 的控制路径。

### 05 · P0 · 大文件最早的一段等待没有可解释的进度

**证据与代价。** 基线 `drafts.ts:214–262,323–345` 先建文件项、准备本地源并计算哈希，暂存时还可能再读全源校验。`BetaApp.tsx:581–589` 把前期统称「正在复制并校验本机源」，上传阶段才出现偏移量。一次选择多个大文件时，人无法分清排队、读源、校验、上传，也无法判断能否离开。不能把后段网络字节当成前段磁盘进度。

**修复与验收（P05/P08/P09）。** 按文件身份记录排队、复制、哈希、分块暂存、接收与末端校验的起止，以及实际可得的字节数和总量。仅能测阶段时显示阶段与最后变化时间。分别注入慢读、缺源、断网和校验失败，关掉面板再回来。用户能指出卡在哪一段并继续对应操作。大文件的吞吐、CPU/IO 与持续时间另在本机按需查。

### 06 · P1 · 品牌、页面身份与排障地址同时占用常态首屏

**证据与代价。** B 图同时有窗口标题、左栏中英文品牌、独立收起键、主区版本与地址、「当下」标题、档案选择和档案管理。右上类似日期的值在 `BetaApp.tsx:248–255` 实际是档案名，左下再次显示。初次使用者可能把它当日期筛选。熟悉者每次都花相同高度跳过这组信息。

**修复与验收（P01/P02/P03/P09）。** Logo 自身切换侧栏，旁边弱化显示「外心 · 0.6.0 beta12」，用构建版本生成。运行地址、目录放在可查可复制的本机详情，档案入口保留对象含义。工作区已合并顶栏、采用 Logo 开关。分别用鼠标、Tab/空格和触摸切侧栏，辨认日期状档案、找到版本及地址，再回到同一行消息。还需核对移动壳、紧急连接失败页和实际窗口/任务栏图标。

### 07 · P1 · 专注配置与检索挤到同一屏时，聊天只剩一条

**证据与代价。** B 图的中部计时卡突出，记录标题和检索整行在其下。基线 `BetaApp.tsx:498–516,529` 同时设工作区滚动、最高 48dvh 的专注滚动、消息历史滚动，`BetaWorkspaceView.tsx:25` 又为记录设最小高度。人在照片、软键盘或短窗口下边看旧文边工作，指针或手指起点决定滚的是哪一层。基线能分别隐藏面板，普通聊天仍留着管理工具。

**修复与验收（P02/P03/P04/P07）。** 记录可以完整展开，默认读写给正文与贴底输入，频用专注动作保留紧凑且可返回的入口。工作区已接入简洁记录、合并顶栏，浮窗桥已移除正常态独立按钮，专注配置改为紧凑布局。普通双面板仍有内外滚动，新的正文可见高度与浮窗入口可发现性待宿主核对。用短屏横置、手机竖屏开中文 IME、桌面窄窗，执行「读中段 → 记一句 → 查到它 → 暂停 → 回中段」。记录实际可读消息、滚错容器次数、返回位置和发送键遮挡。用户判定留白是否合适。

### 08 · P1 · 输入区下的永久提示有空间成本，新对勾又有范围歧义

**证据与代价。** B 图最下有「本机已保存」。基线 `BetaApp.tsx:605` 用同一常驻行显示快捷键、草稿、提交与待查证。工作区 `BetaCaptureStatus` 收进固定输入槽，位置更稳，但选图标的条件含整个设备草稿控制器的 `drafts.confirmed.length`，说明文字却按当前档案与草稿版本匹配。档案 A 的旧回执可使空档案 B 得到对勾。尚未提交的草稿也使用对勾。喝口水回来的人需要再开详情，甚至会误以为已经送出。

**修复与验收（P01/P04/P08）。** 图标与无障碍名称共同来自同一档案、草稿版本、命令 ID 与回执。暂存、待提交、结果未知、已获本机回执有不同形状。A 提交 → 切到空 B → 在 B 编辑但未提交 → 回执丢失后恢复 → 再开新草稿。眼看、屏读和触摸展开的事实应一致，输入框和发送位全程稳定，失败有原位处理入口。

### 09 · P1 · 切换时间块时，界面把旧块叫成「切换目标」

**证据与代价。** B 图同时显示「切换目标」、左侧到点策略和中央「开始计时」。基线 `BetaFocusTimer.tsx:64–65,110,125–131` 将当前块的名称存入 `panel.name`，在「切换目标」后显示它，真正的新名取自另一份草稿。共享 `FocusTimerView.tsx:503–511` 的提交键仍叫「开始计时」。人在 A 进行中拟切 B，必须猜这次会启动 B、结束 A，还是切回 A。工作区已把到点策略移入紧凑配置卡，旧块名仍以「切换目标」展示，提交键仍显示「开始计时」。

**修复与验收（P03/P06/P09/P10）。** 在 A 的卡片附近显示「从 A 切到 B」，将新名、到点策略与一次明确轮转动作放在一起，放弃编辑可返回 A。分别用触摸和键盘试取消、轮转、并发时另一端先切到 C。用户在提交前能报出影响对象。回执与时间线只出现权威接受的变更。

### 10 · P1 · 消息作者与动作类型仍然共用过多视觉线索

**证据与代价。** A 图中蓝色系统项、紫色助手项、右侧人类项能从形态和位置辨认。基线 `BetaApp.tsx:533–543` 用同一种系统气泡处理时间块与非人类 capture，前者用同一个 Timer，后者 Bot。人类另有位置和颜色。已有差异，但扫一屏开、停、续、反馈时仍要逐字读。工作区新增 `BetaTimeblockAvatar` 区分多种动作，开始与继续同用绿色 Play，普通 Agent 记录的气泡仍沿用 system。

**修复与验收（P01/P02/P07/P08）。** 先用来源的标签、布局或气泡轮廓区分人、Agent、计时服务，再用动作图形和语义色编码开始/暂停/继续/结束/反馈。保留精确文本供读屏。用混合时间线，在正常、灰度、浅/深色及读屏下分别找出「我的原话」「Agent 的说明」「暂停后第一次继续」。让用户选择语义容易区分且耐看的版本。

### 11 · P1 · 历史上的「暂停时间块」没有带回具体块

**证据与代价。** `timeblock-label.ts:3–6` 对暂停、继续、结束返回通用字串，`BetaApp.tsx:533–536` 渲染为无详情操作的段落。A 图能在块对象上看到开始、结束、工作与反馈用时。Beta 的回顾摘要另有来源入口，普通动作行缺少同等定位。隔天搜索出两条「暂停」时，用户只能向前翻猜块名，反馈可能追加到错误对象。

**修复与验收（P03/P06/P08/P10）。** 动作行带可辨认的块名、来源，按需打开同一个块的区间、起止与反馈依据，再就近补反馈。可折叠明细以保留密度。用两个同名块、一次轮转、一次缺父，在单条暂停处进入。依据能区分两块，缺失部分标待确认，返回保留筛选、选中和滚动。

### 12 · P1 · 人类消息缺少复制、引用及从引用返回原文的入口

**证据与代价。** A 图消息附近能看见复制、链接、引用。基线 `BetaApp.tsx:539–543` 为 capture 注入正文和原件，未注入行操作，当前差异也未接线。在长对话末尾回应某句原话，只能选择正文、抄写上下文、再搜索原条目。共用气泡外观没有恢复这条能力。

**修复与验收（P03/P06/P07/P10）。** 行聚焦或点更多时给出可用动作，引用携带档案内稳定事件 ID 并能跳回原文。用鼠标、键盘和触摸各从同文两条中的第二条引用，取消一次再发送，点开引用时定位正确条目，返回后编辑草稿和历史锚点仍在。复制失败时保留选择并说明原因。

### 13 · P1 · 简洁记录可能偷偷保留一个看不见的筛选

**证据与代价。** 基线 `BetaApp.tsx:384–398,516–532` 已将输入中的搜索词与已提交 query 分开，但未提供突出的当前筛选或一键清除。工作区让简洁态继续使用同一 query，同时隐藏整行搜索工具。搜索 A 后进简洁记录再发 B，若 B 不匹配，提交可以成功而当前列表看不到 B。空结果文案也不能直接清除筛选。

**修复与验收（P03/P04/P08/P09）。** 有筛选时才出现可清除的小标签，或明确进入全记录并可回之前的筛选。提交回执能定位实际事件，再返回原查询。用鼠标筛 A、触摸进简洁态、键盘发 B，验证能说明列表范围、找到 B、回到 A 的旧位置，期间没有重发。

### 14 · P2 · 隐藏再显示会把原来的折叠状态改为展开

**证据与代价。** 基线与工作区 `BetaWorkspaceView.tsx` 对隐藏按钮均采用「hidden → expanded」。用户先折叠专注，只想给记录短暂腾出最后一行，再显示时却得到整张计时卡，阅读位置附近的几何变化远超预期。面板一直挂载能保住不少内部状态。这条问题发生在布局偏好本身。

**修复与验收（P04/P07/P09）。** 分开记住可见性与上次展开程度，另留明确的恢复默认动作。把聊天停在中段、输入选区留在句中，折叠 → 隐藏 → 显示 → 展开 → 返回输入，逐项核对原稿、选区、锚点、键盘焦点与未提交标记。普通往返和显式恢复默认应得到各自预期的布局。

### 15 · P1 · 一件附件旁的「恢复暂存」会遍历整组

**证据与代价。** 基线 `BetaApp.tsx:590–592` 在失败文件行提供恢复按钮，却传入 `resumeFiles(profileId)`。`drafts.ts:269–279` 对该档案全部草稿文件执行准备或上传。一个小文件失败时，用户只想修它，操作范围却可以扩及正在等待的其他大文件，引入读取、查证或等待成本。未测重复读写的实际字节数。

**修复与验收（P05/P07/P09/P10）。** 本行操作按文件 ID 恢复，整组重试有独立入口和范围说明。构造 A 缺源、B 可恢复、C 已校验，点 B 只产生 B 的领域请求。再选择恢复全部，各文件单独回显资格、成本和结果，整组提交合同仍然成立。

### 16 · P1 · 草稿图片要等准备完成才能辨认，队列里看不到的缩略图却也可开始读

**证据与代价。** `BetaApp.tsx:581–587` 仅在 `file.original` 存在时挂缩略图，之前显示通用图标。消息内联图在 `BetaImagePreview.tsx:103–120` 有近视口检查，草稿 `thumbnail` 通过同一条件时只需工作区可见。队列自身最高 28dvh。一次挑十张相似图片，要等复制/哈希才分得清，队列远处的就绪项也有资格排队读取。现有串行队列和单图上限应保留，不能据此估算整机内存。

**修复与验收（P01/P03/P05/P08）。** 对支持格式按可见项或手动点选提供有预算的本地预览，明确「已选」及「原件已校验」各自成立的条件。用相似图片、超预算图片和坏图验收选错移除、离屏释放、重开、显式预览失败。读取范围及峰值资源可核对，打开预览不触发取件、发送或文件选择器。

### 17 · P1 · 选设备和撤销设备时，人要靠八位 ID 认机器

**证据与代价。** `BetaPeersPage.tsx:18,163–179` 用固定「设备」加截短 ID 命名成员，详情给全 ID、指纹和端点。人在手机和平板之间处理同步或撤销授权时，需要先去另一台核对字符串。断线时尤其难辨，误选代价高。邀请、加入表单还排在已授权设备之前，反复管理旧成员要再次经过入门流程。

**修复与验收（P02/P03/P06/P09）。** 常用列表优先给可读设备名、本机/对端、所属档案和最近确认，详情保留稳定身份与指纹。未配对时突出邀请，已有多台时让用户先找到目标。用两台同名设备与一次地址变化执行「找平板 → 核对身份 → 撤销 → 查看后果」，另一台连接保持，已存副本的边界讲清。

### 18 · P1 · 授权给外部 Agent 的事情，在设备管理里办不了

**证据与代价。** `BetaPeersPage.tsx:133–183` 办理设备邀请、加入、重新授权和撤销。Beta 全项盘点 V16 记录了受范围限制的外部 Actor 路径与尚缺的授权产品入口。给工具临时只读权限或收回某个写权限时，界面中最像的操作是「邀请另一设备」，实际主体和后果不同。[Beta 全项盘点](../plans/2026-11-17-v0.6-beta-progress-audit.md)

**修复与验收（P06/P08/P09）。** 单独管理应用/Agent 的档案、主体、读写范围、有效状态和撤销结果。配对仍在设备页。本地合成两个 Agent grant 和一个设备成员，撤销其中一个 grant，验证其下一次受限请求、另一 grant 与设备同步分别符合权限结果。界面凭可读元数据能完成核对，诊断排除 secret。

### 19 · P1 · 平板掉电时，当前管理入口无法就地定位哪项工作在运行

**证据与代价。** 基线的 `BetaRuntimeLocation.tsx` 提供地址/目录，`BetaPeersPage.tsx` 提供连接详情，设置页有部分系统资格。设计文档 D0–D5 对本地观测总览、阶段度量及其自成本另有计划。当前差异主要让地址按需读取。用户面对「发热但记录已同步」仍需跨页猜是原件哈希、传输、图像解码还是观察器。完整面板属后续建设。最小定位能力直接服务 P0。[本地观测面板设计与验收门](../plans/2026-11-17-beta-observability-ui-design.md)

**修复与验收（P03/P05/P06/P08）。** 从本机详情按需查看实例、时间窗、数据来源和可展开的资源/任务阶段。为非凭据数据保留本地查看或继续展开的可能，业务私密正文由用户有意进入，默认导出范围可检查。区分零、缺测、上次确认与暂停。用慢哈希和断连两类合成故障让人指出最后证据、定位到对象、关闭详情返回当前位置。测开关前后自成本。未来遥测的接收方、字段选择、保留与撤销另行决定，本地查看不产生上传。

### 20 · P1 · 上翻旧消息以后，缺少从当前位置回到最新一条的操作

**证据与代价。** `BetaApp.tsx:407–424,529–544` 对尾随与历史阅读作了区分，可以保住 `scrollTop`，历史顶端有「加载更早记录」。当用户主动离开尾部后，消息区没有对称的「回到最新」或「查看刚发的那条」入口。越是成功地保留旧位置，发完新消息的人越需要手动长滚，再找原来那段。

**修复与验收（P04/P06/P10）。** 离开尾部且确有新内容时，在当前阅读区给出安静的定位动作。带上锚点以便返回。位置用事件身份处理，图片后解码、补页或延迟回执仍能命中。用户上翻两页、发送一句、收到对端一条，再点看新消息并返回。全过程不自动夺走阅读，鼠标、键盘、触摸都能完成。
