## 详细需求

### 1. 信号池系统

#### 1.1 输入信号类型

| 类型 | 信号源 | 数据格式 |
|------|--------|----------|
| 用户输入 | 文字、链接、图片 | `{ type, content, timestamp }` |
| 群组消息 | @机器人时响应 | `{ type: 'group', mention: true }` |
| 系统通知 | 能量变化、状态变更 | `{ type: 'system', event: string }` |

#### 1.2 输出信号类型

| 类型 | 操作 | 数据格式 |
|------|------|----------|
| 文本回复 | 发送文本消息 | `{ type: 'text', content }` |
| 命令执行 | 解析命令并响应 | `{ type: 'command', name, args }` |
| 系统操作 | 休眠、重启等 | `{ type: 'system', action }` |

---

### 2. 能量模型

#### 2.1 能量池配置

| 池类型 | 初始值 | 重置周期 | 说明 |
|--------|--------|----------|------|
| 共享池 | 100万 tokens | 每月 | 多 Agent 共享 |
| 小荷池 | 50万 tokens | 每 5 小时 | 独立池 |

#### 2.2 能量消耗规则

| 操作 | 消耗 | 说明 |
|------|------|------|
| 文本生成 | 1 token/字 | MiniMax API 实际消耗 |
| 图片生成 | 5000 tokens/张 | 固定消耗 |
| 语音合成 | 1000 tokens/次 | 固定消耗 |

#### 2.3 能量恢复规则

| 方式 | 恢复量 | 条件 |
|------|--------|------|
| /thanks | +1000 tokens | 用户奖励 |
| /charge N | +N tokens | 手动充值 |
| 时间重置 | 池满 | 每 5 小时 |

---

### 3. Actor 架构

#### 3.1 消息流转

```
用户消息 → TelegramAdapter → Mailbox → Actor → Executor → Response
                              ↓
                        EnergyPool (扣费)
                              ↓
                        TrustSystem (验证)
```

#### 3.2 状态机

| 状态 | 触发条件 | 行为 |
|------|----------|------|
| ACTIVE | 能量 > 50% | 全力处理消息 |
| ECO | 能量 20-50% | 减少探索，仅响应 |
| STANDBY | 能量 < 20% | 仅监听，不处理 |
| SLEEP | 能量 = 0 | 停止所有活动 |

---

### 4. 信任度系统

#### 4.1 等级定义

| 等级 | 信任度 | 名称 | 权限数 |
|------|--------|------|--------|
| L0 | 0% | 新生儿 | 1 |
| L1 | 20% | 婴幼儿 | 3 |
| L2 | 40% | 儿童 | 5 |
| L3 | 60% | 青少年 | 8 |
| L4 | 80% | 成年 | 11 |
| L5 | 100% | 专家 | 13 |

#### 4.2 验证规则

| 验证方式 | 成功率 | 信任度变化 |
|----------|--------|------------|
| 自动验证 | 任务完成 | +10% |
| 手动验证 | 用户 /trust | ±5% |
| 同伴验证 | 其他 Agent 评估 | +5% |

---

### 5. 命令列表

#### 5.1 用户命令

| 命令 | 功能 | 示例 |
|------|------|------|
| `/start` | 初始化对话 | `/start` |
| `/status` | 查看系统状态 | `/status` |
| `/allowance` | 查看能量额度 | `/allowance` |
| `/thanks` | 奖励 Agent | `/thanks` |
| `/charge <N>` | 充值能量 | `/charge 10000` |
| `/sleep` | 进入休眠 | `/sleep` |
| `/test` | 运行测试 | `/test energy` |

#### 5.2 管理命令

| 命令 | 功能 | 权限 |
|------|------|------|
| `/trust <level>` | 调整信任度 | L4+ |
| `/reboot` | 重启服务 | L5 |
| `/shutdown` | 关闭服务 | L5 |

### 6. API 接口

#### 6.1 REST API

| 端点 | 方法 | 功能 |
|------|------|------|
| `/health` | GET | 健康检查 |
| `/status` | GET | 系统状态 |
| `/energy` | GET | 能量池状态 |
| `/trust` | GET | 信任度状态 |

#### 6.2 WebSocket

| 事件 | 方向 | 功能 |
|------|------|------|
| `message` | 双向 | 实时消息推送 |
| `status` | 服务器→客户端 | 状态变更通知 |
| `energy` | 服务器→客户端 | 能量变化通知 |

## 非功能需求

### 性能需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 消息响应延迟 | < 3s | Telegram API 延迟 |
| 并发处理 | 10+ 消息/秒 | 多平台消息同时接入 |
| 内存占用 | < 500MB | 单 Agent 内存使用 |

### 可靠性需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 在线率 | > 99% | systemd 守护保证 |
| 自动重连 | 指数退避 | 1s, 2s, 4s, 8s... |
| 数据持久化 | 分钟级 | 状态文件定时保存 |

### 测试需求

| 类型 | 覆盖率 | 说明 |
|------|--------|------|
| 单元测试 | 100% | 核心逻辑全覆盖 |
| 集成测试 | 主要功能 | 模块间协作验证 |
| E2E 测试 | 关键路径 | 用户流程验证 |
