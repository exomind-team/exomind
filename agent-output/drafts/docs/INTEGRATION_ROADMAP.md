## 1. 概述

### 1.1 文档目的

本路线图整合以下三个项目的核心能力，提出 ExoMind 系统的分阶段开发方案，并支持多端适配（Web/Tauri/Android）。

| 项目 | 来源 | 核心能力 |
|------|------|----------|
| **Exo Agents 多代理系统** | `wzy-agents-260203/` | 多代理协作、SSE 通信、记忆系统、健康监控 |
| **ExoBuffer Connector** | `ExoBuffer-Connector/` | 事件采集、实时同步、Fact/Analysis 数据模型 |
| **语音 IME 模块** | `exomind-model/` | 云端语音识别、TTS 语音合成 |

### 1.3 整合原则

| 原则 | 说明 |
|------|------|
| **复用优先** | 优先复用现有项目的成熟代码，避免重复造轮子 |
| **渐进式整合** | 分阶段整合，每个阶段产出可运行的最小系统 |
| **统一架构** | 采用 TypeScript + Rust 技术栈，保持架构一致性 |
| **数据兼容** | Fact/Analysis 数据模型统一，记忆系统分层设计 |
| **多端适配** | Web/Tauri/Android 同一功能多端体验一致 |

### 1.4 Agent 语言策略 ⭐

> **关键决策**: 主 Agent 使用 TypeScript，子 Agent 保留 Python

| Agent 类型 | 语言 | 理由 |
|------------|------|------|
| **主 Agent** | TypeScript | 与前端架构统一，复用现有代码 |
| **子 Agent** | Python | 复用 wzy-agents 的成熟实现 |
| **通信协议** | HTTP + SSE | 跨语言通信，兼容现有架构 |

## 2. 三个项目核心能力分析

### 2.1 Exo Agents 多代理系统 (`wzy-agents-260203/`)

**项目特点**：
- 文档驱动（文档占比 95.6%）
- 多代理并行运行，各司其职
- 记忆系统分层设计（短期 + 长期 9 领域）
- 双轨健康监控（技术健康 + 成长健康）

**核心模块**：

| 模块 | 文件 | 功能 |
|------|------|------|
| Agent 基类 | `agent.py`, `agent_async.py` | 消息处理、Claude CLI 调用 |
| SSE 通信 | `sse_agent.py`, `sse_agent_cluster.py` | 实时消息流式传输 |
| 记忆系统 | `memory/*.md` | 9 个分领域长期记忆 |
| RSS 收集 | `rss_infosource_collector/` | 信息源采集与整理 |

**提取复用**：
- Agent 基类架构
- SSE 客户端实现
- 记忆系统设计模式
- 健康检查机制

### 2.2 ExoBuffer Connector (`ExoBuffer-Connector/`)

**核心定位**：
- 事件采集与实时同步系统
- Append-only 数据存储
- SSE 多客户端实时广播

**数据模型**：

```typescript
// Fact - 事实记录
interface Fact {
  fact_id: string;      // 格式: f-{uuid}
  timestamp: number;    // 毫秒级 Unix 时间戳
  source: 'manual' | 'api' | 'tool';
  content_type: 'text' | 'url';
  content: string;      // 原始内容，禁止加工
  meta: FactMeta;
}

// Analysis - 分析结果
interface Analysis {
  analysis_id: string;  // 格式: a-{uuid}
  fact_id: string;      // 关联的 Fact
  analysis_type: 'sentiment' | 'note' | 'hint' | 'link';
  result: string;
  confidence: number;   // 0.0 - 1.0
}
```

**核心功能**：
- POST `/api/fact` - 创建 Fact
- GET `/api/facts` - 获取列表（支持过滤）
- SSE `/api/events` - 实时事件流
- 话题标签 + 关键词过滤

### 2.3 语音 IME 模块 (`exomind-model/`)

**核心能力**：
- 云端语音识别（ASR）
- 文本转语音（TTS）

**集成策略**：
- 优先使用云端 API（不考虑本地模型）
- ASR 结果直接输入 Agent
- TTS 输出 Agent 语音响应

## 7. 风险与应对

### 7.1 技术风险

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| Claude Code API 变更 | 高 | 抽象接口，隔离依赖 |
| Python→TS 迁移 | 高 | 渐进式迁移，保留 Python 子 Agent |
| 语音 API 延迟 | 中 | 本地缓存 + 流式处理 |
| SSE 连接不稳定 | 中 | 指数退避重连 |
| 内存占用过高 | 中 | 资源限制 + 定期清理 |
| 多端数据一致 | 高 | 统一数据源，事件溯源 |

### 7.2 进度风险

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 整合复杂度超预期 | 高 | 分阶段交付，可裁剪 |
| 依赖项目变更 | 中 | 锁定版本，分支管理 |
| 测试覆盖不足 | 中 | TDD 驱动，100% 覆盖 |
| 浏览器兼容性 | 低 | 现代浏览器即可 |
