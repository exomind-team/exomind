# Beta 标签与只增更正

Core9 是冻结 Beta16/Core8 之后的源码增量，尚未代表完整新候选验收。
当前进度和设备边界见[持续完成计划](../plans/2026-11-19-beta16-frozen-and-beta-completion.md)。

## 数据语义

标签仍属于 capture 的提交快照，按既有规范化规则保存；精确标签匹配可与正文搜索、
分页和固定 highwater 组合，标签不产生授权。旧的无标签查询保持原行为。

更正以独立 `correction/1` 事实保存目标 event ID、目标 digest 和新文字，原 capture
不覆盖。作者来自鉴权上下文，只有 Human 可追加；AgentNote、Observer 不可冒充。
已知目标不匹配会拒绝，目标尚未到达时可保留独立事实；查询分别报告 unresolved、
digest_matches、digest_conflict，不把乱序或冲突解释为已经改好。
同命令重试返回原回执；复制事实不会为接收端制造一条本地 Human 提交回执。

## 升级与复制

Core9 增加标签索引并扩展事实种类。迁移先验证旧结构、保留备份，再在事务中升级；
不得通过降 `user_version` 或重建空库假装兼容。旧事实字节、回执、身份、origin epoch、
位置与来源证明保持原值。当前已用冻结 Core8 引擎生成的合成档案验证升级及重启，
不将该结果外推成真实旧档案的来源密钥或缺失父事件已经恢复。

同档案业务同步继续严格匹配 schema。Core8/9 的 Hello 在事实交换前拒绝；应升级
相关设备，不能向旧端发送它不理解的 correction，再宣称“文字到了就同步成功”。
本机档案升级与跨版本 peer 互通是两条不同的合同。

## 展示与后续接线

Host 提供标签分页、更正追加与更正分页；Native 对应三个 `beta_*` 命令。
原文检索、更正检索与最新呈现的含义必须对齐，不把改过的文字显示出来却让它无法查找。
更正对历史回顾的覆盖变化仍需完成接线：保留旧派生结果，按新事实提示可更新，不能静默
改写旧总结，也不能忽略更正后宣称材料已完整。前端整理与完整候选验证继续执行。
