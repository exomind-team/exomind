# 评论策略与模板

## 评论类型

- 普通审核评论
- 无问题确认评论
- 需要人类测试评论
- 同一条评论中的引用回复

## 普通审核模板

使用 `[Codex Reviewer]` 作为前缀。

建议结构：

1. 结论
2. 问题
3. 验证方式
4. 下一步

## 无问题模板

在未发现问题时使用简短确认。

示例：

```text
[Codex Reviewer] 已审阅最新变更，未发现问题。
```

## 需要人类测试模板

使用 `[Codex Reviewer] ❤️ 需要人类测试` 作为前缀。

评论必须包含：

- 为什么机器审阅不足以完成判断
- 人类需要测试什么
- 应如何测试
- 什么结果算通过，什么算失败
- 已添加 `🙋needs-human-test` 标签的确认

## 回复风格

若需要回应多条已有意见，必须合并在同一条评论中。

引用格式：

```text
> 原文关键句
```

然后提供：

- 分析
- 验证方式
- 下一步建议

## 回读校验

评论发布后，必须回读并检查：

- 前缀是否合法
- 是否存在可疑的连续问号乱码
- 是否存在未转义的 `\n`
- 语言是否与 PR 一致

若评论未通过校验：

- 先将修正版草稿写入 `./temp/`
- 再通过 `gh api` 编辑评论
- 编辑后重新校验

## 语言策略

使用 PR 的主语言。

推荐判定顺序：

- PR 标题语言
- PR body 语言
- 现有讨论语言

没有充分理由时，不要在同一条评论中随意切换语言。

## 标签策略

只有在机器审阅无法安全验证目标行为时，才添加 `🙋needs-human-test`。

不要因为纯推测性担忧就添加该标签。

## 审批与合并门禁

### 批准（approve）

必须同时满足：

- 当前无阻塞问题
- 先前提出的问题均已修复
- CI 通过
- 本地验证通过

### 合并（merge）

必须同时满足：

- approve 条件已经满足
- 每个审阅项都有验证结果
- 没有剩余待执行工作
- 不再存在有效的 `🙋needs-human-test` 标签
