## 2. Blackboard Phase 1 已定合同

### 2.1 定位与范围

- `blackboard` 仍是**每档案一个持久对象**
- 但其 Phase 1 语义收口为：
  - 临时草稿
  - 协调便笺
  - 交接摘要
- Phase 1 只测试：
  - 信息记录
  - 信息存储
  - 信息读写
- 不在 Phase 1 做：
  - 自动提升到任务
  - 自动提升到提案
  - 共享长期记忆池

### 2.2 条目模型

- Phase 1 的内容单位采用：**时间序条目**
- 变更模型采用：**追加修正**
- 保留语义采用：**语义临时**
- 读写接口采用：**数据对象读写**

### 2.3 写入者与归因

- 默认可写入者：
  - 成员
  - 授权 Agent
- 每条记录至少归因到：
  - 作者
  - 座席 / 设备

### 2.4 空间与计量

- `blackboard` 应被视为一种**actor 空间资源**
- Phase 1 默认采用：**每黑板总上限**
- 空间占用默认计算：
  - 所有仍保留在黑板中的条目
- 空间接近或达到上限时默认：
  - 先预警
  - 再阻写

### 2.5 移出与释放空间

- Phase 1 需要显式“移出黑板”动作
- 第一条最小可实现动作收口为：
  - **弹出最早条目**
- 默认可执行者：
  - 成员
  - 授权 Agent
- Phase 1 先不做：
  - pin / protect
  - “别弹这条”保护机制
- 触发方式默认：
  - **显式执行**

### 2.6 弹出后的去向

- Phase 1 中，条目被移出黑板后默认：
  - **直接离开黑板存储**
  - 不自动提升到任务 / 提案
  - 不自动转入另一套黑板内归档区
- 之所以允许“直接删除”，是为了让空间上限成为真实约束，而不是假约束

### 2.7 信号回送语义

- `blackboard` 可以接收来自其他节点的交互型信号
- 只有**交互型请求**才默认创建后续回送关系
- 当执行“弹出最早条目”时：
  - 弹出的内容可作为信号回送给原发起者
- 删除时机收口为：
  - **回送成功进入发送流程后再删除**
- 若回送失败：
  - 条目保留在黑板
  - 本次操作报错

### 2.8 回链 / 连边语义

- 这里不引入“一次性 reply 通道”或“隐藏私有回链”这种特殊机制
- 本轮最终收口为：
  - 这类回链就是**正式连边**
  - 进入**档案级持久路由**
  - 在 **route editor** 中可见
- 当前默认原则：
  - 不额外发明新的连边类型
  - 节省实现复杂度
  - “建立连边”与“连边当前是否起效”继续分开理解

### 2.9 本轮刻意不锁死的点

以下点本轮只明确“不按旧说法继续写”，但不继续深挖：

- 弹出 / 删除动作是否需要额外 retained tombstone
- 黑板移出动作与更广义审计系统的最终关系
- 黑板条目提升到任务 / 提案的正式产品故事

这些点后续分别并入“审计界面”或第二阶段产品讨论。

## 3. 扩大讨论问题簇

以下主题当前都**不在本轮直接收口**，而是只记录问题簇，后续再与 `@HailayLin` 专门讨论。

### 3.1 `集体档案的Agent`

当前最小已定值只有一条：

- 集体 Agent 第一阶段最小现实形态，默认先挂在：**座席主机**

但以下问题本轮不继续强行定稿：

- 多个成员设备同时在线时，如何定义“唯一执行”
- 分区、断连、重连条件下，双执行 / 双提交如何认定与收敛
- 持久状态的真相源是否最终固定为“档案真相 + 宿主缓存”
- 没有合适宿主在线时，未执行任务以何种语义保留
- 路由信号、定时唤醒、成员手动触发、提案批准后执行这几类来源如何分层
- 哪些副作用允许自动提交，哪些必须额外门禁

### 3.2 `档案防伪 / 公开标识轮换`

本轮明确只记问题，不继续讨论答案。

后续问题簇至少包括：

- 防伪到底面对什么威胁模型
- 公开标识稳定性与轮换能力如何兼容
- `PublicCard`、公开标识、邀请材料分别承担什么信任责任
- 标识泄露、撞库、冒名、旧标识失效时怎样应对
- 是否需要签名、见证或其他证明材料

### 3.3 `审计界面`

本轮明确只记问题，不继续讨论答案。

后续问题簇至少包括：

- 对象局部历史与全局审计总控台如何分层
- `blackboard` 的移出 / 删除动作是否需要额外可见痕迹
- 审计本身占用多少空间才是可接受的
- 人类、成员、Agent 分别能看到哪些审计面
- 审计是否需要独立 UI 表面，还是继续嵌入现有对象视图

本轮真正新增的稳定判断是：`blackboard` Phase 1 要按“**语义临时 + 容量受限 + 数据对象读写 + 显式弹出 + 正式连边回送**”来写；而 `集体档案的Agent`、`档案防伪 / 公开标识轮换`、`审计界面` 则统一改为“**记录问题簇，后续与 @HailayLin 扩大讨论**”。
