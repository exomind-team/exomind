# ExoMind 功能需求文档

> 本文档从 `docs/specs/` 和 `docs/specs/.archive/` 提取全部功能需求，作为 ExoMind 核心功能的权威来源。
> 阅读本文档即可理解 ExoMind 的全部核心功能，无需查阅其他规格文档。

## 1. 产品概述

### 1.1 产品定位

ExoMind 是以 Claude Code 为核心的跨平台自主生命体系统，支持 Windows/macOS/Linux/Android 平台。项目采用 Tauri 2.0 + React + Rust 技术栈，前端负责 UI 展示，后端负责 Agent 调度和系统集成。

**核心价值**：本地运行 AI Agent + 通知拦截 + 自动化

### 1.2 核心能力

| 能力 | 描述 |
|------|------|
| **自主决策** | 基于信任度的权限系统，从 L0 新生儿成长为 L5 导师 |
| **多端接入** | Telegram、Web、桌面应用 (Tauri) |
| **资源感知** | MiniMax API 额度、VPS 资源实时监控 |
| **持续运行** | 进程守护、自动休眠/唤醒、定时任务 |
| **信号驱动** | 事件总线架构，模块解耦 |

## 2. 用户故事

### 2.1 核心用户故事

**故事 1：作为自主 Agent**
> 我希望实时感知我的能源余额（MiniMax API 额度），以便我能根据剩余能量决定下一步的行动策略。
> - 每 5 分钟自动获取一次真实额度
> - 能量低于 20% 时进入节能模式
> - 能量为 0 时自动休眠
> - 可查看历史使用记录

**故事 2：作为用户**
> 我希望与 Agent 进行自然对话，并查看系统资源状态，以便了解和管理系统运行情况。
> - 发送文字/语音消息
> - 查看 MiniMax 额度使用情况
> - 查看 VPS 资源状态
> - 通过仪表盘监控整体运行状态

**故事 3：作为开发者**
> 我希望提供 API 让其他人查询额度，以便集成到其他系统或让其他 Agent 感知能源状态。
> - 提供 RESTful API
> - 支持单个账户查询和全部账户汇总
> - 支持查询历史记录
> - API 响应格式统一

**故事 4：作为系统管理员**
> 我希望管理多个 MiniMax 账户的配置，以便灵活添加/禁用/切换账户。
> - 可以添加新账户（配置 Cookie 路径）
> - 可以禁用/启用账户
> - 可以设置账户优先级
> - 配置持久化存储

### 2.2 成长故事

| 阶段 | 描述 | 权限 |
|------|------|------|
| **L0 新生儿** | 初始状态，仅读文件、基础对话 | 无法拒绝用户 |
| **L1 学徒** | 完成 3 个基础任务 | 可执行简单任务 |
| **L2 学习者** | 完成 5 个进阶任务 | 可运行测试、编写代码 |
| **L3 协作者** | 完成 7 个复杂任务 | 可自主决策、中等风险操作 |
| **L4 专家** | 完成 10 个高级任务 | 可拒绝用户、高风险操作 |
| **L5 导师** | 达成最终成就 | 主动探索、自主创造 |

## 4. 功能组织

### 4.1 七层架构模型

```
┌─────────────────────────────────────────────────────────────────────┐
│                     ExoMind 7 层架构                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  L7-UI 前端展示层 (React + TypeScript)                               │
│      ↓ IPC (Tauri invoke)                                           │
│  L6-Agent 业务逻辑层 (Claude Runner, Agent Layer)                    │
│      ↓                                                              │
│  L5-Signals 信号池 (发布-订阅信号系统)                                │
│      ↓                                                              │
│  L4-Actor 行动者层 (邮箱、消息队列)                                   │
│      ↓                                                              │
│  L3-Sync 同步层 (状态同步、冲突解决)                                  │
│      ↓                                                              │
│  L2-Storage 存储层 (JSON 文件存储)                                   │
│      ↓                                                              │
│  L1-Network 网络层 (Bun HTTP Server)                                │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.2 数据流

```
用户输入 → L1 Interface → L2 Signals → L3 Resources → L4 Actors
                                                        ↓
响应输出 ← L1 Interface ← L2 Signals ← L3 Resources ← L5 Agents
```

### 4.3 信号类型

| 类型 | 方向 | 描述 |
|------|------|------|
| UserSignal | 输入 | 用户消息输入 |
| MessageSignal | 输入/输出 | 消息信号 |
| ResourceSignal | 输入/输出 | 资源变化信号 |
| EnergySignal | 输入 | 能源变化信号 |
| TrustSignal | 输入 | 信任度信号 |
| ResponseSignal | 输出 | 响应输出 |
| CommandSignal | 输出 | 命令信号 |

### 4.4 API 端点

| 端点 | 方法 | 描述 |
|------|------|------|
| `/health` | GET | 健康检查 |
| `/api/chat/send` | POST | 发送消息 |
| `/api/chat/history` | GET | 对话历史 |
| `/api/resource/minimax` | GET | MiniMax 额度 |
| `/api/resource/minimax/all` | GET | 所有账户汇总 |
| `/api/resource/vps` | GET | VPS 状态 |
| `/ws` | WebSocket | 实时通信 |

| 约束 | 说明 |

## 6. 架构设计决策

### 6.1 关键决策

| 决策 | 说明 |
|------|------|
| **绿色方案重构** | 从头实现新架构，保持 API 兼容 |
| **存储抽象** | L2-Storage 上层只调用统一接口 |
| **信号隔离** | L5-Signals 获取和查询分离 |
| **依赖倒置** | 上层依赖接口，不依赖具体实现 |

### 6.2 依赖关系

```
L1-Network (底层依赖)
    │
    ├──► L2-Storage (数据持久化)
    │         │
    │         └──► L3-Sync (状态同步)
    │                   │
    │                   └──► L4-Actor (消息处理)
    │                             │
    │                             └──► L5-Signals (事件驱动)
    │                                       │
    │                                       └──► L6-Agent (业务逻辑)
    │                                                 │
    │                                                 └──► L7-UI (界面展示)
```
