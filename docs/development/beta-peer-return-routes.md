# 已认证连接的返拨地址与原件队列

一次连接能双向交换文字，不代表接收端已有新建原件下载连接所需的来源地址。
Beta19 真机在 EasyTier 下出现过这一差异：原件元数据到达，但来源 route 为空，
624 KiB 小件在自动策略开启、上限 8 MiB 时仍未取回。

## 当前修复

Join service/2 在已固定身份的 TLS 会话中交换最多 8 条返拨候选；service/1 与旧
transport ALPN 保留。持久写入前复核成员 Ready、pin、generation 和取消状态，
地址不能创建成员、改变权限或替代邀请。代理观察到的本机 loopback 地址仍会过滤。

路由合并优先保留最近成功地址，再接纳新的已认证候选，最后补足旧候选，最多 8 条。
满缓存不能吞掉刚收到的可达候选；成功过的地址也不能被一批未验证候选挤掉。
无路由时原件进入可解释的等待来源状态，不能仅显示 idle 且没有原因。

队列只轮转本机 Ready 且有原件读取权限的成员档案。成员元数据每页最多 16 行，
缓存游标绑定成员 generation，空页和尾页不占缓存。网络路由读取受既有全局成员/
路由上限约束，不随 Core 中全部未共享档案增长。恢复请求仍沿用独立的逐原件退避、
来源轮换、取消、hash mismatch 和授权门控。

## 证据范围

Windows 上真实 Host/PeerNetwork 的代理邀请、旧 V1 TLS Join、错误 pin/旧代次/
取消写入，以及 256 个 Solo 档案后的共享原件均已通过。关键来源读取会建立新的
固定身份 TLS 会话，不能用 plain TCP 通或文字到达代替这层证明。

这部分是 Beta19 之后的源码增量。最终同版本 PC/Android 包、真实 EasyTier 路由、
切网与后台恢复仍须另验；Core11 严格拒绝 Core10 peer 事实交换，升级时两端版本
必须匹配。外部 Agent HTTP `exomind-beta/1` 和旧 Runtime `/act/*` 没有因此改协议。
