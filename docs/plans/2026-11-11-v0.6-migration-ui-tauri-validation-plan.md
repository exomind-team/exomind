## 1. 目标与已确认方向

本路线拆成两个有独立验收与存盘点的阶段。**Alpha 选择性搬迁可复用骨架，Beta 在骨架上形成新版。**不能把两阶段的代码、需求和验收混成一个大改版。

### 第一阶段：0.6.0-alpha——选择性迁移旧版桌面骨架

从现有 0.5 开发源码选择性搬迁可复用的产品骨架，允许少量、可解释、可回退的适配和边界重构。重点抽出 Tauri 独立桌面窗口、全局快捷键、托盘、窗口/进程生命周期及系统集成；可保留旧版主界面外壳和品牌配色作为连续性基础，但不要求把全部旧业务枝叶搬入 Alpha。桌面 Alpha 必须产出实际 Windows exe，并完成真窗验收。

Alpha 是可运行、可回滚的骨架检查点，不是 0.5 的数据升级版。Alpha 测试使用新的隔离目录和合成数据；不读取、不导入、不覆盖旧版档案。候选 Node `next/` 不得进入 Alpha 的文件集、版本包或提交。

Alpha 完成后，先将该阶段作为独立 Git 检查点提交并推送到 `dev-0.6`，并保留可回滚的 `0.6.0-alpha` Windows exe。只有这一检查点完成后，才开始 Beta 的大改造。此处“推送存盘”指 Git 分支检查点；是否创建公开 Release/正式发布另按仓库发布治理执行。

### 第二阶段：0.6.0-beta——从 Alpha 出发形成新版

从已推送的 Alpha 检查点继续，才进行真正的架构、UI/UX、交互和功能重构。Pro Web Demo 中经核查的行为、边界和测试用于启发与对照；不照搬其静态外观，也不把其 Node Runtime 当正式核心。Beta 可采用新数据结构与存储形式，无需兼容 0.5 数据；整体配色风格保持承接，并结合 arc-ui-design 形成特色。保持关键日用能力，并交付 Rust RT、Web 前端与 Tauri 宿主协同的 Windows Beta exe。

### 用户确认的最终技术方向与产品边界

1. **Tauri App 是正式产品宿主**：Alpha 优先搬迁独立桌面窗口、全局快捷键、托盘及生命周期；Beta 在此骨架上调整窗口规则。Android 若进入 Beta 目标，也使用明确的原生承载和后台方案。
2. **Rust RT 是可扩展核心**：拥有运行时能力和本机最终 apply 权威；Web 是可灵活组织的前端，不承担长期同步调度或业务真相主权。Node 候选仅作 Beta 参考与行为对照。
3. **Alpha 搬骨架，Beta 填枝叶**：Alpha 选择性复用旧代码，为窗口、快捷键、托盘和生命周期建立独立可运行的宿主；Beta 再填充/裁剪功能并重做布局、交互、动效和连通性。
4. **按当前用途精简 Beta**：不再自建任务管理；保留时间块开始、暂停/恢复、结束、状态、备注与反馈、自动总结、悬浮呈现，以及文字/图片/文件收集。已配对设备应自动同步，离线后补齐；原件保留至用户主动清理。
5. **先打通简单、组合式的单通道**：优先验证现有 EasyTier 网络上的同版本设备连通、认证、持久化和补齐；避免把配对流程设计得比用户需要更繁琐。协议断代需与同版本互通、迁移说明及匹配的新 Agent skill 一起交付。
6. **Beta 使用新数据模型**：不实现 0.5 数据自动兼容或隐式迁移。Beta 的新 schema、存储和事件形式以新目标设计；测试使用合成数据，旧档案只作背景对照。任何未来旧数据导入都作为独立、明确授权的工具/流程，不阻塞 0.6 Beta。

WinCraft 可以承担悬浮窗主要 UI，外心提供状态接口或 provider 抽象；这是 Beta 可评估的组合方案，不是 Alpha 的前置条件，也不能在真实宿主验证前替代 Tauri 窗口骨架。主窗口、快捷键和托盘是 Alpha 骨架与 Beta 成品都要具备的桌面能力。

## 5. 两阶段 UI / UX 与交互基准

**Alpha 的判断标准是“旧版中可复用的桌面骨架已独立运行”。**从旧代码中选择性抽取主窗、悬浮窗、全局快捷键、托盘与生命周期；保留旧版暖色品牌与必要的最小页面外壳，不要求搬完业务模块，也不在 Alpha 开始 Beta 的大规模布局/交互重写。

**Beta 的判断标准是“在 Alpha 骨架上形成完整的新产品”。**可以重排布局、交互、动效和连通性，移除当前用途不成立的任务管理，并组合即时图文收集、时间块回顾与同步。整体配色保持旧版暖色石色语汇的连续性，再结合 arc-ui-design 提炼特色；Web Demo 提供行为参考，不要求像素级复刻。Beta 使用新数据结构，不兼容 0.5 数据。

| 表面 / 任务 | Alpha：选择性迁移系统骨架 | Beta：填充与重构目标 |
|---|---|---|
| 应用壳与主题 | [全局 token](../../src/index.css)、`tailwind.config.js`、[UI 规范](../development/ui-spec.md)、[#807 计划](2026-04-02-issue-807-ui-unification-implementation-plan.md)；承接旧版暖色品牌、主题 token 与最小页面外壳；不要求迁完所有业务页面 | 允许重组信息架构、布局、交互与动效；保持暖色石色系连续性并结合 arc-ui-design 做特色，用真实容器验证焦点、反馈和窄屏操作 |

**Alpha 基线采集**：使用隔离的旧版开发实例和合成数据，记录主窗、悬浮窗、全局快捷键、托盘与退出/隐藏生命周期。当前只拿到运行中 PC v0.5.1 的可访问结构，尚无可用截图/动效录制；补齐隔离真窗证据后再验 Alpha 骨架与配色连续性。不可将含个人记录的日用窗口截图放进仓库或交接包。

**Beta 对照采集**：对照同一组匿名合成场景，分别观察 Alpha 旧界面、Web Demo 行为和 Beta 页面；记录哪些旧路径保留、替代或移除及其证据。截图只证明几何/视觉，交互录制与真实宿主操作才证明时序/行为。
