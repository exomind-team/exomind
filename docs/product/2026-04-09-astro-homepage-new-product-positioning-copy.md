# ExoMind Astro 首页新产品定位文案

> 日期：2026-04-09  
> 用途：作为 ExoMind Astro 首页后续改版的产品定位与文案总纲  
> 结构说明：本文按金字塔原理组织，先给全文概要结论，再逐层展开到定位、页面结构与证据

---

## 1. 全文概要结论

ExoMind 不应被定义为“笔记软件”或“Agent 编排平台”的折中物，而应被定义为：

**一个面向个人成长的个人外心，也是一个新一代认知操作系统。**

这一定义对应三条总纲：

1. **前台价值主线是成长闭环，不是功能堆叠**
   - 用户首先感知到的应是记录、上下文恢复、任务推进、复盘沉淀，而不是“多 Agent 编排”。
2. **后台差异来自 Agent 运行机制，不是普通 AI 助手**
   - Agent 是执行层，负责让系统持续记忆、持续推进，而不是每次从空白开始。
3. **基础设施差异来自本地档案与去中心化多端组网**
   - ExoMind 不是传统“文档副本同步型笔记软件”，而是可以在多节点上持续接续的运行时系统。

如果只保留一句对外表达，应写成：

**ExoMind 是一个记得你是谁的个人外心。**

如果只保留一句对内表达，应写成：

**ExoMind = 成长闭环前台 + Agent Workbench 执行层 + 去中心化多端组网基础设施 + 认知生命理论约束层**

## 2. 第一层展开：产品到底是什么

### 2.1 对外定位

对外不应再问“它更像笔记软件还是 Agent 平台”，而应直接回答“它是什么”：

- `个人外心`
- `认知操作系统`
- `多端互联的持续记忆系统`

三者不是竞争关系，而是同一产品的不同翻译层：

- `个人外心` 解决第一眼理解
- `认知操作系统` 解决品类拉升
- `多端互联` 解决与普通笔记软件的区分

### 2.2 对内定义

对内产品结构应固定为四层：

1. `成长闭环前台`
   - 事件日志、时间块、任务、复盘
2. `Agent 执行层`
   - 上下文恢复、Agent 推进、过程记录与回放
3. `基础设施层`
   - 本地档案、去中心化多端组网、边界隔离
4. `理论约束层`
   - 持续运行、边界、不可删除、生命判据

### 2.3 明确它不是什么

为了避免官网滑回旧心智，需要同时排除两种错误定义：

- 它不是“更贵的 AI 笔记软件”
- 它不是“面向开发者的 Agent 编排平台”

前者会压扁差异化，后者会抬高理解门槛。

## 3. 第二层展开：为什么必须这样定义

### 3.1 为什么“笔记软件”不能做产品帽子

一旦进入 Obsidian / Notion / 备忘录的比较框架，ExoMind 最关键的能力会被误读为普通功能点：

- 持续记忆
- 上下文延续
- 主动推进
- 复盘沉淀

结果是用户会以“记笔记好不好用”来评估它，而不是以“它是否形成了持续运行的认知闭环”来评估它。

### 3.2 为什么“Agent 编排”不能做首页主类目

`编排`、`多智能体`、`Agent Platform` 这类语言更适合开发者，不适合普通用户首屏理解。

问题不在它不准确，而在它会带来错误流量和错误预期：

- 普通用户会被吓跑
- 开发者会把它直接拿去对标 GoLutra
- 产品真正的成长叙事会被运行时术语吞掉

因此，首页应该翻译 Agent 价值，而不是直接展示 Agent 术语。

### 3.3 为什么“局域网同步”必须升级为“去中心化多端组网”

`局域网同步` 只描述传输环境，不能描述 ExoMind 的产品本质。

当前架构更接近：

- `device pairing`
- `RT ↔ RT` 直接通信
- `Discovery + Channel Establishment + Relay`
- `signal replication + backfill`
- `profile / archive scope` 隔离

因此，ExoMind 与传统笔记软件的差异不是：

- “是否支持同步”

而是：

- “同步文档副本” vs “组网运行时节点”

建议固定三层表述：

- 面向普通用户：`多端互联`
- 面向产品能力：`去中心化多端组网`
- 面向技术叙事：`基于 ECS 软总线的 RT 组网`

需要同时保留真实边界：

- 当前近期里程碑仍是“个人同步基线”
- 所以可把“组网”作为架构级差异
- 但不能把它表述成已经完全成熟的广义多节点网络产品

## 4. 第三层展开：官网应该如何逐步披露

### 4.1 Hero 只回答一个问题

Hero 不负责解释全部产品，只负责让用户立刻知道：

**“这不是又一个会遗忘我的工具。”**

因此 Hero 只做三件事：

1. 说出认知痛点
   - 例如：忙了一天，却说不清最重要的事是什么
2. 给出价值承诺
   - ExoMind 记得，而且下次不从空白开始
3. 给出行动句
   - `开始建立一个人的外心`

### 4.2 Features 再展开成三层

Features 不应平铺功能卡，而应在 Hero 之后做第一次结构化展开：

1. `成长闭环层`
   - 事件日志
   - 时间块
   - 任务 / 复盘
2. `Agent 网络层`
   - 上下文恢复
   - Agent 推进
   - 工作过程记录与回放
3. `基础设施层`
   - 本地优先
   - 去中心化多端组网
   - 档案隔离 / 用户掌控边界

这三层正好对应用户从“我需要它吗”到“它为什么不一样”的认知展开。

### 4.3 About 再解释深层原则

About 才负责第三层披露，解释这些“为什么”：

- 为什么它不是普通笔记软件
- 为什么它不是普通聊天工具
- 为什么强调持续运行、边界、不可删除
- 为什么 `Build your exomind` 在前，`Connect exominds` 在后

也就是说：

- Hero 讲感知
- Features 讲结构
- About 讲原理

## 5. 第四层展开：推荐文案

### 5.1 一句话定位

`ExoMind 是认真对待自己生命的人使用的个人外心，也是你的新一代认知操作系统。`

### 5.2 官网副标题

`它帮你记住真实发生过的事，延续你的上下文，在多台设备上持续接续，并让 AI 在下一次继续从你自己开始。`

### 5.3 团队内部定义

`ExoMind = 成长闭环前台 + Agent Workbench / Signal Network 执行层 + 本地档案 / 去中心化多端组网基础设施 + 认知生命理论约束层`

## 6. 执行动作

### P0

- 把首页 Hero 从“生命成长助手”收紧到“持续记忆 / 上下文延续”
- 把 `AI 智能体` 从平级功能卡改为贯穿式机制表达

### P1

- 在 Features 中固定“成长闭环层 -> Agent 网络层 -> 基础设施层”
- 把“局域网同步 / 多设备同步”降级为子能力，把总概念提升为“多端互联 / 去中心化多端组网”
- 在 About 中补齐“为什么它不是普通软件”的桥接段

### P2

- 首页文案 A/B：
  - A：`记忆搭档 / 认知伴侣`
  - B：`个人外心 / 认知操作系统`
