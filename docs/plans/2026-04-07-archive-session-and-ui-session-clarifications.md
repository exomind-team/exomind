# 2026-04-07 ArchiveSession 与 UiSession 第一阶段澄清

> 状态：本轮补充落盘
>
> 目的：把近期围绕 `ArchiveSession`、外部 UI 连接、切档案事务与自动恢复语义的讨论结果单独摘出，避免继续让主线文档混杂旧的“RT 全局前台 / suspended”表述。

---

## 1. 计划摘要

本轮最重要的语义修正有四条：

- `ArchiveSession` 更像某个 `RT` 上某个档案的本地运行会话，而不是“当前激活档案”的 UI 别名
- 外部 UI 连接应单独建模为 `UiSession / ClientSession`
- `前台 / 后台` 是 **UI 视角** 的概念，不是 `RT` 状态机概念
- 第一阶段 `ArchiveSession` 状态机从旧的 `running / suspended / stopped` 收口为：
  - `running`
  - `closed`

---

## 2. ArchiveSession 最小合同

### 2.1 语义

- `ArchiveSession` 表示某个 `RT` 上某个档案的本地运行时会话
- 它是 `RT` 本地对象
- 不跨 `RT` 同步
- 其真相应落在 `RT` 本地会话元数据中

### 2.2 状态机

第一阶段最小状态机收口为：

- `running`
- `closed`

本轮明确不再把以下概念塞进 `RT` 状态机：

- 前台
- 后台
- `suspended`

这些都不应再作为 `ArchiveSession` 的第一阶段核心状态。

### 2.3 自动恢复

- `RT` 会记录每个档案会话的本地运行状态
- 只要会话没有被明确关闭，`RT` 重启后默认自动恢复
- 这类“自动恢复”偏好挂在：
  - **RT 本地会话元数据**
- 不挂在：
  - 档案级跨 RT 设置
  - 单个 UI 客户端的临时历史

---

## 3. UiSession / ClientSession 最小合同

### 3.1 为什么要单独建模

基于本轮讨论，档案更像操作系统中的用户，而外部 UI 更像终端 / 客户端连接。

因此：

- `ArchiveSession` 不是外部 UI 连接本身
- 外部 UI 连接需要单独建模成：
  - `UiSession`
  - 或 `ClientSession`

### 3.2 第一阶段收口

第一阶段默认采用：

- `UiSession / ClientSession` 是 `RT` 本地一等对象
- 一个 UI 客户端同一时刻只连接一个档案
- 同一档案在同一 `RT` 上，第一阶段只允许一个 UI 连接
- `RT` 侧对 UI 会话只先跟踪：
  - `connected`
  - `disconnected`

当前明确不在 `RT` 侧引入：

- `active / inactive`
- 前台 / 后台
- 可见性层级

---

## 4. UI 视角的前台 / 后台

### 4.1 基本原则

- “前台档案”是 **UI 当前连接着的那个档案**
- “后台档案”是 **该 UI 当前未连接、但在 RT 中仍处于 running 的档案**
- 这是：
  - `RT` 运行状态被 UI 反映后形成的派生概念

它不需要在 `RT` 状态机中单独存储。

### 4.2 第一阶段边界

- 不再追求“设备全局唯一前台”
- 尽量避免把“设备”作为核心架构抽象
- 因为一个物理设备完全可能同时运行多个 `RT`

---

## 5. 连接、断开与关闭

### 5.1 UI 连接激活运行态

当一个 UI 去连接某个当前未运行的档案时，第一阶段默认：

- **自动拉起该档案的 `ArchiveSession`**

### 5.2 断开连接 vs 关闭会话

本轮明确区分：

- **断开 UI 连接**
- **关闭 ArchiveSession**

它们不是同一个动作。

### 5.3 最后一个 UI 断开

如果某个档案在一个 `RT` 上最后一个 UI 也断开了，第一阶段默认：

- 会话继续运行

但档案可配置：

- “最后一个 UI 断开时是否自动关闭会话”

### 5.4 UI 侧停止会话

UI 可以显式执行：

- 停止会话
- `logout`

其默认作用范围是：

- 当前 UI 正连接着的那个 `ArchiveSession`

不波及同一 `RT` 上其他档案会话。

---

## 6. 切档案事务

### 6.1 默认快捷策略

第一阶段默认开启 UI 侧快捷策略：

- **自动关闭切出的档案**

### 6.2 固定流程

当 UI 从档案 A 切到档案 B 时，固定流程为：

1. 先启动 / 连接新档案 B
2. 若失败，则回退到旧档案 A
3. 若成功，再请求关闭旧档案 A
4. 若关闭 A 失败，仍切到 B，但需要把 A 的关闭失败显式反馈出来

也就是说：

- “切换成功”优先指向新档案已成功拉起
- 旧档案关闭失败不应把 UI 再强行切回去

---

## 7. 一句话总结

这一轮之后，`ArchiveSession` 应按“**RT 本地运行会话**”理解，`UiSession / ClientSession` 应按“**外部 UI 终端连接**”理解；第一阶段不再把“前台 / 后台 / suspended”混进 `RT` 状态机，而改成“**UI 侧前台 / RT 侧 running/closed + 连接/断开**”。
