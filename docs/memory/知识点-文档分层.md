# 知识点：文档分层

> 架构设计、模块规格、其他文档的功能区分与目录结构

---

## 场景：架构设计与模块规格容易混淆

**问题**：两者都涉及"设计"，容易写重复或界限不清。

**核心区分**：
- **架构设计** = 系统蓝图（**整体怎么搭**）
- **模块规格** = 施工图纸（**这个模块怎么做**）

---

## 三者的功能对比

| 维度 | 架构设计 | 模块规格 | API 文档 |
|------|---------|---------|----------|
| **范围** | 系统**整体** | 单个**模块** | 单个**接口** |
| **视角** | 宏观、全局 | 微观、局部 | 实现细节 |
| **读者** | 架构师、新成员 | 开发者、测试 | 使用者 |
| **内容** | 7层架构、模块关系、数据流向 | 设计理由、功能、验收标准 | 参数、返回值、示例 |
| **位置** | `docs/architecture/` | `docs/specs/` | 代码注释 + `docs/api/` |
| **变更频率** | 低（架构稳定后少变） | 高（随需求迭代） | 中（随接口变化） |

## 目录结构方案

```
docs/
├── architecture/                    # 【系统蓝图】
│   ├── README.md                    # 架构总览
│   ├── 7-LAYER.md                   # 7层架构详解
│   ├── DATA-FLOW.md                 # 数据流向设计
│   ├── INTERFACE.md                 # 模块接口定义
│   └── DECISIONS/                   # 架构决策记录 (ADR)
│       ├── ADR-001-why-signal-pool.md
│       ├── ADR-002-why-tauri.md
│       └── TEMPLATE.md
│
├── specs/                           # 【施工图纸】
│   ├── README.md                    # 规格总览
│   ├── SPEC-201-SignalPool.md       # 模块详细规格
│   ├── SPEC-202-AgentLayer.md
│   └── TEMPLATE.md                  # 规格模板
│
├── api/                             # 【接口手册】
│   ├── README.md
│   └── XXX.md
│
└── FRONTEND_STACK.md               # 其他专项文档
```

## 内容示例对比

### 架构设计（整体蓝图）
```markdown
# docs/architecture/7-LAYER.md

## L5 - SignalPool 层
- **职责**：全应用状态管理
- **上游**：L6 业务逻辑层
- **下游**：L4 终端执行器
- **接口**：SignalPool.subscribe() / emit()
- **数据流向**：业务事件 → 信号分发 → 状态更新
```

### 架构决策（为什么）
```markdown
# docs/architecture/DECISIONS/ADR-001-why-signal-pool.md

## 决策：使用发布-订阅模式替代直接调用

### 原因
- 解耦生产者与消费者
- 支持多个订阅者
- 便于调试和追踪

### 替代方案
- 直接函数调用（rejected：耦合度高）
- Redux（rejected：过于复杂）

### 影响
- 引入消息队列复杂度
- 需要处理订阅生命周期
```

### 模块规格（施工图纸）
```markdown
# docs/specs/SPEC-201-SignalPool.md

## 功能定义
- 信号注册：registerSignal(type, handler)
- 信号订阅：subscribe(type, callback)
- 信号发布：emit(type, payload)

## 设计理由
选择发布-订阅模式是因为...

## 验收标准
- [ ] 支持100+信号类型
- [ ] 订阅回调延迟 < 10ms
```

## 记忆口诀

```
架构是蓝图 —— 整体怎么搭
规格是图纸 —— 模块怎么做
决策是理由 —— 为什么选择
API 是手册 —— 怎么用
```

---

## 常见错误

| 错误 | 正确做法 |
|------|----------|
| 在 SPEC 里写整体架构 | SPEC 只写本模块，架构引用 architecture/ |
| 在架构里写实现细节 | 架构只写接口边界，实现在 SPEC |
| 设计理由分散在各处 | 统一放在 DECISIONS/ 中 |
