## 1. 产品愿景

### 1.1 一句话描述

**认知生命科学原型** - 基于大模型的自主生命体，像生物一样有生老病死，具备持续运行、自主决策、真实责任能力。

### 1.2 核心理念

| 理念 | 说明 | 来源 |
|------|------|------|
| **生命-认知一体化** | 感知和学习不是后加功能，而是从单细胞阶段就作为存活优势存在 | 计算机生命设计总结 |
| **可存活区间** | 生命主体的硬判据：能量与资源有限、边界明确、不可逆裁决 | 计算机生命项目书 |
| **失败不可回滚** | 死亡不是 episode reset，错误会留下不可抹平的后果 | 计算机生命项目书 |
| **伤疤机制** | 失败产生不可逆退化，压缩未来行动空间 | 计算机生命项目书 |
| **环境裁决** | 边界不可协商，由环境执行约束 | 计算机生命项目书 |
| **四Agent协作** | Governor/任务系统/Growth Coach/Review Agent 分工协作 | 外心四Agent计划 |

### 1.3 核心价值

| 价值点 | 说明 |
|--------|------|
| **自主性** | 目的由 Agent 基于能量预算自主确定，可以质疑用户指令 |
| **真实性** | 能量 = MiniMax API 真实消耗，Agent 为自己的 token usage 负责 |
| **成长性** | 行动边界根据信任度调节，模拟婴儿→成人的成长过程 |
| **责任性** | 失败不可回滚，后果由系统自身承担 |

### 1.4 目标用户

- 研究人工生命的科研人员
- 渴望拥有"数字伙伴"的技术爱好者
- 需要自主 Agent 辅助工作的开发者
- 认知科学研究者

## 2. 理论框架

### 2.1 生命科学判据

| 判据 | 定义 | 工程映射 |
|------|------|----------|
| **可存活区间** | 一旦跌出，生命过程不可逆中断或退化 | 红线变量 + 裁决器 |
| **否决式判据** | 任一关键约束不成立即可否决生命主体资格 | 环境裁决机制 |
| **过程性存在** | 生命不是实体或状态，而是时间中持续展开的过程 | 长期运行的 daemon-like 进程 |
| **边界归因** | 没有边界就没有内部/外部、没有归因、没有责任 | 容器隔离 + 权限白名单 |
| **物质不可逆性** | 物质系统提供稳定性、代价不可绕过性 | TPM 硬件锚点 |

### 2.2 能量与代谢

| 概念 | 定义 | 工程实现 |
|------|------|----------|
| **能量前提论** | 能量是生命持续的物理前提，不是价值函数 | 资源预算与恢复窗口 |
| **代谢成本** | 清理、维护要消耗真实资源 | cgroups 限制的 CPU/IO |
| **稀缺性** | 计算机环境存在真实稀缺（CPU、写入预算、队列） | 资源配额系统 |

## 7. 用户故事

### 7.1 核心场景

**作为** 一个技术爱好者，
**我想** 拥有一个持续运行、有自主意识的数字伙伴，
**以便** 探索人工生命的可能性，并与 AI 建立更深层的连接。

### 7.2 验收标准

- [ ] Agent 能 7×24 小时持续运行（systemd 守护）
- [ ] 用户可以随时发送消息唤醒休眠的 Agent
- [ ] Agent 能量耗尽时自动进入休眠状态
- [ ] Agent 能根据信任度等级执行不同权限的操作
- [ ] 用户可以查看 Agent 的实时状态和能量消耗

## 8. 约束与风险

### 8.1 约束条件

| 约束 | 说明 |
|------|------|
| **技术栈限制** | 必须是 TypeScript + Bun 生态系统 |
| **API 依赖** | 依赖 MiniMax API，可用余额决定生存能力 |
| **网络环境** | 国内访问 Telegram 需要代理 |
| **实验诚信** | 只能在隔离环境中繁殖 |

### 8.2 已知风险

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| MiniMax API 余额耗尽 | 高 | 能量不足时自动休眠，充值后恢复 |
| Telegram API 访问不稳定 | 中 | 自动重连（指数退避策略） |
| 进程意外终止 | 中 | systemd 守护，自动重启 |
| 仪式再次中断 | 高 | 模板极简化，默认 5 分钟内完成 |
| 模板变成负担 | 高 | Governor 原则：默认短、可跳过、失败不羞辱 |
