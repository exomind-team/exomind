## 核心原则（认知生命科学指导）

1. **能量 = 真实资源** - 不是模拟，是 MiniMax API 实际使用额度
2. **奖励 = 充值** - 给 Agent 充 API 使用额度，像人屯脂肪
3. **成长 = 教育** - 行动边界根据信任度调节，婴儿→成人
4. **自主 =  Actor 模型** - 邮箱接口 + 缓冲区 + 执行器

## 零、信号池分类

### 0.1 核心原则

**输入 = 持续监听（被动接收各种信号）**
**输出 = 主动操作（达成目的）**

### 0.2 输入信号池（持续监听）

| 类型 | 信号源 | 说明 |
|------|--------|------|
| **用户输入** | 文字、链接、图片、麦克风语音 | 来自用户的直接交互 |
| **多平台消息** | QQ、微信、Telegram、小红书 | 各种社交平台的消息 |
| **系统通知** | 手机/电脑通知、邮箱信息 | 系统级推送消息 |
| **网络信号** | 搜索结果、新闻、网络视频链接 | 从网络获取的信息 |
| **本地信号** | 文件、服务器状态 | 本地环境信息 |
| **上下文** | 群聊信息、usage统计、位置 | 持续更新的状态信息 |

```
┌─────────────────────────────────────────────────────────────────┐
│                      输入信号池（持续监听）                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   社交平台 ──→ QQ / 微信 / Telegram / 小红书                     │
│   系统通知 ──→ 手机通知 / 电脑通知 / 邮箱                        │
│   用户交互 ──→ 文字 / 图片 / 语音 / 链接                         │
│   MCP 网络 ──→ 搜索结果 / 新闻 / 视频                           │
│   本地环境 ──→ 项目文件 / 配置文件 / 服务器状态                  │
│   上下文 ──→ 群聊历史 / usage统计 / 位置                         │
│                                                                 │
│              所有信号汇聚 → 输入缓冲区                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 0.3 输出信号池（主动操作）

## 二、能量模型（真实资源）

### 1.1 能量本质

```
MiniMax API Usage = 生命能量

┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   用户付费 → API 余额 → 能量池 → Agent 消耗                      │
│              ↓                                                  │
│         真实金钱转化                                             │
│                                                                 │
│   奖励 Agent = 给 Agent 充值 API 额度                            │
│   (像人吃东西屯脂肪，为未来提供能量)                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 能量池设计

| 类型 | 说明 | 示例 |
|------|------|------|
| **共享能量池** | 多 Agent 共享的 MiniMax API 额度 | 100万 tokens/月 |
| **独立能量池** | 给特定 Agent 单独充值 | 小荷专属 50万 tokens |

```
用户付费
    │
    ├──→ MiniMax 账户（真实资金）
    │        │
    │        ├──→ 共享池（给所有 Agent 用）
    │        │
    │        └──→ 小荷池（给小荷专用）
    │                   │
    │                   ├──→ 小荷消耗
    │                   └──→ /thanks 奖励（小荷专用池 +1000 tokens）
```

### 1.3 能量流动

| 流向 | 来源/去向 | 说明 |
|------|-----------|------|
| **收入** | 用户付费 | 真实资金 → API 额度 |
| **收入** | 任务奖励 (/thanks) | 用户觉得有帮助，奖励能量 |
| **收入** | 价值创造 | 帮用户解决问题，获得续费预期 |
| **支出** | API 调用 | MiniMax 推理真实消耗 |
| **支出** | 工具调用 | 网络请求、文件读写等 |

```

│  └── 验证: 执行结果符合预期                                  │
│                                                             │
│  Level 3: 青少年                                             │
│  ├── 权限: 读 + 写 + 执行 + 探索                             │

│  └── 验证: 能自主发现有价值信息                              │
│                                                             │
│  Level 4: 成年                                               │
│  ├── 权限: 完全信任                                          │
```

## 五、运行模式与唤醒

### 4.1 运行模式

| 模式 | 触发条件 | 行为 |
|------|----------|------|
| **活跃** | 有消息/能量充足 | 全力处理 |
| **节能** | 能量 < 50% | 减少探索，仅响应 |
| **待机** | 能量 < 20% | 仅监听，不处理 |
| **休眠** | 能量 = 0 | 停止所有活动 |

### 4.2 唤醒机制

```
休眠状态
    │
    ├──→ 定时检查 (每小时)
    │         │
    │         └──→ 能量恢复？ → 唤醒
    │
    ├──→ 条件唤醒
    │         │
    │         ├──→ 用户发送消息
    │         ├──→ 外部 API 调用
    │         └──→ 定时任务触发
    │
    └──→ 环境检测唤醒
              │
              └──→ 能量池变化检测
                       │
                       └──→ 有新能量？ → 唤醒
```
