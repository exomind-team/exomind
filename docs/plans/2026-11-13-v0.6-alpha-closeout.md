### 3.1 开发实例清理

- 清理候选只来自已验证根进程的后代；端口监听、相同构建目录、外部 app PID 提示不授予清理权。
- 创建时间与记录的可执行路径均存在时，两者必须匹配；子进程不得早于当前父进程。
- 自叶到根逐个复验，每个原生终止动作使用同一 Windows handle 校验身份并执行，不使用按 PID 的树终止。
- Android 开发实例同样采集并验证进程身份。身份变化、原生失败、孤立监听或快照后新子进程留下时，保留元数据并报告未确认停止。
- 启动器已退出时，RT/bridge 监听与可能的遗留子进程仍阻止同名复用、停止确认及 `prune` 删除元数据；这些提示不授予终止权。该反例经独立只读审阅提出，已复现并修复。
- Node 测试使用 Node 环境；共享测试初始化只在存在 DOM 时安装浏览器 shim。
- Android 安装回归从 `tauri.conf.json.identifier` 取得版本化包名；测试写入的假 APK 在结束时恢复或移除。

### 3.2 Android 本机记录与系统栏

旧 Alpha04 的真机诊断已取得以下证据：

- 启动日志显示“无法获取当前档案”，界面显示“未打开档案”；此时仍能进入发送/计时界面，失败 toast 一律提示“检查网络”。
- 创建并打开合成档案后，保持同一 VPN 开启状态，既有 WebView HTTP 通道成功保存合成 marker；停止并重启 0.6 包后，档案及该 marker 仍可回读。
- 因此本轮修复档案入口、提交资格和错误归因；试验性原生 EventLog 网络桥已全部撤回。没有证据把故障归因于 VPN/TUN。
- Android Activity 无条件启用 edge-to-edge、仅依赖 WebView CSS safe area，且没有用户要求的全屏设置，是独立的系统栏缺口。

本轮新候选单独编号为 `0.6.0-alpha05`，不覆盖 Alpha04 旧产物。拟验证：默认由 Activity 应用系统栏/缺口 insets，开启全屏时隐藏系统栏，旋转和返回前台后重应用；设置持久化且串行提交，失败不保存假偏好。原草稿仅本地暂存并完整恢复，不发送其正文。修复候选的构建及真机结果尚待回填。

源码闭合情况：

- 当下入口复用 `SwitchAccountSheet` 创建/打开本地档案，未打开时不挂载记录与计时；提交时再次校验档案资格。
- 保存失败不再统一归因为网络；保留草稿并提示对应处理入口。
- 草稿在 debounce 前卸载时立即保存；待回执提交不把暂空输入当成删除；旧成功回执只能清自己的快照，不能清后来输入（包括已持久化的新稿）。
- 全屏启动应用与设置变更共用串行原生队列；JNI 失败先清 Java 异常再返回错误，避免污染共享主线程。
- Android 文件补丁在写入前校验组播、全屏方法及安装调用，CLI/CI 不接受部分补丁；独立审阅提出的两个 P2 均已修正。
