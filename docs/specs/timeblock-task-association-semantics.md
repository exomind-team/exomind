# 时间块 × 任务关联语义

## 定义

时间块的“关联任务”指：

> 从时间块创建开始，到时间块结束为止，只要某个任务在任意一段时间内处于已关联状态，这个任务就属于该时间块的关联任务集合。

这意味着：

- 不要求任务从时间块开始到结束全程伴随
- 中途追加后又移除的任务，仍然属于这个时间块的关联任务
- 时间块与任务的关系一旦成立，就是双向成立

## 两层语义

### 1. 当前 / 结束时仍关联的任务快照

来源：

- `taskIds`

用途：

- 活跃时间块当前状态
- 运行中增删关联
- 结束时任务状态回写

说明：

- 它是“当前仍关联”或“结束时仍关联”的快照
- 它不等于“这个时间块历史上关联过哪些任务”

### 2. 时间块历史关联任务全集

来源：

- `taskAssociationLog` 中所有 `associated` 事件的任务 ID 去重并集

用途：

- 时间块详情页的“关联任务”
- 历史回顾与统计
- 任务 ↔ 时间块双向关联关系建立

说明：

- 即使任务后来被 `disassociated`，它仍属于该时间块的历史关联任务

## 任务侧语义

任务的 `timeBlockIds` 表示：

> 该任务历史上曾与哪些时间块建立过关联关系。

因此：

- 不要求该任务在整个时间块期间都持续关联
- 只要曾在该时间块的任意一段时间被关联过，这个时间块就应进入任务的 `timeBlockIds`

## 为“出现程度”保留的数据基础

在新语义下，可以进一步定义任务在时间块中的“出现程度”：

```text
出现程度 = 任务在该时间块中处于关联状态的总时长 / 时间块总实际执行时长
```

这依赖 `taskAssociationLog` 的时间戳回放，因此：

- `taskIds` 不足以计算出现程度
- `taskAssociationLog` 是后续计算“出现程度”的事实基础

## 示例

给定一个时间块：

- `09:00` 关联 A
- `09:10` 关联 B
- `09:20` 移除 B
- `09:30` 结束，`taskIds = [A]`

则：

- 当前 / 结束时仍关联任务：`[A]`
- 时间块历史关联任务全集：`[A, B]`
- 任务 A 与任务 B 都应把这个时间块记入自己的 `timeBlockIds`
- 若后续计算出现程度：
  - A 的出现程度 = `30 / 30 = 100%`
  - B 的出现程度 = `10 / 30 = 33.3%`
