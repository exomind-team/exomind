## Beta12 优先修的两个场景

### P1 · 回读刚写的内容，确认能否关窗

记录气泡的正文与输入框下面的保存状态都偏淡。前者要连续读，后者决定用户是否敢关窗。深色模式改善了部分状态字，对正文没有改善。建议分别调整气泡底色和保存状态字色，保留暖石底和陶橙强调。

| 桌面原图上的文字 | 字号 | 前景 / 背景 | 对比度 |
|---|---:|---|---:|
| 浅色「记录草稿已暂存 · 尚未提交」 | 11 CSS px | #7F8EA3 / #FAF7F5 | 3.12∶1 |
| 深色同一行 | 11 CSS px | #78726D / #0C0A09 | 4.16∶1 |
| 两种主题的个人记录正文 | 13 CSS px | #FAFAF9 / #C75B3A | 4.03∶1 |

**验收**　在两种主题各输入一条合成记录，分别查看暂存提示、提交后的本机确认和记录正文。以浏览器计算样式和实际底色复算，小字均至少达到 4.5∶1，再看错误态能否凭文字识别。单把正文改成纯白，在当前橙底也只有 4.21∶1。[WCAG 2.2 普通文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

**取证方法**　取两张桌面初始 PNG 的原始像素，左上为原点。状态取 x=272–409、y=875–895，正文取 x=1040–1205、y=507–554。用区域内出现最多的背景色及实心字色，按 sRGB 相对亮度计算，排除抗锯齿边缘。字号和配色入口见 [ChatMessageRowView](../../src/ui/app/components/ChatMessageRowView.tsx)、[BetaApp](../../src/beta/BetaApp.tsx) 的 afterControls、[输入框底色](../../src/ui/app/components/NowInputRowView.tsx) 和[主题变量](../../src/index.css)。

### P1 · 第一次开启时间块，判断计时从哪一步开始

最醒目的按钮写着「点击开启时间块」，小字才说明还要配置。实际第一步打开配置。它的可访问名称却是「展开专注配置（Expand focus configuration）」，没有包含屏幕上的主标签。这给鼠标用户留下开始时刻的疑问，也让依照屏幕文字发语音指令的人失去可靠的目标。建议把可见主标签改成「配置时间块」，用同一文字生成可访问名称，在表单确认处用「开始计时」。[入口视图](../../src/ui/app/components/FocusTimerView.tsx) · [Beta 点击处理](../../src/beta/BetaFocusTimer.tsx) · [WCAG 2.2 可见标签与可访问名称](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html)

**验收**　在空闲态用新可见名称查询按钮，恰好命中一个。分别用点击、轻触和键盘打开配置，取消后开始命令为零。再完成确认，开始命令恰好一次，卡片显示刚填的名称和时间。测试应按名称定位，现有短屏场景按 test ID 能成功点击，无法捕捉文字分歧。语音控制识别留给目标设备实测。

## 值得保留的优点

- **当下有共同的工作位置。** 开时间块、边做边记和翻看刚才的文字共用一页。在开始后的四张短屏图里，输入框和计时控件同时可见。用户无需为了写一句话主动退出计时。
- **草稿有自己的身份。** 「记录草稿已暂存 · 尚未提交」紧贴输入框，能回答“我写的半句话是否已经进入时间线”。图片旁的预览、文件名和大小也让用户能先辨认内容再操作。这两处比给整个工作区加一个笼统的成功标记更贴近任务。
- **Alpha 的视觉记忆有具体落点。** 奶白／深棕底、靶心、圆角暖橙卡和左右分置的计时控制构成稳定的识别物。封存后对照 Alpha05 的 `99b6b648`，旧 FocusTimerWidget 的空闲区已有同样的渐变、68px 卡高、靶心与展开动作；Beta 的 FocusTimerView 保留了这组结构。可确认这个局部的延续。整套界面是否仍有 Alpha 的亲切感，特别是长时间阅读橙底气泡的感受，仍由使用者裁决。

## 三个场景的官方参照

- **计时中翻历史。** Toggl Track 的 Android 文档把运行中条目放在列表底部附近，允许点入调整；专注时可另进全屏。可借到 ExoMind 的是“看历史时仍可接触到当前计时”，特别适合拿来比较短屏的往返次数。[Toggl Track Timer for Android](https://support.toggl.com/en-us/article/toggl-track-timer-for-android-1v3i5g8/)
- **隔天找回一段想法。** Obsidian Daily notes 用日期决定打开哪篇笔记，日期属性也可通向相应日记。对 ExoMind 的启发是先给回顾一个用户认得的日期或时间块，再让其查到具体来源。是否需要单独的日历页，现有材料无法决定。[Obsidian Daily notes](https://obsidian.md/help/plugins/daily-notes)
- **知道文件到了哪一步。** Syncthing 说明接收方会核验内容块，匹配后写入临时副本。这为跨端验收提供一个尺度：分别观察记录元数据出现、内容到达、完整文件可用。此处参照的是确认粒度，协议实现各自独立。[Syncthing Understanding Synchronization](https://docs.syncthing.net/users/syncing.html)
