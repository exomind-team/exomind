# Agent Hub 可选模型对话框修正计划

日期：`2026-04-11`

## 背景

当前 Agent Hub 的 PTY 创建/恢复对话框里，“模型（model）”在实现上已经是可选的：

- 创建 Claude 时，只有在模型输入非空时才附加 `--model`
- 创建 Codex 时，只有在模型输入非空时才附加 `-m`
- runtime 的 `spawn/resume` 侧也没有在前端留空时擅自补默认模型

因此这轮问题不在“后端偷偷选了默认模型”，而在前端 UX：

1. 对话框关闭后会清空模型输入，用户再次打开需要重填
2. 占位符直接写成具体模型名，容易误导成“默认会用这个模型”
3. 恢复已有终端仍暴露模型/推理强度覆盖入口，和“沿用历史会话自身配置”相冲突

## 目标

1. 明确把“模型”收敛为创建模式下的可选项。
2. 模型输入在对话框关闭后保留最近一次草稿，并按 Claude / Codex 分开记忆。
3. 恢复已有终端时不再要求、展示或发送模型覆盖。
4. 模型占位符从“默认值暗示”改成“格式示例提示”。
5. `额外参数` 占位符同样使用“示例格式”，避免被误读为默认会附带的参数。
6. 完成后通过 `tsc`、`vitest` 和真实 Tauri 窗口复核。

## 不改的内容

- 不修改 runtime 默认模型选择策略
- 不新增后端字段
- 不改变 Claude / Codex 创建时“空模型不传参”的既有语义
- 不扩大为完整表单记忆系统；本轮只处理模型输入的用户草稿

## 设计决策

### 1. 创建与恢复分离

创建模式：

- Claude / Codex 继续显示模型输入
- 模型保持可选，留空时不传模型参数

恢复模式：

- 不再显示模型输入
- 不再显示 Codex 的推理强度选择
- 恢复请求只发送：
  - `agent_type`
  - `session_id`
  - 可选 `name`
  - 可选 `extra_args`

### 2. 草稿记忆策略

- 为 `claude` 与 `codex` 分别保存最近一次输入的模型草稿
- 切换 agent type 时切换到对应草稿
- 关闭对话框时保留模型草稿
- 其他字段维持当前“关闭即重置”的行为

### 3. 文案策略

占位符改为“例如”语义，而不是裸模型名：

- Claude：`例如：claude-sonnet-4-5`
- Codex：`例如：gpt-5.4`
- 额外参数：`例如：--search --full-auto`

恢复模式继续通过说明文案强调：

- 路径沿用历史会话
- 模型/推理配置也沿用历史会话，不在这里覆盖

## 实现步骤

1. 调整 `PtySpawnDialog`
   - 引入按 agent type 记忆的模型草稿 state
   - 对话框关闭时不再清空模型草稿
   - 恢复模式隐藏模型与推理强度控件
   - `handleResume()` 不再发送 `model` / `reasoning_effort`
   - 调整模型占位符文案
2. 更新 `pty-spawn-dialog` 单测
   - 创建 Codex 时仍可显式传模型与推理强度
   - 创建时模型留空不传 `-m`
   - 关闭再打开后，Claude / Codex 各自保留最近一次模型草稿
   - 恢复模式不再渲染模型/推理强度控件
   - 恢复请求不再发送 `model` / `reasoning_effort`
   - 占位符文案使用“例如：...”
3. 运行验证
   - `bunx tsc --noEmit`
   - `npx vitest run tests/unit/ui/agent-hub/pty-spawn-dialog.test.tsx`
4. 用真实 Tauri 桌面窗口复核
   - 创建 Claude：模型可留空
   - 创建 Codex：模型可留空，显式填写时仍可提交
   - 关闭再打开：模型草稿仍在
   - 恢复已有终端：不出现模型输入，不发送模型覆盖

## 验收点

1. 创建 Claude / Codex 时，留空模型不会在请求体里生成模型参数。
2. Claude 与 Codex 模型输入互不串值，分别记忆各自最近草稿。
3. 恢复已有终端时，对话框不再出现模型和推理强度控件。
4. `/pty/resume` 请求体不再带 `model`、`reasoning_effort`。
5. 占位符表达为格式示例，不暗示默认模型。
