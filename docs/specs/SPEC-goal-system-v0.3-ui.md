## 0. UI 设计原则

### 0.1 取消 ≈ 删除

用户感知层面「取消」等同于「删除」：已取消的目标默认从视图中隐藏，如同被删除。但逻辑层保留完整记录。传达理念：目标要认真对待。

### 0.2 空槽位 = 提醒

空槽位边（taskNodeRef 为空）在视觉上以「待定义」样式提醒用户：要达成目标需要具体的行动计划。

### 0.3 状态只读

目标的展示状态完全由逻辑层实时派生。优先级：cancelled > completed > in_progress > suspended > pending（仅适用于目标，边的状态由关联任务决定）。`cancelled` 是唯一的存储态标记，通过 `cancelGoal` 设置。`completed` 不存储——当完成规则满足时自动显示为已完成，规则不满足时自动回退。任务边的状态派生自关联任务，UI 层不直接修改边状态。

### 0.4 AND/OR 是简化入口

UI 层提供 AND/OR 切换作为 completionRule 的简化操作入口。P0 仅支持全局 AND 或全局 OR 切换，不支持 DNF 混合编辑。

### 0.5 开发者模式（原型阶段）

原型阶段在**边详情面板底部**提供「⚙ 开发者」折叠区（警告色标题，默认折叠），用于在任务系统事件集成就绪前手动模拟状态变更。**正式版通过 feature flag 隐藏。**

**实现机制**：逻辑层提供 `setEdgeStatusOverride` / `clearEdgeStatusOverride` 原型 API（详见逻辑文档 §8.1）。override **不受入边冻结约束**——即使 target 派生为 completed 仍可设置，便于调试。

**边详情面板折叠区**：
- 边状态下拉框（pending / in_progress / suspended / completed / cancelled）→ 调用 `setEdgeStatusOverride`
- 「清除覆盖」按钮 → 调用 `clearEdgeStatusOverride`，边状态恢复正常派生
- `clearAllEdgeStatusOverrides` 无 UI 入口，仅供代码调用（刷新页面自动清除所有 override）

**操作反馈**：所有开发者操作的 toast 带「[开发者]」前缀（如「[开发者] 边'xxx'状态已设为 completed」）。

> **注意**：设置边状态 override 后，关联目标的派生状态会实时变化。例如将所有入边设为 completed 可使目标派生为已完成。清除 override 后目标自动回退。

### 0.6 触屏兼容

所有右键交互均有触屏等效方案（长按替代右键）。详情面板采用响应式布局（桌面=侧栏，移动=底部抽屉）。详见 §11。

## 1. 视图架构

### 1.1 主视图：目标网络（力导向图）

画布式力导向图，是目标系统的主交互界面：

- **节点**：Me（固定中心）+ 目标节点（外围）
- **边**：任务边（有向，箭头指向 target）
- **布局**：d3-force 物理模拟

### 1.2 辅助面板：详情面板

点击节点或边后弹出详情面板，展示和编辑属性。

**响应式布局**（参考 TaskDagDetailPanel）：
- **桌面端**：右侧栏，固定宽度 w-[340px]，absolute 定位
- **移动端**：底部抽屉，max-h-[72vh]，全宽，rounded-t-[28px]

### 1.3 已取消内容的隐藏与恢复

**已取消的目标节点**：
- 默认从视图中隐藏（含其所有关联边）
- 从 cancelled 目标出发的僵尸边（空槽位永远 pending）也一并隐藏

**「显示已取消」开关**：
- 位置：画布右上角工具栏
- 默认：关闭
- 持久化：localStorage
- 打开后：已取消目标以半透明样式显示，僵尸边以特殊样式标识（可右键删除）

**cancelled 边的区分处理**：

| 场景 | 来源 | 视觉处理 |
|------|------|---------|
| (A) 目标被取消 | 目标 cancelled=true | 边随目标隐藏，受「显示已取消」开关控制 |
| (B) 目标活跃但关联任务被取消 | 边的 taskNodeRef 指向的任务被取消 | 边以**半透明+划线**样式保留在图上，不随开关隐藏 |

> 场景 B 的边保留在图上是为了提示用户「这条路径已失效，可能需要新手段」。用户可点击查看详情或右键删除。

### 1.4 未来视图：星图视图

概念视图，本版本不实现，仅保留设计意向。

### 1.5 空状态引导

初次打开目标系统（只有 Me 节点）时，Me 节点旁显示引导气泡：

```
💡 右键添加你的第一个目标
```

文案根据设备类型动态显示：桌面端「右键添加你的第一个目标」，触屏设备「长按添加你的第一个目标」。

用户添加第一个目标后气泡自动消失。气泡关闭状态持久化到 localStorage，不会重复出现。

### 1.6 completionRule 空集警告

当目标的 completionRule 为空集 `{}`（永远无法自动完成）时：

- **画布上**：目标节点显示警告图标（⚠ 感叹号角标）
- **详情面板**：completionRule 区域显示「无完成条件，请添加任务边」提示文案
- **触发场景**：删除边导致规则清空、所有入边引用被移除

### 1.7 浏览模式与编辑模式

画布左上角模式切换器（参考现有 `GoalModeSelector` 实现）：

| 模式 | 节点拖拽行为 | 从节点拖拽行为 | 默认 |
|------|------------|-------------|------|
| **浏览** | 移动节点位置（松手后继续力模拟） | 移动节点位置 | ✅ |
| **编辑** | 单击=选中/打开详情面板，拖拽=创建连线 | 创建连线（§3.2） | |

模式状态持久化到 localStorage（key: `exomind:goals-mode`）。

> 编辑模式下：单击节点打开详情面板（同浏览模式），从节点拖拽则开始连线。节点位置不可手动移动。
>
> 连线模式（§3.3 右键「连接到...」）在两种模式下均可用，不依赖编辑模式。

## 2. 力导向布局

### 2.1 物理模拟参数

| 力 | 作用 | 说明 |
|----|------|------|
| 排斥力 | 目标节点间相互排斥 | 防止重叠 |
| 链接约束 | 任务边约束两端距离 | 连接的节点不会飞太远 |
| 中心力 | Me 固定在画布中心 | Me 坐标 (0, 0)，不参与物理模拟 |

具体参数值详见 `goal-force-layout.ts`，原型阶段通过实验迭代调优（跟踪 issue：力导向参数调优）。

### 2.2 距离语义（视觉呈现）

逻辑层提供 `getHopDistance(goalId)` → UI 层用此值：

- 渲染距离标尺（同心圆或径向刻度）（P1）
- 近（1跳）= 近期目标，远（多跳）= 长期目标
- 标尺方向：Me 向外，越远越长期
- 注：路径计算排除 cancelled 边

### 2.3 节点视觉

| 节点类型 | 外观 | 状态映射 | 可操作性 |
|----------|------|---------|---------|
| Me | 特殊样式（大圆、渐变高亮），沿用现有 orange→rose 渐变 | 始终显示 | 右键菜单 |
| 目标-pending | 默认样式，沿用现有 sky→indigo 渐变 | 可交互 | 完整右键菜单 |
| 目标-in_progress | 默认样式 + 进行中指示器（琥珀色边框/脉冲） | **派生**：有入边在 in_progress | 完整右键菜单 |
| 目标-suspended | 默认样式 + 挂起指示器（灰色边框） | **派生**：无 in_progress 入边，但有 suspended 入边或所有入边已终结但规则未满足 | 完整右键菜单 |
| 目标-completed | 完成样式（绿色/打勾），P0 opacity 0.5-0.7 | 派生态（completionRule 满足时） | 右键可添加下游目标、连接到... |
| 目标-cancelled | 默认隐藏 | 终态（唯一存储态终态） | 「显示已取消」开关打开时半透明展示，不出现右键菜单 |
| 目标-空规则警告 | 任何活跃状态 + ⚠ 角标 | completionRule = {} | 提示需要添加任务边 |

**派生状态优先级**：`in_progress > suspended > pending`。即同时存在 in_progress 和 suspended 入边时，展示状态为 in_progress。

> suspended 有两种子情况：(a) 有任务被暂停；(b) 所有手段用尽等待新手段。UI 可通过 tooltip 区分。

> completed 目标虽为派生态，仍有入边冻结（逻辑文档 §2.2）和字段冻结（派生冻结），防止意外反完成。

### 2.4 边视觉

| 边状态 | 外观 | 说明 |
|--------|------|------|
| pending（空槽位） | 细虚线 + 「待定义」标签 | 提醒用户绑定任务 |
| pending（有任务） | 虚线 | 任务尚未开始 |
| in_progress | 实线 + 琥珀高亮色 | 正在进行 |
| suspended | 虚线 + 灰色 | 已挂起 |
| completed | 实线 + 绿色 | 已完成 |
| cancelled（目标取消） | 随目标隐藏 | 受「显示已取消」开关控制（§1.3 场景 A） |
| cancelled（任务取消） | 半透明 + 划线 | 保留在图上，提示路径失效（§1.3 场景 B） |
| C5 自动补充 | 空槽位样式 + 高亮闪烁 ~1s | 自动补充时的出场动画（§5.4） |

### 2.5 平行边视觉

逻辑文档允许两节点间有多条任务边（§2.2）。现有代码已实现平行边偏移（`GoalsPage.tsx` 的 `parallelIndex` / `parallelTotal`）：

- **单条边**：直线连接
- **多条平行边**：以二次贝塞尔��线偏移显示，垂直于连线方向等距分布（间距 ~20px）
- **标签**：沿各自曲线中点显示，自然错位避免重叠
- **右键/点击**：命中区域沿曲线扩展，用户可精准选择单条边

## 3. 用户操作 → 逻辑 API 映射

### 3.1 添加目标（基于节点派生）

| 交互 | 逻辑调用 | 后续 |
|------|---------|------|
| 右键目标节点 → 添加下游目标 | `createGoal({ fromNode: goalId, direction: 'downstream' })` | 自动选中新目标，打开详情面板编辑 |
| 右键目标节点 → 添加上游目标 | `createGoal({ fromNode: goalId, direction: 'upstream', rulePosition: { clauseIndex: 0 } })` | 自动选中新目标，打开详情面板编辑 |
| 右键 Me → 添加目标 | `createGoal({ fromNode: meId, direction: 'downstream' })` | 自动选中新目标，打开详情面板编辑 |

**创建后行为**：直接创建空名称目标（显示「待命名」），自动选中并打开详情面板让用户命名。无弹窗输入框。

> 目标不能凭空创建（C5），必须基于已有节点派生。Me 上只能 downstream（Me 不能作为 target）。
>
> **upstream 创建的新目标**无入边，completionRule 初始化为 `{}`（空集），会显示 §1.6 空集警告角标——这是预期行为，引导用户为其添加入边。

### 3.2 添加任务边（拖拽连线）

| 交互 | 逻辑调用 |
|------|---------|
| 编辑模式下从节点 A 拖拽到节点 B | `createEdge({ source: A.id, target: B.id, rulePosition: { clauseIndex: 0 } })` |

**创建后行为**：新边自动选中并打开详情面板（方便立即命名和绑定任务）。

**rulePosition 的 UI 决策**：默认 AND 模式（clauseIndex: 0，加入第一个子集）。

**拖拽过程的视觉反馈**：
- 起点：从节点边缘开始拖拽
- 过程：虚线跟随鼠标，可连节点边框高亮
- 目标：hover 在有效目标节点时吸附效果
- 松手在空白处：取消操作

**失败处理**：
- DAG 检测失败 → toast「不能形成环」
- 自环 → toast「不能连到自己」
- target 派生为 completed → toast「已完成的目标不能添加新任务」
- source 为 cancelled → toast「已取消的目标不能发起新任务」

### 3.3 连线模式（右键触发）

从右键菜单「连接到...」进入连线模式，适用于任何模式（浏览/编辑）：

**交互流程**：
1. **进入**：右键节点 → 点击「连接到...」
2. **视觉状态**：光标变十字 + 从发起节点出发的虚线跟随鼠标 + 可连节点边框高亮
3. **确认**：点击目标节点 → 调用 `createEdge({ source: 发起方.id, target: 点击方.id, rulePosition: { clauseIndex: 0 } })`
4. **取消**：ESC / 点击画布空白

**方向规则**：发起方 = source，点击方 = target。

**失败处理**：同 §3.2。

### 3.4 编辑属性

| 交互 | 逻辑调用 | 冻结规则 |
|------|---------|---------|
| 详情面板修改目标标题 | `updateGoal({ goalId, title })` | cancelled 不可编辑；派生为 completed 不可编辑 |
| 详情面板修改目标描述 | `updateGoal({ goalId, description })` | cancelled 不可编辑；派生为 completed 不可编辑 |
| 详情面板切换 AND/OR | 见 §3.9 | cancelled 不可编辑；派生为 completed 不可编辑 |
| 详情面板修改边标题 | `updateEdge({ edgeId, title })` | target 派生为 completed 时冻结 |
| 详情面板修改边描述 | `updateEdge({ edgeId, description })` | target 派生为 completed 时冻结 |
| 详情面板绑定/解绑任务 | `updateEdge({ edgeId, taskNodeRef })` | target 派生为 completed 时冻结 |

**冻结规则**：
- `cancelled` 目标：不可编辑（存储态终态）
- 派生为 `completed` 的目标：不可编辑（派生冻结——防止意外反完成）
- 冻结基于实时派生状态，冻结字段显示为灰色禁用状态（disabled），不可点击编辑。

### 3.5 取消目标

| 交互 | 逻辑调用 |
|------|---------|
| 右键菜单 → 取消目标 | 弹窗确认 → `cancelGoal({ goalId, cascadeInTasks: false, cascadeOutTasks: false })` |

**前置条件**：目标未 cancelled 且派生状态非 completed。

**P0 弹窗**（简化版）：
```
确认取消目标「xxx」？

取消后目标将被隐藏，此操作不可撤销。

        [返回]  [确认取消]
```

> 按钮文案避免「取消」歧义（弹窗取消 vs 取消目标）：左按钮用「返回」，右按钮用「确认取消」。

cascade 参数默认为 false。入边关联的任务继续运行。

**P1 弹窗**（完整版）：增加两个勾选框：
```
☐ 同时取消入边关联的任务（达成手段）
☐ 同时取消出边关联的任务（后续路径）
```

取消后目标从视图中隐藏（§1.3）。

### 3.6 删除任务边

| 交互 | 逻辑调用 |
|------|---------|
| 右键边 → 删除 | `deleteEdge({ edgeId })` |

**无确认弹窗**，直接执行。

**失败处理**：
- target 派生为 completed → toast「已完成目标的入边不可删除」

**副作用反馈**：
- 若删除导致 completionRule 子集被移除或缩减 → toast「完成条件已自动调整」
- 若删除导致 completionRule 变为空集 → 目标节点出现 ⚠ 警告角标（§1.6）
- 若触发 C5 自动补充（target 无入边，自动添加 Me→target 空槽位边）→ 新边高亮闪烁 ~1s + toast「已自动添加连接以保持目标可达」（§5.4）

### 3.7 拆解边（P1）

| 交互 | 逻辑调用 |
|------|---------|
| 右键边 → 拆解 | 弹窗 → `splitEdge({ edgeId, ... })` |

**拆解弹窗**：
1. 选择中间节点：「新建目标」（输入名称）或「选择已有目标」（下拉列表，范围：未 cancelled 且派生非 completed 的目标，可搜索过滤）
2. 原边分配：「原边作为前半段」或「原边作为后半段」
3. rulePosition：默认 clauseIndex=0
4. 确认 → 调用 splitEdge

失败时（如 DAG 检测）整体回滚，toast 提示原因。

### 3.8 修改边的端点（reconnect）（P1）

| 交互 | 逻辑调用 |
|------|---------|
| 拖拽边的端点到新节点 | `reconnectEdge({ edgeId, newSource/newTarget, rulePosition: { clauseIndex: 0 } })` |

rulePosition 默认 clauseIndex=0（AND 合并）。

**失败处理**：
- 同 §3.2 的 4 种 toast（DAG/自环/target completed/source cancelled）
- 旧 target 已完成且要修改 target → toast「已完成目标的入边指向不可修改」

**副作用反馈**：
- 若旧 target 因此无入边 → 触发 C5 自动补充（§3.6 副作用反馈同理）

### 3.9 AND/OR 切换（completionRule 简化入口）

| 交互 | 逻辑调用 |
|------|---------|
| 详情面板切换为 AND | `updateGoal({ goalId, completionRule: [[所有入边ID]] })` |
| 详情面板切换为 OR | `updateGoal({ goalId, completionRule: 入边ID.map(id => [id]) })` |

AND → 逻辑层设为 `{ {所有入边} }`（一个子集含全部入边）
OR → 逻辑层设为 `{ {E1}, {E2}, ... }`（每条入边一个独立子集）

**展示**：根据当前 completionRule 结构反推显示 AND / OR / 自定义。

**切换反馈**：toast 通知「完成条件已更新为 AND/OR」。开发者控制台输出规则变化前后对比（`console.log`）。

### 3.10 画布操作

| 交互 | 说明 |
|------|------|
| 拖拽节点 | 改变物理模拟位置，松手后继续模拟（浏览模式） |
| 缩放 | 鼠标滚轮 / 双指缩放 |
| 平移 | 拖拽画布空白 |

## 4. 详情面板

**编辑保存策略**：
- 文本字段（title / description）：blur 时调用 API 保存
- AND/OR 切换：即时保存
- 面板切换（点击其他节点/边）：自动触发当前字段 blur → 保存 → 切换内容
- 无「未保存」状态，不需要保存按钮

## 5. 视觉特效

### 5.1 吸纳动画（P1）

当目标派生状态变为 completed 时，触发「吸收」动画——目标被 Me 吸纳：

1. **聚拢**：目标节点脱离力导向布局，沿直线向 Me 中心移动（~500ms，ease-out）
2. **缩小**：移动过程中节点逐渐缩小至 Me 圆的边缘（scale 1.0 → 0.2）
3. **融合**：节点到达 Me 边缘时淡出消失（opacity 1.0 → 0）
4. **Me 脉冲**：Me 圆短暂扩大+发光脉冲（~300ms），表示「吸收完成」
5. **归位**：动画结束后，目标节点切换为 completed 样式，重新参与力导向布局，由物理模拟决定最终位置

**关联边的动画**：
- 目标的入边在聚拢阶段跟随缩短，融合时淡出
- 动画结束后入边恢复显示（completed 样式：实线绿）

**语义**：完成目标 = 目标归于自身 = 被 Me 吸收。这不是「消失」而是「成为我的一部分」。

**P0 替代**：无吸纳动画。目标派生为 completed 时直接切换为绿色/打勾样式（实时反映派生状态变化）。

### 5.2 级联传播高亮（P1）

派生状态沿 DAG 传播时，沿传播路径的边短暂高亮闪烁（~300ms），帮助用户理解「为什么这个目标突然完成了」。

### 5.3 待命名/待定义提示

- 目标 title 为空 → 显示半透明「待命名」，点击打开详情面板编辑
- 空槽位边 → 显示半透明「待定义」，点击打开详情面板引导绑定任务

### 5.4 C5 自动补充动画

当删除边或 reconnect 触发 C5（target 无入边，自动补充 Me→target 空槽位边）时：

1. **出场**：新边以高亮闪烁样式出现（~1s）
2. **toast**：「已自动添加连接以保持目标可达」
3. **稳态**：闪烁结束后切换为正常空槽位边样式（细虚线 + 「待定义」）

## 6. 右键菜单

> 触屏设备上，长按（~500ms）触发与右键相同的上下文菜单。详见 §11。

### 6.1 目标节点右键

**活跃目标**（未 cancelled 且派生状态非 completed，含展示态 pending / in_progress / suspended）：

| 菜单项 | 动作 |
|--------|------|
| 详情 | 打开详情面板（可编辑） |
| 添加下游目标 | createGoal downstream → 自动选中新目标 |
| 添加上游目标 | createGoal upstream → 自动选中新目标 |
| 连接到... | 进入连线模式（§3.3） |
| 取消目标 | 弹窗确认 → cancelGoal（§3.5） |

> Me 节点不显示「添加上游目标」和「取消目标」。

**completed 目标**：

| 菜单项 | 动作 |
|--------|------|
| 详情 | 打开详情面板（**只读**） |
| 添加下游目标 | createGoal downstream（已完成的目标可成为新目标的基石） |
| 连接到... | 进入连线模式（§3.3）。completed 目标允许新增出边 |

> 注：completed 目标**不显示**「添加上游目标」（入边冻结）和「取消目标」（已完成不可取消）。
>
> completed 状态基于实时派生，如果边状态变化导致目标不再 completed（如通过开发者 override），菜单自动恢复为活跃目标菜单。

**cancelled 目标**：默认隐藏，不出现右键菜单。

### 6.2 任务边右键

| 菜单项 | 可用条件 | 动作 |
|--------|---------|------|
| 详情 | 总是 | 打开详情面板（活跃目标可编辑，cancelled/派生 completed 只读） |
| 拆解 | target 非 completed（P1） | 弹窗 → splitEdge |
| 删除 | target 非 completed | deleteEdge（无确认弹窗） |

> 边的状态由关联任务决定（§0.3），不提供状态操作菜单项。

### 6.3 Me 节点右键

| 菜单项 | 动作 |
|--------|------|
| 详情 | 打开 Me 详情面板 |
| 添加目标 | createGoal({ fromNode: meId, direction: 'downstream' }) |

### 6.4 画布空白区域

右键/长按画布空白区域：禁用浏览器默认菜单，不显示自定义菜单。

## 10. 原型阶段放宽在 UI 层的体现

逐条对应逻辑文档 §8：

| 约束 | 逻辑层状态 | UI 层处理 |
|------|-----------|----------|
| **C2** 已取消不可逆 | cancelled 保持不可逆 | 无需放宽，cancelled 是唯一存储态终态 |
| **C5** 自动空槽位边 | 可选实现 | 若不实现：不触发自动补充边和对应动画/toast。空规则警告（§1.6）独立于 C5，作为 P0 始终展示。建议实现 |
| **C6** DAG 检测 | 可选实现 | 建议实现（现有代码已有 `wouldCreateCycle`）。不实现则去掉 DAG 失败 toast |
| **C8** 完成纯推导 | completed 为纯派生，无需放宽（本身就是实时计算） | UI 通过开发者模式（§0.5）改边状态 override 间接影响目标派生结果 |
| **C9** 空槽位限制 | 不限制 | UI 仍按严格模式展示空槽位为 pending |
| **completionRule** | UI 用 AND/OR 简化 | 仅全局 AND/OR 切换（§3.9），不支持 DNF 混合编辑 |
| **级联传播** | 无深度限制，同步执行 | 无特殊处理 |

## 11. 触屏/响应式适配

### 11.1 交互映射

| 桌面交互 | 触屏等效 | 说明 |
|----------|---------|------|
| 右键 | 长按（≥500ms 不移动） | 触发同一上下文菜单 |
| hover tooltip | 点击节点/边 | 打开详情面板替代 tooltip |
| 滚轮缩放 | 双指缩放 | ReactFlow 原生支持 |
| 拖拽节点 | 触屏拖拽（短按即移动） | 浏览模式 |
| 拖拽连线 | 触屏拖拽（短按即移动） | 编辑模式 |

**手势冲突解决**：长按与拖拽都从触摸节点开始。规则：
- 触摸后 **未移动且 ≥500ms** → 触发右键菜单（长按）
- 触摸后 **移动超过 10px**（无论是否达到 500ms）→ 取消长按计时器，开始拖拽
- 即：快速触摸+移动 = 拖拽，静止长按 = 菜单

**编辑模式触屏连线**：从节点短按拖出 = 开始连线（虚线跟随手指）→ 拖到目标节点松手 = 确认连线 → 拖到空白处松手 = 取消。与桌面端编辑模式行为一致。

### 11.2 详情面板响应式

参考 `TaskDagDetailPanel` 的响应式模式：

| 条件 | 面板形态 |
|------|---------|
| 桌面端（宽度 > 768px） | 右侧栏，w-[340px]，absolute right-4 top-4 |
| 移动端（宽度 ≤ 768px） | 底部抽屉，inset-x-0 bottom-0，max-h-[72vh]，rounded-t-[28px] |

关闭方式：点击面板 × 按钮 / 点击画布空白区域。
