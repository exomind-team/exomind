## 1. 目标与已确认方向

本路线按用户最新确认拆成两个有独立验收与存盘点的阶段。**Alpha 先守住旧版形状，Beta 才形成新版。**不能把两阶段的代码、需求和验收混成一个大改版。

### 第一阶段：0.6.0-alpha——迁移旧版，保持旧形状

从现有 0.5 开发源码搬迁必要代码，允许少量、可解释、可回退的适配和修复；不做大规模架构、UI、交互或功能重设计。保留旧版主界面、导航、主题、交互节奏及其日用能力，作为可启动、可操作、可保存的迁移基线。桌面 Alpha 必须产出实际 Windows exe，并完成相关真窗验收。

Alpha 暂时保留旧版的任务入口等既有界面元素，以维护“旧版形状”；不在该阶段借迁移之名提前删改。Alpha 的数据库、用户数据与安装目录隔离，不自动导入或覆盖日用档案。候选 Node `next/` 不得进入 Alpha 的文件集、版本包或提交。

Alpha 完成后，先将该阶段作为独立 Git 检查点提交并推送到 `dev-0.6`，并保留可回滚的 `0.6.0-alpha` Windows exe。只有这一检查点完成后，才开始 Beta 的大改造。此处“推送存盘”指 Git 分支检查点；是否创建公开 Release/正式发布另按仓库发布治理执行。

### 第二阶段：0.6.0-beta——从 Alpha 出发形成新版

从已推送的 Alpha 检查点继续，才进行真正的架构、UI/UX、交互和功能重构。Pro Web Demo 中经核查的行为、边界和测试用于启发与对照；不照搬其静态外观，也不把其 Node Runtime 当正式核心。形成具有自身一致性的新产品，同时保留最终确定的日用能力，并交付 Rust RT、Web 前端与 Tauri 宿主协同的 Windows Beta exe。

### 用户确认的最终技术方向与产品边界

1. **Tauri App 是正式产品宿主**：承担独立桌面窗口、全局快捷键、托盘及生命周期；Android 若进入 Beta 目标，也使用明确的原生承载和后台方案。
2. **Rust RT 是可扩展核心**：拥有运行时能力和本机最终 apply 权威；Web 是可灵活组织的前端，不承担长期同步调度或业务真相主权。Node 候选仅作 Beta 参考与行为对照。
3. **Alpha 保持旧版形状，Beta 再形成新版**：Alpha 对齐旧版主窗、悬浮窗、主题、工作流和反馈；Beta 才可重新组织布局、功能入口和交互，并用真实使用路径验收。
4. **按当前用途精简 Beta**：不再自建任务管理；保留时间块开始、暂停/恢复、结束、状态、备注与反馈、自动总结、悬浮呈现，以及文字/图片/文件收集。已配对设备应自动同步，离线后补齐；原件保留至用户主动清理。
5. **先打通简单、组合式的单通道**：优先验证现有 EasyTier 网络上的同版本设备连通、认证、持久化和补齐；避免把配对流程设计得比用户需要更繁琐。协议断代需与同版本互通、迁移说明及匹配的新 Agent skill 一起交付。
6. **数据保护先于功能精简**：Alpha 不破坏旧数据；Beta 先明确旧任务/其他档案的查看、导入、保留和主动清理边界。历史数据用于信息扩展和对照，不取代当下使用证据。

WinCraft 可以承担悬浮窗主要 UI，外心提供状态接口或 provider 抽象；这是 Beta 可评估的组合方案，不是 Alpha 的前置条件，也不能在真实宿主验证前替代旧悬浮工作台。正式 Tauri App 的主窗口、快捷键和托盘属于两个阶段都要保住的桌面能力。

## 5. 两阶段 UI / UX 与交互基准

**Alpha 的判断标准是“形状与日用路径没有被重构打散”。**它复用旧版真实页面与交互，保留任务入口和现有导航；只做为新版本启动、构建、持久化或修复阻断所需的少量改动。不得把 Beta 的新布局、青绿色候选 CSS、Node 页面或尚未验证的动效提前塞入 Alpha。

**Beta 的判断标准是“围绕即时上下文存储形成完整的新产品”。**可以重排主导航与页面、移除当前用途不成立的任务管理、把文字/图片/文件快速收集与时间块回顾组合起来；从旧版继承已验证有效的状态反馈和系统工作流，从 Web Demo 提取行为契约，但不要求像素级复刻 Demo。风格和交互最终以 Beta 的新设计及真实任务验收。

| 表面 / 任务 | Alpha：保持旧版形状 | Beta：重构目标与验收 |
|---|---|---|
| 应用壳与主题 | [全局 token](../../src/index.css)、`tailwind.config.js`、[UI 规范](../development/ui-spec.md)、[#807 计划](2026-04-02-issue-807-ui-unification-implementation-plan.md)；导航、字体层次、暖色品牌、亮/暗主题和特殊表面保持现状 | 形成独有的新信息架构和视觉系统；用实际容器验证密度、主题、焦点、反馈和窄屏操作完整性 |

| 桌面系统入口 | `src-tauri/src/commands/shortcut_commands.rs`、`now_workbench_overlay_commands.rs`、`src/services/main-window-shortcut-runtime.ts`；快捷键、焦点、隐藏/显示、Alt-Tab、关闭与托盘维持旧行为 | 重构后逐项复验全局热键、托盘、窗口生命周期、跨 WebView 状态一致；[#963](https://github.com/exomind-team/exomind/issues/963) 仍开放，不能以 issue 存在冒充已实现 |
| 动效与跨端 | 以上组件、`src/index.css` 和现有端到端测试；避免迁移时丢失时序、中断和减少动效行为 | 新动效对应真实事件；检查键鼠/触摸等价、断连/失败/迟到结果、手机安全区与减少动效 |

**Alpha 基线采集**：使用隔离的旧版开发实例和合成数据，比较空闲、进行中、暂停、结束反馈、长文本、图片/文件、失败、断连与重启；记录主窗和悬浮窗画面及短交互。当前只拿到运行中 PC v0.5.1 的可访问结构，尚无可用截图/动效录制；必须补齐隔离真窗基线后再宣称 Alpha 保持视觉体验。不可将含个人记录的日用窗口截图放进仓库或交接包。

**Beta 对照采集**：对照同一组匿名合成场景，分别观察 Alpha 旧界面、Web Demo 行为和 Beta 页面；记录哪些旧路径保留、替代或移除及其证据。截图只证明几何/视觉，交互录制与真实宿主操作才证明时序/行为。
