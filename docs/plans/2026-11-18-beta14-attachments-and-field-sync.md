## 附件存储与运行边界

挂载意图先可靠保存，再固定源字节，最后才允许用户提交一组引用。普通文件和剪贴板引用可能被改名、删除、撤销权限或在重启后失效，因此不能只保存路径并假定稍后读到的仍是原内容。用户文件始终只读；桌面 Native 直接分块读取选中文件，边界工作不通过整文件 JS 数组完成。浏览器/Android HTML File 输入保留有界二进制通道；Android URI剪贴板先流式保存私有快照，不再以16MiB图片Base64通道冒充任意文件支持。

私有源副本按设备/P/文件ID绑定，Core附件库按固定描述与SHA校验。后者已就绪时，按原代际CAS释放重复源，清理失败不会把已验证结果写成失败，也不会删除更新的副本。草稿预览可以读取已验证的私有stage，不因重复源释放而消失。阶段/耗时只在内存观察，不逐块写草稿日志；界面隐藏可停止绘制，已接受的Native工作及后台原件获取不依赖消息行挂载。

系统打开只接受档案/原件/请求ID：先通过已提交原件路由核验，再生成并校验应用缓存副本。Windows交给默认程序；Android通过仅覆盖`beta-open`缓存的FileProvider授予本次只读URI并调用系统打开方式。原件正文不因此送给模型，自动获取/预览也不执行附件。

准备工作最多两路。显式取消按确切UUID；异步入场前的取消意图也保留，晚到请求不能逃逸。应用退出会停止并排空自有工作。选择意图写盘失败只标记仍属于本轮的文件，保留等待期间的新文字、后来加入的文件和用户已移除的状态；新增红例实际证明旧实现曾覆盖新文字。

图标源仍为仓库批准的Alpha品牌pack。每次fresh init后准备普通/圆图/前景、背景和自适应XML，绑定manifest并覆盖已有API33模板别名；不手改或提交生成目录，也不凭空绘制新的单色品牌。最终包需核对实际资源，不以源码PNG存在替代验收。

Android第一轮Rust编译完成，在既有Windows符号链接权限处失败；核对fresh AArch64 ELF与未解析符号后，`android-package-a`实际清单合并失败：原件插件和Tauri都直接声明`androidx.core.content.FileProvider`，Android按类名合并，独立authority仍冲突。改由插件自己的`BetaOriginalFileProvider`继承该类，保持原authority、`beta-open/`唯一缓存路径及只读授权，不覆盖Tauri provider或扩大文件暴露。`android-provider-green`合并通过但暴露插件未声明AndroidX Core编译依赖；按其他Android插件同版显式补依赖后，`android-provider-green-b`真实清单合并/Kotlin编译通过、正常0/清理确认。两失败保留，不把工作树验证冒充最终APK；后续重新从提交构建并核包。此项仅Android源码，已验Windows EXE仍绑定4c72a0e5。
