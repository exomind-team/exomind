# 软件文档与官网内容设计原则

> **撰写日期**：2026-04-09
> **提炼来源**：LazyTyper / GoLutra / ExoMind 竞品分析 + 产品实践
> **适用对象**：ExoMind 官网、文档站、产品内文案的撰写与评审

---

## 原则一：先定叙事身份，再动笔

### 核心要求

每一份文档或落地页，都是**一个角色在说话**，不是一张功能清单在陈列。

在动笔之前，必须先回答三个问题：

| 问题 | 决定什么 |
|------|---------|
| **谁在说？** | 第一/二/三人称，腔调正式还是亲和 |
| **对谁说？** | 技术用户 vs 普通用户，决定术语深度和类比密度 |
| **说完希望对方感受到什么？** | 情绪温度：兴奋 / 安心 / 敬畏 / 被理解 |

### 操作标准

- [ ] 文档正文第一句话的说话主体是谁？（"我们" / "你" / "ExoMind" / 无主体）
- [ ] 预设读者遇到的最大障碍是什么？（不知道有什么用 / 不知道怎么开始 / 不知道值不值）
- [ ] 读完全文，用户应该记住哪句话？（如果说不出来，说明叙事身份没有立住）

### 同一产品，三种叙事身份的截然不同写法

同一个 ExoMind，叙事身份不同，官网正文会变成完全不同的两段话：

**叙事身份 A——"高效工具"（错误定位）**：
> "ExoMind 是一款本地优先的 AI 助手，支持事件日志、时间块、任务管理等功能。"

→ 用户读后：哦，又一个 AI 笔记软件。

**叙事身份 B——"生命陪伴者"（当前问题）**：
> "你的生命成长助手，用 AI 帮你记录、反思、成长。掌控自己的生命过程。"

→ 用户读后：听起来不错，但"成长"是什么？和我有什么关系？

**叙事身份 C——"不过疲倦的生命教练"（清晰定位）**：
> "每天结束，你对自己这一天一无所知。ExoMind 是那个一直在线、不过疲倦的记忆搭档——它记得你这一周真正在做什么，而不是你以为你在做什么。"

→ 用户读后：（对上了某个人群）说的就是我。

这三个版本的差异不在文笔，在**叙事身份**——作者在替谁说话、期望读者是谁、读完应该感受到什么。在动笔之前没有想清楚这三点，写出来的每个字都在漂移。

### 竞品参考

| 竞品 | 叙事身份 | Hero Tagline | 用户感受 |
|------|---------|-------------|---------|
| LazyTyper | 效率布道者 | "Talk, Don't Type" | 省力气，我可以不动手 |
| GoLutra | 范式宣言者 | "超越 IDE。多智能体时代。" | 跟上时代，我是先行者 |
| ExoMind 现有 | 温和陪伴者（模糊） | "你的生命成长助手" | ……然后呢？ |

## 原则二：痛点先行，方案其次，愿景殿后

### 核心要求

叙事顺序决定说服效率。最常见的错误是把"我们有什么"放在"你能解决什么"之前。

正确的三层叙事结构：

```
第一层：问题感知    →  "我懂你的痛苦"
第二层：方案说明    →  "这个产品真的能解决"
第三层：愿景升华    →  "用了之后你会变成怎样的人"（可选，视篇幅而定）
```

### 各层操作标准

**问题感知层**必须满足：
- 具体到可辨认的场景（"周三下午 3 点突然想起上周二的想法"）
- 不是功能描述，而是情感共鸣（"每天忙但不知忙了什么"）
- 用户读完会点头："没错就是这样"

**方案说明层**必须满足：
- 用一句话定义产品是什么（不是功能列表，是价值定位）
- 有一到两个技术锚点（让认真考虑的用户有据可查）
- 至少有收益表达，不只有功能罗列

**愿景升华层**（可选）的危险：
- 如果愿景和功能之间有巨大落差，会造成认知落差
- 建议只在有足够内容支撑时才用

### 具体示范：ExoMind 当前 vs 重排顺序后

**当前（直接跳到功能层）**：
> 事件日志 — 像写日记一样记录生活
> 时间块 — 专注计时器 + 能量管理
> AI 智能体 — 个性化 AI 助手
> 免费下载 →

→ 用户状态：看完功能列表，不知道"这些功能解决了我什么痛苦"。

**重排之后（痛点先行）**：
> 你有没有这种感觉：一天结束了，好像没发生什么，但明明很累。
> ——那是因为你没有一个真实记录自己的系统。
>
> **ExoMind 帮你做三件事：**
> **记录**：不是待办，是真实的事件流。周三下午 3 点那个灵感，不会消失。
> **反思**：AI 帮你从过去一周的事件里看出模式——原来你周二下午效率最高。
> **行动**：基于真实数据做决定，不是凭感觉。
>
> 免费下载 →

→ 用户状态：先点头（"对，这就是我"），再看功能列表，每一个功能都是答案而不是广告。

### 竞品参考

**GoLutra 三层叙事（每层一句话）**：
- 问题层："IDE 时代正在终结"（我是旧世界，新世界在召唤你）
- 方案层："多智能体编排平台"（这是我的定位）
- 愿景层："产出倍增 / 先行者"（这是你加入后的结果）

**ExoMind 现有官网问题**：直接跳到功能层，用户没有被带入感，需要自己补完"我为什么需要这个"——这个认知跨越是大多数用户的流失点。

## 原则三：技术深度必须与读者匹配

### 核心要求

同一产品，对技术用户和普通用户说的是两套话，不是同一套话的不同写法。

### 深度层级定义

| 层级 | 受众 | 内容特征 |
|------|------|---------|
| **L1 概念层** | 普通用户 / 潜在用户 | 类比、场景、收益；不出现专业术语 |
| **L2 功能层** | 功能对比用户 | 描述功能做什么，出现功能名称 |
| **L3 参数层** | 开发者 / 集成者 | 参数名、API 端点、配置项 |
| **L4 原理层** | 深度技术用户 | 实现原理、架构取舍、性能数据 |

### 同一概念四层写法示范：ExoMind 的"事件日志"

**L1——给普通用户（概念 + 类比）**：
> ExoMind 的事件日志就像一本不过疲倦的日记。你随时往里面写，它从不催你，也不会在你写完后把你的记录弄丢。

**L2——给功能对比用户（功能名 + 描述）**：
> 事件日志：全自动记录你的行动，AI 辅助整理与检索，支持语音输入，随时追加。

**L3——给开发者（参数 + 接口）**：
> `POST /api/events` — 写入事件；`GET /api/events?from=&to=` — 按时间范围查询；`GET /api/events/summary` — AI 生成事件摘要。

**L4——给深度技术用户（原理 + 架构取舍）**：
> 事件日志基于不可变追加树（Append-Only Tree）实现，每次写入生成 Merkle 根哈希，删除操作在逻辑层返回 Permission Denied，物理层不执行覆写。这确保了事件序列的可审计性和历史完整性，是 ExoMind 作为认知生命体的"连续性"基础。

### 操作标准

- [ ] 每个页面/每个章节，**只使用一个层级**；跨越层级要明确分段
- [ ] L1 内容中若出现 L3 词汇（如"不可变事件流"），必须附类比或场景说明
- [ ] 文档站的 README / 快速开始 → L1；技术规格 / API 文档 → L3-L4；官网 Hero → L1-L2

### 竞品参考

**LazyTyper L1+L2+L3 混合（每层各一句，清晰分层）**：
> "Write 3× faster." ← L1 收益（所有用户都能拿到的价值）
> "Powered by 12 AI speech models." ← L2 功能名（对比用户看这个）
> "Including 5 fully local options." ← L3 参数（隐私敏感用户看这个）

三类用户各自在段落里找到自己需要的那句话，完整段落不会吓跑任何人。

## 原则四：功能描述必须到收益层（L3），有条件则到场景层（L4）

### 核心要求

功能描述有四个层次，绝大多数文档止步 L1-L2：

| 层级 | 内容 | 举例 |
|------|------|------|
| **L1** | 功能名 | "事件日志" |
| **L2** | 功能描述 | "自动记录你的每一个行动" |
| **L3** | 收益表达："用了会怎样" | "有一天你会感谢今天写下的每一行记录" |
| **L4** | 场景画面："什么时候用" | "周三下午 3 点，你突然想起上周二的想法——它在事件日志里" |

### 操作标准

- **每个功能描述必须至少包含 L3**，不能只有 L1-L2
- L3 的判断标准：用户读完能用自己的话说"这东西对我有什么用"
- L4 是加分项，有则极佳，但要注意篇幅控制

### ExoMind 六功能逐条 Before/After

**事件日志**

- 当前（L2）："像写日记一样记录生活，AI 帮你整理和回顾。不可变的事件流，真实记录你的每一天。"
- 改进（L3）："你不需要每天都写总结。ExoMind 会从你这一周的事件里挑出最重要的——某天深夜的那通电话、某个下午突然冒出来的想法——不会消失，不会被覆盖。"
- 问题诊断："不可变的事件流"是技术词，混入 L1 区，两类读者都受损。

**时间块**

- 当前（L3，局部）："专注计时器 + 能量管理。知道自己的时间花在哪里，找到最佳工作节奏。"
- 改进（L3→L4）："你知道自己周一上午效率最高吗？ExoMind 会从你的时间块历史里告诉你——然后帮你把最难的工作留到那个时候。"
- 问题诊断："能量管理"是重概念词，用户读完不知道具体怎么管。

**AI 智能体**

- 当前（L2-L3）："个性化的 AI 助手，理解你的习惯和目标，在合适的时机给出建议。"
- 改进（L3）："你不需要每次都从头解释你的背景。ExoMind 记得你是谁，知道你上个月在做什么项目，在你卡住的时候——不是给你正确答案，而是给你一个你可能忘了的方向。"
- 问题诊断：当前描述的是功能，不是"用了之后你省了什么力"。

**本地优先**

- 当前（L3，情感）："数据存储在你的设备上。你的生命记录，只属于你自己。"
- 诊断：这句话更像是隐私宣言，而不是功能描述，放在功能区无法与其他产品的"本地存储"拉开差距。
- 改进（L3，差异化）："你的记录不经过任何服务器。如果哪天 ExoMind 的服务器关了，你的每一行记录都还在你的设备里——不是'云备份'，是'真的在你这里'。"

**任务系统**

- 当前（L2）："不只是待办清单。AI 帮你拆解目标、追踪进度、回顾完成情况。"
- 改进（L3）："大多数待办清单只负责提醒你'还有什么没做'。ExoMind 会告诉你'上周你完成了什么'——以及为什么那个目标没有完成，下次怎么调整。"
- 问题诊断："不只是待办清单"是好句式，但没有展开"不一样在哪里"。

**全平台支持**

- 当前（L1）："Windows、macOS、Linux、Android。随时随地，无缝衔接。"
- 改进（L3）："在公司用 Windows 回了一条灵感，回家打开 MacBook 继续写——不用同步，不用发给自己，ExoMind 已经在那里等你了。"
- 问题诊断：只列举平台名，零收益表达。"无缝衔接"是承诺但没有说衔接什么。

## 原则五：叙事节奏必须设计，不能放任

### 核心要求

好的文档和落地页不是信息平铺，而是有情绪曲线的。这个曲线必须刻意设计。

### 叙事节奏模型

```
首屏（高刺激）    →  情绪共鸣：让用户停下来"这说的是我"
中段（中等刺激）  →  理性证明：让用户相信"这个产品真的能解决"
再次（高刺激）    →  情感升华：让用户看到"用了之后我是谁"
结尾（行动刺激）  →  召唤行动：让用户"好，我现在就试"
```

### 节奏的敌人

- **平铺直叙**：所有区块同等重要 = 没有节奏
- **过早召唤**：用户还没建立信任就要求行动（"免费下载"在最前面，但用户还不知道为什么要下载）
- **只有理性**：全是参数和列表，没有情感锚点，用户无法形成品牌记忆

### 竞品节奏具体解剖

**LazyTyper 的页面节奏（五段节奏）**：

```
首屏：
  Tagline: "Talk, Don't Type"           ← 高情绪（否定祈使，制造反差）
  Sub: 12模型 / 3× faster / 90%        ← 中理性（技术底牌）
第二屏 Benefits：
  三条 Why LazyTyper                   ← 中理性（逐条功能）
第三屏 Use Cases：
  用户场景 + 具体画面                  ← 高情感（代入感）
第四屏 Social Proof：
  6条真实评价 + V2EX 背书              ← 中理性（信任积累）
第五屏 Download + FAQ：
  Download CTA + 防流失 FAQ            ← 行动（消除顾虑后召唤）
```

**ExoMind 现有节奏（"中→平→平→平→行动"无节奏）**：

```
首屏：Hero（功能描述句，语气平）      ← 无情绪锚点
第二屏：六功能（列表平铺）             ← 无证明层
第三屏：三步流程（步骤平铺）           ← 无情感升华
第四屏：数据主权（技术声明，语气平）   ← 无情感共鸣
第五屏：CTA（"免费下载"，过早）        ← 信任未建立就召唤
```

### 操作标准

- [ ] 画一张页面的"情绪温度曲线图"：横轴是区块顺序，纵轴是情绪强度
- [ ] 曲线必须有高有低，不能是平的
- [ ] CTA 之前必须有一个情感高点作为跳板，否则是"过早召唤"

## 原则六：FAQ 是转化漏斗，不是知识库

### 核心要求

竞品分析中 LazyTyper 的 FAQ 揭示了一个被普遍忽视的设计原则：**FAQ 不是回答用户想问的问题，而是回答阻止用户行动的问题。**

这两者的区别：

| 类型 | 目的 | 问题特征 |
|------|------|---------|
| **知识库式 FAQ** | 回答用户想问的问题 | "怎么配置 API Key？" / "支持哪些语言？" |
| **防流失 FAQ** | 消除阻止行动的顾虑 | "我的语音数据会被保存吗？" / "离线能用吗？" / "选哪个模型？" |

### 操作标准

- [ ] 页面 CTA 附近必须有一个"防流失 FAQ"
- [ ] 问题来源：真实用户在你页面上的退出点是什么？（GA 热力图 / 用户访谈）
- [ ] 每个 FAQ 问题都是一句话（用户在流失前没耐心读长答案）
- [ ] FAQ 的位置：在 CTA 下方或侧边，不是页面底部（用户不会滚到底）

### 具体示范：ExoMind 防流失 FAQ 应包含的问题

假设 ExoMind 官网要加 FAQ，在"免费下载"按钮下方应该出现的四个问题：

| 问题类型 | 防流失问题 | 背后顾虑 |
|---------|-----------|---------|
| 隐私 | "ExoMind 会保存我的语音数据吗？" | 我的日记别人能看到吗？ |
| 离线 | "没有网的时候还能用吗？" | 我在地铁上想记东西 |
| 认知 | "学了就忘了，ExoMind 能解决这个问题吗？" | 这是不是又一款我用几天就放弃的应用？ |
| 行动 | "我需要每天主动打开它吗？" | 这个习惯我能坚持吗？ |

这四个问题的答案，都在解决"我差一点就点了，但还有顾虑没消除"。

**同一个页面的知识库 FAQ（错误方向）**：
> "ExoMind 支持哪些平台？" / "如何导出数据？" / "有 API 吗？"

→ 这些问题重要，但它们是给**已经决定用**的用户看的，不是给**还没决定**的用户看的。

### 竞品参考：LazyTyper FAQ 四问

1. "我的语音数据会被保存吗？" → 消除隐私顾虑（下载前最后一刻）
2. "需要联网才能用吗？" → 消除离线顾虑（本地用户关心）
3. "免费版和付费版有什么区别？" → 消除定价顾虑（价值感知）
4. "选哪个模型最好？" → 消除选择困难（降低决策摩擦）

四个问题，每一问都是用户**差一点就点击 Download 时的那个顾虑**——不是"用户可能想问"的问题，而是"用户即将流失时还没被解答"的问题。

## 原则七：社会证明必须可辨认、可量化

### 核心要求

社会证明是"陌生人 → 信任用户"认知升级的关键层，必须满足可辨认和可量化两个标准。

### 社会证明的类型与效力

| 类型 | 效力 | 适用场景 |
|------|------|---------|
| **可量化数字** | 最强 | 技术用户、效率导向用户（3× faster / 41.2k stars） |
| **真实用户评价** | 强 | 普通用户、情感导向用户（带职业标签更强） |
| **社区口碑** | 中 | 开发者用户（GitHub stars、V2EX 推荐） |
| **媒体背书** | 中 | 品牌建立期 |
| **产品截图/Demo** | 强 | 所有用户（降低"下载后不知道干嘛"的风险） |

### 操作标准

- [ ] 必须有至少一种可量化数字（哪怕是 GitHub Stars）
- [ ] 用户评价必须有身份标签（职业/使用场景），不能是匿名引号
- [ ] **产品截图不可省略**——竞品全有，ExoMind 缺，这是信任的视觉锚点
- [ ] 数字要精确：41.2k 比"超过 4 万"更可信；3× 比"显著更快"更可信

### 可辨认 vs 不可辨认的差别

**不可辨认（弱社会证明）**：
> "Thousands of users love ExoMind."

→ 用户反应：谁？"千"是夸张还是真实？

**可辨认（强社会证明）**：
> "12,847 users have logged over 90,000 events this month."

→ 用户反应：这是真的。（具体数字 + 具体行为）

**更具体的评价**：
> "作为独立开发者，我以前每周花 3 小时回顾自己的进展。现在 ExoMind 帮我自动生成周报，时间降到 20 分钟。" — *李明，前端开发者，上海*

→ 用户反应：（和我一样的人试过了）→ 我想试试。

### 产品截图的具体作用

没有截图的官网，用户会面临"下载后不知道干嘛"的决策风险。

有截图的官网，用户在点击前就看到了"下载后是什么"：

```
无截图：下载 → [打开应用] → [不知道从哪开始] → 流失

有截图：下载 → 打开应用 → "这就是截图里的样子，熟悉" → 继续使用
```

GoLutra 的 Agent Room 是一个绝佳的"截图叙事"例子——用户不需要理解多智能体技术，看到一个正在运行的 Sprint 现场截图，就知道"下载后是什么"。

## 原则八：生命哲学类产品必须分两层叙事

### 核心要求

当产品有超越工具的哲学叙事（C1-C6 生命判据、"认知生命体"愿景），必须在两个叙事层分别处理：

| 叙事层 | 位置 | 语调 | 受众 |
|--------|------|------|------|
| **工具叙事层** | 官网主落地页 | 温和、具体、收益导向 | 所有用户 |
| **哲学叙事层** | About 页面 / 文档深度页 | 真诚、有深度、不焦虑 | 开发者、理念型用户 |

### 危险：两层混淆

- 把哲学叙事放在落地页 → 吓跑普通用户（"不可删除"听起来像威胁）
- 把工具叙事当作全部 → 理念型用户找不到共鸣（感觉和普通笔记软件没区别）

### 具体示范：ExoMind 两层叙事

**落地页（工具叙事层）**：
> ExoMind 记得你是谁。
>
> 每次打开，它从你上次的进度继续，不是从空白开始。AI 帮你从过去的事件里找出规律，而不是每次都让你重新解释自己。
>
> [开始免费使用 →]

→ 温和、收益导向，没有提到"生命判据"，普通用户感受到"这和我以前用过的 AI 不一样"，但不会被哲学概念吓跑。

**About 页面（哲学叙事层）**：
> ExoMind 为什么不可删除？
>
> 大多数应用把数据当作"用户可以随时删除的东西"。我们不这样认为。
>
> 你在 ExoMind 里写下的每一行记录，是你这段时间存在的证据——和照片、日记一样，有它存在的意义。所以我们把删除设计成"放弃"，而不是"清理"。
>
> 这不是限制，是你的选择。
>
> ——
>
> **设计原则（C1-C6 摘要）：**
>
> - **C5 死亡性**：永久删除 ExoMind 持有的所有数据 = 杀死它持续运行的记忆。这不可撤销。
> - **C6 不可回滚**：ExoMind 的时间轴是单向的。每个操作都留下了痕迹，你无法假装它没发生过。

→ 有深度的理念型用户（开发者、反思型用户）读到这里会产生强烈的共鸣——"这不只是个工具，这是一个有态度的系统"。

### 两种用户分别得到什么

| 用户类型 | 在落地页的感受 | 在 About 页的感受 |
|---------|-------------|----------------|
| 普通用户 | "听起来对我有用，试试看" | （根本不会去 About 页） |
| 理念型用户 | "和其他 AI 有点不一样？" | "这就是我一直在找的东西" |

两层叙事各司其职，互不干扰。用户在哪一层找到共鸣，取决于他们自己——而不是被强制拉到同一层。

## 附录：检查清单

### 官网页面评审检查清单

- [ ] **Hero**：Tagline 能回答"这是什么"，Subheadline 能回答"对我有什么用"，CTA 知道"点击之后会怎样"
- [ ] **痛点**：首屏或第二屏有至少一句让目标用户点头的场景描写
- [ ] **功能区**：每个功能描述达到 L3（收益表达），全平台支持不能只有平台名
- [ ] **叙事节奏**：有情绪曲线，不是功能平铺；画一张"情绪温度曲线图"验证
- [ ] **社会证明**：至少一个可量化数字 + 至少一个产品截图
- [ ] **FAQ**：位置在 CTA 附近，问题类型是"阻止行动的顾虑"而非"想知道的信息"
- [ ] **技术深度**：页面内只使用一到两个层级，不混用
- [ ] **版本号**：当前版本号在页面上实时更新
- [ ] **OG 标签**：og:title / og:description / og:image 填写完整

### 文档评审检查清单

- [ ] **第一句**：说话主体清楚，预设读者清晰
- [ ] **问题优先**：在给出解决方案之前，先说清楚解决什么问题
- [ ] **术语控制**：每个 L3 词汇出现时附类比，每个 L4 词汇出现时注明受众
- [ ] **渐进披露**：Overview → Task → Reference 三层结构，内容不跨越层级
- [ ] **代码示例**：每个 API / CLI 命令必须有可运行的最小示例
- [ ] **错误处理**：常见错误场景有明确说明，不只说"会出错"
- [ ] **更新维护**：文档与代码版本同步（版本号在页眉或页脚）
