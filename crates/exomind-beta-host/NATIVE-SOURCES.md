# Native 草稿原件暂存

Native 未发送稿的文件字节存放在独立的 `private-sources/sources.sqlite3`。
它不追加 Core 事实、不建立业务引用，也不提供 HTTP、Agent 或浮窗读取入口。
文字与固定提交快照仍由 [Native intent journal](NATIVE-INTENTS.md) 保存。
Web 端继续使用浏览器文件副本；Native 失败不得回退到 IDB。

## 身份、范围与提交顺序

- 仅当前 Host 的 owner session 可调用；key 必须是规范 JSON
  `[当前 device UUID, 已存在的 profile UUID, original UUID]`，不是路径。
- 同 key 的长度与 SHA-256 永久绑定，释放后保留身份墓碑；不同内容必须使用新身份。
- 选中文件先分块复制并完成独立完整 hash 校验，再确认草稿中的原件清单。
  Core 上传使用同一份有界 range reader，整组验证完成后才提交业务记录。
- 不能把本机复制完成当作业务提交回执或另一设备已持有。

## 有界读写与状态

单个源上限 4 GiB，活动源累计预留上限 8 GiB；重新启用已释放源也须重新检查预留。
这是当前工程上限，不授权自动淘汰其他资料。
物理块固定 256 KiB，末块可更短；每块有 SHA-256。
偏移、长度、完整块布局、重放内容和溢出均须检查。
读取至多跨两个物理块，前端不组装整文件 Blob。

`copying → frozen → ready / hash_mismatch`；显式释放进入 `released`。
每次字节追加、冻结或释放推进 generation，完成状态只来自实际校验。
同偏移相同字节可重放，不同字节不能覆盖已接收前缀。
SQLite 使用 WAL 与 FULL 提交；应答表示该次事务已提交，不承诺物理掉电已验证。
两个私有连接都先设置 512 KiB 的 SQLite 单值/行限制，再查询定长身份与有界块，
避免损坏库在应用检查长度之前分配过大字符串或 BLOB。

完整 hash 在 Host 主锁之外，通过独立只读连接的短事务进行；最多两个校验任务。
最终提升为 ready 前重新检查停止状态、owner、源身份与 generation。
即使已是 ready，显式重验也不能跳过完整 hash。
Host 停止先禁止新操作并取消校验，等独立读连接退出后才释放根目录。

## 释放与恢复

释放必须携带实际读句柄持有的预期 generation，不得先查最新代次再删除。
先提交 released 墓碑，再按有界批次回收私有块；每批重新检查代次并让出 Host 主锁。
旧清理操作不得删除随后重新选择产生的新副本，也不删除 Core 原件或业务事实。

完整字节已提交、校验应答中断时，可以重新校验已有副本，不重建 File。
实际缺件必须明确显示缺少来源；用户正确重新选择后才能复制缺失字节。
错误文件不能改变原固定提交。
健康 ready 副本重新选择时先完整重验并复用，不能先删后重拷。
锁冲突、无法打开、权限或 I/O 错误属于暂不可用，不授权删除；只有明确坏字节且
原绑定/代次仍匹配时，用户正确重选才可按旧代次 CAS 重建该源。

初始化以独立 `private-sources.initialized` 标记、应用/schema/layout 与 device 绑定校验。
已初始化目录、库或绑定缺失/损坏时停止暂存操作并保留现场，不能静默创建空库。
这类缓存失败不应破坏仍可用的 Core 文字与既有原件。

## 验证范围

专项覆盖真实自有 writer 子进程强杀、分块重开、跨块读取、块与完整 hash 损坏、配额重开、
SQL 拒写保留前缀、owner/档案/生命周期隔离、迟到清理 CAS、校验取消及停止后的提交围栏。
物理掉电、多 GiB 实机吞吐、所有厂商 Android 存储行为与完整文件选择器业务链路须另行验收。
