# Beta26 外心环境与多连接设计

> 状态：方向已获用户批准；待进入实施。  
> 日期：2026-11-21。  
> 范围：附近发现、邀请、环境身份、连接管理、同步可观测性，以及跨这些
> 状态面适用的 UI/UX 默认规则。

## 1. 目标

本轮选择增量方案 B：

1. 先修复现有邀请、发现和错误呈现中的确定性缺陷；
2. 再把设备身份从档案内路由列表中析出，形成稳定的“外心环境”；
3. 让同一对设备同时持有多条连接，分别控制本端启停、记录对端可见状态并手动测试；
4. 把邀请从“复制一大段 JSON”改为一次发现后即可发送、另一端确认的完整流程；
5. 让每次同步能够追溯到来源环境、目标环境、所用连接和最终阶段；
6. 在所有等待和错误中提供可执行出口或可复制的脱敏诊断。

这不是把现有的“档案成员”改造成一个更宽的权限。环境发现、连接可达和档案
授权继续是三件事：

- 发现只证明某个地址最近宣布过外心环境；
- 连接测试只证明某条路径当前能完成身份核验和协议交换；
- 只有同一档案的有效成员授权才允许读取、追加或同步该档案。

## 2. 不照搬 T3 Code

T3 Code 的“Environment 稳定、route 可变、连接由单一 supervisor 管理”是
本轮借鉴的工程规律。外心不复制 T3 的 provider、thread、project、MCP OAuth、
remote delegation 或完整守卫器实现，也不把 T3 的环境列表当成外心用户对象。

方案 C 即“完整连接督导器/多路优选与自动回切”只进入长期路线图。执行它需要
先有 B 的真实故障矩阵、性能和移动端证据，不能以架构相似为由提前重写网络层。

## 3. 当前事实

### 3.1 已确认缺陷

- `PeerNetwork::endpoints()` 过滤回环地址后又无条件追加 `127.0.0.1`/`::1`。
- 邀请会把该回环候选发给其他设备；接收端打开它时实际连接自己的 Host。
- 候选遍历中 `PeerPinMismatch` 的优先级高于超时和普通 TLS 失败，因此“远端
  都不可达”可能被最终显示成“邀请方证书不符”。
- “检查邀请”目前只核验邀请签名、协议、schema 和替换关系，不检查来源设备
  当前连通性。
- 设备页当前只被动读取广播，没有用户触发的批量内网扫描。
- 生成邀请后仍需用户另行点击复制。
- 加入成功后没有持久显示该档案来自哪个外心环境。
- 网络开关只有一个全局状态，route 按 `(profile_id, device_id)` 保存；无法
  表示“本端开启、对端关闭”“对端拒绝”“手动测试”或“这次同步用了哪条连接”。

### 3.2 当前可复用能力

- 稳定设备身份与 TLS pin；
- 一次性签名邀请、有效期、撤销和幂等 claim；
- IPv4/IPv6 监听、UDP 被动发现、应用协议服务选择；
- 每档案成员 generation、能力、撤销和 route 持久化；
- 有界事件/原件同步、历史证明和持久回执；
- Host 为唯一业务所有者；
- 已有诊断导出、错误码和按需诊断入口。

这些能力继续保留。新增环境与连接层不能绕过它们。

## 4. 核心对象

| 对象 | 身份与所有者 | 作用 | 不允许推导 |
|---|---|---|---|
| `Environment` | 稳定 `device_id`；远端记录归本机 Host | 一个可被连接的外心实例 | 不代表已授权任何档案 |
| `Profile` | 稳定 `profile_id`；Core/Host | 数据与成员权限范围 | 不因同名环境自动合并 |
| `Membership` | `(profile_id, environment_id)`；Host | 该环境对该档案的读写能力和撤销 | 不因连接建立自动产生 |
| `Connection` | 本机生成的稳定 `connection_id`；Host | 本机到另一环境的一条持久连接配置 | 不是 session、route 或 grant |
| `RouteCandidate` | 连接内短期/可更新端点 | 一次尝试的 IP、端口和接口来源 | 地址可达不等于环境身份 |
| `RuntimeChannel` | 单次 TLS/服务通道；Native/Host | 一次实际传输 | 不进入长期身份键 |
| `InvitationProposal` | 一次性 ID；本机持久 | 已由邀请方发送、等待接收方确认的邀请入口 | 不等于已接受 membership |
| `SyncAttempt` | 稳定尝试 ID；Host | 一次同步及其路径/阶段日志 | 不代表原件或人工验收完成 |

`device_id` 即当前实现中的稳定外心环境 ID。首版不新增第二个环境 UUID；
API 可增加 `environment_id` 作为语义别名，wire 兼容字段仍保留 `device_id`。
`runtime_id` 继续只表示本次进程实例，不能跨重启充当环境身份。

## 5. 连接模型

### 5.1 一条连接是什么

一条 `Connection` 表示用户可见的两环境传输配置，至少包含：

- `connection_id`：稳定本地 ID；
- `remote_environment_id`；
- `kind`：物理网络、EasyTier、其他用户态覆盖网、手工地址或历史迁移项；
- `local_enabled`：本端是否允许用这条连接拨入/拨出；
- `remote_enabled_observed`：最近一次从对端观察到的启停状态及观察时间；
- `endpoints`：有序、有限、去重的候选地址；
- `preferred_endpoint` 与最近成功端点；
- `last_test`、`last_connected`、`last_sync`；
- `state`、`error_code`、`next_action`；
- `created_at`、`updated_at`、`last_seen_at`。

一条连接的有效条件是本端与该环境连接均启用。若对端状态未知，UI 显示
“本端已开启、对端状态未知/截至某时”，不能推测为已关闭。

### 5.2 多连接

同一环境对可以同时保存物理 LAN、EasyTier、手工地址等连接。连接共享稳定
环境身份和档案 membership，但各自保存启停、端点、测试和最近结果。

首版连接选择策略：

1. 优先最近成功且本端启用的连接；
2. 同等条件下使用用户首选顺序；
3. 一条连接失败后尝试其他本端已启用连接；
4. 只有实际有写事实、等待通知或明确点击同步时才拨号；
5. 仅为展示状态不主动轮询所有历史连接。

“测试连接”是显式用户动作。它不创建同步尝试、不改变档案、不发布假的在线
状态；测试结果写入连接自己的最后测试记录。

### 5.3 拒绝与未知

可到达对端必须回传结构化阶段，至少区分：

- `connection_disabled`：对端明确关闭了该连接；
- `identity_mismatch`：TLS pin 与环境身份不符；
- `protocol_mismatch`：协议/能力不兼容；
- `membership_denied`：连接可达但当前档案未授权；
- `busy`、`timeout`、`unreachable`。

不可达时无法得知对端开关，必须保留“未知”。UI 不把 timeout 写成“对端拒绝”。

## 6. 持久化与迁移

Host auth 数据库升级到一个新 schema version，新增：

- `peer_environments`；
- `peer_connections`；
- `peer_connection_endpoints`；
- `peer_invitation_deliveries`；
- `peer_sync_attempts`，只保留有界近期日志。

现有 `peer_members` 和其 generation/能力/撤销语义保持不变。

现有 `peer_network_routes(profile_id, device_id, endpoints)` 迁移时：

1. 按 `device_id` 建立 environment；
2. 合并同一环境重复出现的端点；
3. 为已有端点建立 `legacy` 或可识别的 LAN/overlay 连接；
4. 保留 endpoints 顺序并把原首选端点保留为首选；
5. 不迁移任何 membership、权限或“已验证在线”状态；
6. 新表失败时整体回滚，旧库保持可恢复。

新建连接的初始状态是 `untested`。迁移不等于测试通过。

## 7. 发现与主动扫描

### 7.1 被动发现

继续保留现有被动 UDP announcement，但候选必须归到 environment，并按发现的
本地接口记录来源范围：

- physical LAN；
- EasyTier/覆盖网；
- loopback：只用于同机测试，永不进入共享邀请；
- 其他虚拟接口。

被动发现无档案参数，也不读取档案名、正文或 grant。

### 7.2 用户触发的主动扫描

设备页提供“扫描当前内网”及可选范围。扫描只在用户点击后执行一次，有明确
终态，不做无限轮询：

1. 先发送受限 broadcast/multicast 请求；
2. 对用户选择的每个本地网络范围执行有界 unicast probe；
3. 默认不扫描 loopback、link-local、unspecified、multicast 或 WSL 等不适合
   跨设备到达的范围，用户若主动选择测试范围仍只提供内部诊断；
4. 总地址数、并发数、超时和响应字节都有硬上限；
5. 返回 discovered、already-known、unreachable 和 skipped 的数量；
6. 用户可取消，取消后的迟到结果不得复活列表；
7. 没有发现时仍提供重新扫描、修改扫描范围、检查 EasyTier 状态和复制诊断。

LocalSend 的“多路径发现”是本轮参考：先 multicast/broadcast，失败后对本地地址
做 HTTP/服务级兜底。外心使用自己的 announce/probe 帧，不复制其文件传输协议。

## 8. 邀请流程

### 8.1 默认无复制流程

邀请方在某个档案页选择已发现环境并点击“邀请”：

1. Host 创建现有的一次性签名 invitation；
2. 通过所选环境连接发送一个不含业务正文的 `InvitationProposal`；
3. 接收端持久显示来源环境、档案名、有效期和本端待确认状态；
4. 接收端点击“接受”后才执行 claim；
5. 接收端点击“拒绝”时回传明确拒绝，并保留可撤回/重试的本地事件；
6. 邀请方收到 accepted/refused/expired/unreachable 等终态或明确未知。

若跨设备投递不可用，完整邀请文本复制保留为兼容退路，并在生成后自动复制。
自动复制失败时必须显示复制按钮和失败原因，不能静默。

### 8.2 “检查邀请”

检查分为独立阶段：

- 邀请完整性：签名、协议、schema、有效期、目标档案和 issuer；
- 来源环境：discovered device 与 issuer device/pin 是否一致；
- 连接可达：对邀请内候选与用户补充地址做有界测试；
- 能力兼容：协议版本与所需能力；
- 账户/档案结果：已加入、待确认、拒绝、过期、不可达或身份不符。

每个候选显示自己失败在哪一层。远端全部不可达时报告 `unreachable`，不能由
本机回环产生的 pin mismatch 覆盖真实结果。

### 8.3 加入后的来源感

档案切换器和档案详情应显示：

- 来源环境稳定 ID/可读名；
- 通过哪条连接加入；
- 最近一次来源确认时间；
- 当前连接状态和重新连接入口。

档案仍是本机完整副本；来源标识用于解释和排障，不把档案降为远端缓存。

## 9. 同步可观测性

每次实际同步产生一条有界 `SyncAttempt`：

- attempt ID；
- 来源环境/profile；
- 目标环境/profile；
- 连接与 endpoint；
- 启动原因：自动、手动同步或用户测试；
- 已确认阶段：transport、identity、membership、facts、projection、originals；
- 起止时间、最后确认、结果码和可执行恢复；
- 页/事实/原件数量与预算；
- 脱敏诊断引用。

日志只保存在本机，不包含 bearer、邀请 secret、正文或原件字节。设备页提供
最近同步路径、筛选和“复制脱敏诊断”；历史记录有明确保留上限。

## 10. UI/UX 规则

### 10.1 全状态显影

所有影响用户判断、控制、承诺、权限或恢复的状态都必须有可访问、可追溯的
投影。隐私可以遮住内容，不能把状态、阶段、最后确认时间和恢复边界一起隐藏。

默认层回答“现在是什么、最后确认什么、是否需要我处理、能做什么”；
详情层回答“经过哪些阶段、谁是权威源”；诊断层提供脱敏、可复制、可定位的
技术材料。这个三层结构不要求所有细节常驻。

### 10.2 无悬置等待

任何等待、未知、拒绝、部分成功或错误必须至少提供：

- 重试同一动作；
- 换一条连接；
- 取消或离开而不停止后台合法工作；
- 重新扫描或重选对象；
- 查看详情；
- 复制脱敏诊断。

如果暂时没有可执行动作，必须说明阻塞者、原因边界和复测条件。单独 spinner、
无限闪烁、全局禁用且没有出口不合格。

### 10.3 沉浸不夺控制

强交互与沉浸感来自对象连续、直接操纵、真实反馈和可恢复控制。进入沉浸
布局后，当前状态、退出、取消、恢复和诊断仍可发现；减少动态效果、键盘、
触摸和辅助技术有等价路径。

## 11. Windows 任务栏身份

当前 Beta25 EXE 内含正确外心图标，窗口的小/大图标句柄也有效，但 Windows
任务栏按钮仍显示通用图标。首版修复按以下顺序验证：

1. 检查并设置稳定 AppUserModelID；
2. 确保 EXE、快捷方式和启动器使用同一应用身份；
3. 使用包含合适小/大尺寸的 `.ico`，不只借用一个 16px 窗口图标；
4. 在未固定、固定、重启和升级后分别验证任务栏与 Alt+Tab；
5. 图标缓存清理不能作为唯一修复，也不能删除用户快捷方式。

## 12. 实施分期

### Phase B0：契约与确定性缺陷

- 失败测试先覆盖回环排除、候选错误归因、主动扫描范围、自动复制和状态闭包；
- 修复 invitation 候选与最终错误；
- 增加统一状态面组件和脱敏诊断复制；
- 设备页增加显式刷新/扫描和无结果出口；
- 修正 Windows 任务栏应用身份。

### Phase B1：环境与连接持久层

- 增加 schema、迁移和兼容读取；
- 环境、连接、endpoint、邀请投递与同步日志的 Host API；
- 旧 route 数据迁移；
- 单测覆盖升级、回滚、上限、幂等和权限隔离。

### Phase B2：发现与连接管理 UI

- 扫描范围选择、主动扫描和批量结果；
- 环境卡、连接卡、双侧启停状态；
- 手动“测试连接”、明确的 refused/identity/protocol/membership 错误；
- 不再以自动探测替代用户主动测试。

### Phase B3：一键邀请

- InvitationProposal 投递、接受、拒绝、到期和重投；
- 无复制主路径；
- 自动复制兼容退路；
- 档案来源标识和加入后反馈。

### Phase B4：同步路径与诊断

- SyncAttempt；
- 使用连接和 endpoint 的完整路径；
- 连接失败自动换路及最后报告；
- 脱敏诊断复制和保留上限。

### Phase B5：候选与设备矩阵

- PC 双 Host、EasyTier 双实例、Android 模拟器；
- 物理平板重新接入后用新候选验证 fresh install；
- Wi-Fi/EasyTier 切换、双侧启停、拒绝、过期邀请、重启恢复、文字与原件；
- 只有设备条件满足后关闭物理设备项，不以模拟器代替全部真机结论。

## 13. 必测反例

1. 邀请包永远不含 loopback；其他候选全部不可达时显示 `unreachable`。
2. 一个错误地址命中另一外心实例时，报告该地址 identity mismatch，同时继续
   尝试其他候选，不让它覆盖更早或更晚的真实失败。
3. 无档案设备可发现环境并单向发出邀请，但不会读到对方档案清单。
4. 两端分别关闭连接，任一端关闭都不形成有效路径；远端状态未知时不伪造关闭。
5. 对端明确拒绝时本端显示 refused，网络超时显示 unknown/unreachable。
6. 手动测试只影响测试记录，不创建同步事实或角色；取消后无迟到 UI 状态。
7. 主动扫描有界、可取消、无结果时有下一步，不自动反复扫描全网。
8. 生成邀请自动复制成功/失败均有真实反馈。
9. 加入后能持续看到来源环境，不依赖当前进程内临时状态。
10. 私密状态脱敏后仍能看到阶段、时间和恢复边界。
11. 同步日志能指出实际使用的连接，失败时给出下一条可用路径或诊断。
12. Windows 任务栏在冷启动、固定、重启和升级后显示外心图标。

## 14. 与现有 Beta25 的关系

Beta25 是冻结候选，不在其二进制上重新定义位或覆盖证据。本设计进入新的功能
源码与 Beta26 候选链：

1. 失败回归与最小修复；
2. 环境/连接迁移及 UI；
3. 类型、Beta UI、Host/Native 和合同门禁；
4. 精确 Source CI；
5. 四/五平台构建；
6. PC、EasyTier、Android 模拟器与物理设备分层验收。

任何阶段未通过，不以下一阶段的设计完成或源码绿替代。
