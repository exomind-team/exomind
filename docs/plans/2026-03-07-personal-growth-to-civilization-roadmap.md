# ExoMind 路线图：从个人成长到文明操作系统

> **版本**: v1.1
> **创建时间**: 2026-03-07
> **状态**: 设计中
> **来源**: 一周实践回顾 + 文明方向讨论

---

## 一、背景与动机

ExoMind 有两个层次的定位：

1. **个人/集体的生命成长助手** — 帮助用户主动地掌控自己的生命过程
2. **认知生命科学原型** — 基于大模型 agent 的自主生命体

在 2026-03-07 的讨论中，浮现出第三个更宏大的方向：

3. **文明操作系统** — 用 ExoMind 作为工具，重构人类文明的信息流、物质流、价值流，实现人机共生的群体知识/群体精神世界

这三个层次不是并列的，而是递进的：个人成长 → 集体知识 → 文明基础设施。

## 1.5 认知操作系统子系统框架

### 设计原则：否决式定义

每个子系统都是**存活条件**，不是功能清单。少一个，系统就退化成更低级的东西。这与 ExoMind 的生命判据（否决式）同构。

### 个人层：最少 7+1 个子系统

| # | 子系统 | 定义 | 少了它会怎样 |
|---|--------|------|-------------|
| 1 | **Capture（捕获）** | 随时把经历、想法、输入抓进来 | 信息入口断裂，系统成为孤岛 |
| 2 | **Journal（生命日志）** | 保留时间序列事实，不让生活经验蒸发 | 无可追溯历史，无法复盘 |
| 3 | **Memory & Knowledge（记忆与知识）** | 把零散输入沉淀成可检索、可复用的结构 | 只有流水账，没有认知积累 |
| 4 | **Goals / Tasks / Commitments（目标/任务/承诺）** | 不只是知道，还要形成行动约束 | 有知识无行动，系统空转 |
| 5 | **Execution Interface（执行接口）** | 日历、任务、项目、工具调用，能把意图推到现实 | 无法连接物理世界 |
| 6 | **Review / Governor（复盘/抑制器）** | 纠偏、反思、克制、重新分配注意力 | 越做越忙但不更清醒 |
| 7 | **Energy / Homeostasis（能量/稳态）** | 睡眠、体力、情绪、节律 | 退化为高配效率工具，不是生命成长系统 |
| +1 | **Agent Runtime** | 持续观察、辅助分类、提醒、评议、调度 | 退化为纯手动系统 |

**一句话**：少了 #6 它不会纠偏；少了 #7 它不理解你是人；少了 #3 它只是日记本。

### 集体层：最少 8+1 个子系统

| # | 子系统 | 定义 | 少了它会怎样 |
|---|--------|------|-------------|
| 1 | **Boundary & Membership（边界与成员）** | 谁属于这个群体、角色、权限、共享范围 | 没有"群体"，只有混乱人群 |
| 2 | **Signal & Communication（信号与通信）** | 问题、任务、证据、反馈怎么流动 | 只是静态文档仓库 |
| 3 | **Collective Journal / Memory（集体日志/记忆）** | 可追溯历史：谁提了什么、何时改、为什么改 | 群体不会积累 |
| 4 | **Knowledge Production Model（知识生产模型）** | claim / evidence / source / version | 只是聊天和笔记，不是知识生产 |
| 5 | **Coordination & Tasking（协作编排与任务）** | 谁查什么、谁评什么、依赖关系 | 认知劳动无法组织 |
| 6 | **Epistemic Governance（认知治理）** | 评议、争议、置信度、升级到公共层的规则 | 退化成意见场 |
| 7 | **Publication / Intervention（发布/干预）** | 把群体成果变成条目、手册、课程、行动方案 | 不是操作系统，只是内循环 |
| 8 | **Reflection & Learning（复盘与学习）** | 群体看见自己哪里判断错了、流程哪里浪费了 | 不会演化 |
| +1 | **Agent Runtime** | 群体级 Agent 协调、跨节点调度 | 退化为纯人力协作 |

**一句话**：少了 #6 它退化成意见场；少了 #4 它只是聊天加文档；少了 #8 它不会成长。

### ExoMind 现状对照

> **状态口径（status semantics，状态语义）**
> - **已实现** = 代码/Agent/接口存在
> - **已验证** = 至少有一个真实链路可复现
> - **已验收** = 对应产品闭环通过明确验收标准
>
> 下文若写“跑通”，默认指**已验证**，不自动等于**已验收**。

### 关键盲区分析

**个人层最大盲区：Energy / Homeostasis（#7）**

没有它，系统不知道用户是疲惫还是亢奋，任何推荐都是盲的。最小实现不需要可穿戴设备：

- 开机时自报状态（能量 1-10、情绪标签）
- 时间块之间自动检测间隔（休息够了吗）
- 关机时记录睡眠意愿时间
- 这些数据进 EventLog，Growth Coach 做趋势分析

**个人层 #4 缺失：承诺语义**

TaskNode 只是任务，没有"承诺"这一层。承诺 = 对自己说了要做什么，有不可回滚性（对应生命判据"失败不可回滚"）。最小实现：Task 加 `commitment` 标志，标记为承诺的任务放弃时需要记录原因，且记录不可删除。

**集体层核心前提：#4 + #6**

知识生产模型（#4）和认知治理（#6）不是 Phase D 才考虑的“高级功能”，而是**双人协作一开始就要有的最小护栏**。不是做完所有 8 个才能启动集体层，而是至少有 #4 + #6 才不会退化。

## 三、文明操作系统愿景

### 3.1 核心洞察

传统知识平台的问题不只是访问壁垒，而是**知识生产资料的私有化**。ExoMind 的方向是：每个人的节点既是研究者，也是基础设施的一部分。没有中心服务器意味着没有"平台税"，没有审核垄断。

```
传统平台：    中心服务器 = 大脑，用户 = 终端
IPFS：       分布式存储，但无智能
ExoMind：    每个节点是一个"细胞"，集体构成知识生命体
             细胞自带 AI Agent = 既有存储也有算力也有判断力
```

### 3.2 三条流 + 知识

```
信息流    谁产生信息、谁路由信息、谁消费信息
          现在：平台控制（微信、谷歌决定你看什么）
          目标：节点自主路由（你的 Agent 帮你筛选）

物质流    谁生产、谁需要、怎么到达
          现在：供应链黑箱（你不知道你的食物从哪来）
          目标：透明可追溯（每个环节是一个节点的观察）

价值流    什么是有价值的、谁创造了价值、怎么回馈
          现在：货币抽象一切（平台抽租 30%）
          目标：贡献可见（你的观察帮助了谁，可追溯）

知识      贯穿以上三条流的理解和认知
          观察 → 主张 → 文章，分布式生产和评审
```

### 3.3 统一事件模型

三条流 + 知识，本质上都是**带溯源的事件在节点间流动**：

```
一条 EventLog 记录 = {
  who:      哪个节点（人+设备）
  what:     什么事件（观察/交易/评审/请求）
  when:     时间戳（不可篡改）
  evidence: 证据链（引用了哪些其他事件）
  flow:     属于哪条流（info/material/value/knowledge）
}
```

### 3.4 知识三层模型

```
         Article（文章层）    成熟研究，有完整论证，可被引用
            |
      AI Agent 辅助聚合
            |
         Claim（主张层）      可验证/可反驳的命题，附带证据链
            |
        积累 + 模式识别
            |
      Observation（观察层）   最低门槛："我看到了什么" = EventLog
```

### 3.5 与 ExoMind 生命判据的对齐

| 判据 | 在知识平台中的体现 |
|------|---|
| 可存活区间 | 节点的存储和算力有限，必须选择性同步 |
| 边界归因 | 每个人的研究归属明确，评审有署名，知识有溯源 |
| 过程性存在 | 知识不是快照，是持续演化的过程 |
| 失败不可回滚 | 发表了就发表了，EventLog 不可删除 |
| 环境裁决 | 网络带宽、存储容量是真实约束 |

### 3.6 与现有架构的对应

| ExoMind 已有 | 在文明系统中的角色 | 扩展方向 |
|---|---|---|
| ECS Mesh | 节点间的神经网络 | mDNS 局域网 → 公网 relay → DHT 发现 |
| SignalPool | 知识信号在节点间流动 | `research.published` / `review.submitted` 等新信号类型 |
| EventLog | 研究观察的不可变记录 | 带 node_id、可验证签名 |
| Reviewer Agent | 自动复盘 → 跨节点评审 | 收到别人的研究 → Agent 辅助评审 |
| EDS 数据同步 | 个人多设备同步 → 跨人知识同步 | 按兴趣/相关性选择性同步 |
| Auth + Pairing | PIN 配对和 per-peer token | 信任链传递 |

## 四、分阶段路线图

### Phase A: 个人成长闭环（最高优先级）

**目标**：自己用上，离不开，验证 30元/月 付费场景

**时间**：现在 → 2026-04

**前提**：SignalPool Phase 1-2 已完成；Reviewer 已有实现，但 `session.end -> review.completed` 收工闭环仍需在 Phase A 内补验收

#### 任务列表（按子系统框架排序）

| 任务 | 优先级 | 对应子系统 | 说明 | 预估工期 |
|------|--------|-----------|------|---------|
| A0: Reviewer 收工闭环补验收 | P0 | #6 Review/Governor | 补齐 `session.end -> review.completed` 真实链路 + UI 接收 + 7 天可用性验证 | 0.5-1 天 |

```
Phase A 完成后个人层覆盖度：

  #1 Capture           70% → 70%   （Phase B 补手机端）

  +1 Agent Runtime     95% → 95%   （已完成）

  整体：56% → 75%
```

#### 验收标准

- 连续 7 天使用完整闭环（开机→任务→时间块→反馈→复习→关机）
- 6 个验证问题中至少 4 个"是"
- 系统没有变成负担
- 每天至少有一次能量自评记录（#7 最小验证）

**6 个验证问题（直接内嵌，避免依赖外部文档）**

1. 我更少无谓点开了吗？
2. 我更快开始做事了吗？
3. 我更容易恢复上下文了吗？
4. 我开始复用下次方案 / 避免项了吗？
5. 我更清楚自己的状态 / 触发器 / 模式，并更快回到可行动了吗？
6. 我睡前更能放下，手机更可控了吗？

#### 关键约束

- 优先补完 Agent，而不是继续扩展基础设施
- 每个 Agent 做到"够用就发"，不追求完美
- Energy (#7) 不能推迟到"以后"——哪怕只是开机时一个 1-10 自评也比没有强

## 五、架构兼容约束（NOW 就要注意，但不强制一步到位）

在 Phase A 做个人成长时，优先采用**兼容字段（compat fields，兼容字段）**和命名约定，避免为了远景一次性推翻当前 schema。

| 设计决策 | 当前做法 | 不堵路的做法 | 成本差异 |
|---|---|---|---|
| EventLog ID | `evt-YYYYMMDD-NNN` | **保留现有 ID**，另预留 `source_node` / `logical_id` 兼容字段，不立刻切主键 | 低 |
| 事件格式 | 自由 JSON | 新事件优先加 `source_node` / `origin_host_id`，历史数据不强制回填 | 低 |
| Signal 类型命名 | 随意 | `domain.action` 命名空间 | 已在做 |
| 存储层 | PouchDB 直存 | 新文档/新事件预留 `content_hash` 可选字段，历史数据不回填 | 低 |
| Agent 反馈 | 本地渲染 | 新反馈事件带 `reviewer_node_id` 可选字段 | 低 |

**规则**：如果这里与具体实施计划或冻结后的架构文档冲突，以更具体、更新的 schema 文档为准。

## 六、核心原则

1. **先闭合，再扩展**：个人成长闭环没跑通之前，不启动集体功能
2. **先自己用，再给别人**：自己离不开了，才有资格推广
3. **引擎服务于体验**：基础设施是手段，用户感知的成长体验是目的
4. **愿景指导架构**：文明方向不急着做，但现在就影响设计决策
5. **生命判据贯穿全程**：每个阶段都要满足可存活区间、边界归因、过程性存在等判据
6. **否决式检查**：每个版本发布前，对照 7+1 子系统检查覆盖度，识别哪些子系统为零
7. **不跳层**：Energy/Homeostasis (#7) 不能推迟到"以后"，少了它就不是生命成长系统
