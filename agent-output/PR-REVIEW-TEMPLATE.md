# PR 审查模板

## ExoMind PR 审查清单

### 审查团队配置

| 角色 | 职责 | 审查重点 |
|------|------|----------|
| 安全审查员 | Security | 认证、加密、输入验证、依赖安全 |
| 性能审查员 | Performance | 算法复杂度、内存、缓存、网络 |
| 测试覆盖审查员 | Testing | 单元/集成测试、边界条件、覆盖率 |
| 架构合规审查员 | Architecture | 分层架构、接口设计、设计模式 |
| 代码质量审查员 | Code Quality | 类型安全、错误处理、可读性 |

## 安全审查清单 (Security Reviewer)

### 认证与授权

- [ ] 认证令牌安全生成（使用 CSPRNG）
- [ ] 无硬编码密钥/密码
- [ ] 密码哈希使用 PBKDF2/scrypt/bcrypt（至少 100k 迭代）
- [ ] WebSocket 连接有认证机制
- [ ] API 端点有权限检查

### 加密实现

- [ ] 使用安全的随机数生成器
- [ ] 加密算法使用标准库（非自定义实现）
- [ ] 无 ECB 模式或已知不安全的加密模式
- [ ] IV/Salt 每次加密唯一
- [ ] 密钥不在代码或日志中暴露

### 输入验证

- [ ] 所有用户输入验证
- [ ] SQL/NoSQL 注入防护
- [ ] XSS 防护（输出编码）
- [ ] 文件上传安全（类型、大小检查）

### 敏感数据

- [ ] 敏感数据不存储在日志
- [ ] HTTPS/TLS 传输加密
- [ ] 环境变量存储密钥（非代码）
- [ ] 本地存储不含敏感信息

### 依赖安全

- [ ] 无已知漏洞依赖
- [ ] 依赖版本非 latest

## 性能审查清单 (Performance Reviewer)

### 算法复杂度

- [ ] 无 O(n²) 或更差的循环嵌套
- [ ] 搜索/排序使用高效算法
- [ ] 大数据量场景有分页/流式处理

### 内存管理

- [ ] 无内存泄漏（定时器/监听器正确清理）
- [ ] 大对象及时释放
- [ ] 无全局变量累积

### 缓存策略

- [ ] 昂贵计算有缓存
- [ ] 缓存有失效策略
- [ ] 无缓存同时使用的竞态

### 网络请求

- [ ] 请求有超时设置
- [ ] 无不必要的重复请求
- [ ] 大数据传输使用流式处理
- [ ] WebSocket 有心跳/重连

### 数据库

- [ ] 查询有索引支持
- [ ] 无 N+1 查询问题
- [ ] 批量操作优于单个操作

## 审查员操作指南

### 开始审查

```bash
# 1. 获取 PR 信息
gh pr view <PR号> --json title,body,files,state

# 2. 下载变更
gh pr checkout <PR号>

# 3. 阅读变更
gh pr diff <PR号>
```

### 审查过程

1. **阅读 PR 描述** - 理解变更目的
2. **逐文件审查** - 按清单检查
3. **记录问题** - 按模板格式
4. **分级问题** - 阻塞/严重/建议
5. **撰写报告** - 按模板格式

### 审查输出

每个审查员需要输出：
1. 按维度填写的审查报告
2. 总体评级 (A/B/C/D/F)
3. 最终结论 (通过/需修复/拒绝)

### 时间要求

- **初审查**: 24 小时内完成
- **复审查**: 修复提交后 12 小时内完成
```
