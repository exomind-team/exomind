## 3. 架构设计问题（严重）

### 3.1 核心问题：违反本地优先原则

**当前设计**:
```
用户 → 选择设备 → 连接 WebSocket → 发送消息
         ↑
     必须选择设备才能聊天
```

**问题**: 用户必须先连接设备才能发送消息，这是**错误的设计**。

**期望设计**:
```
用户 → 本地记录消息 → 本地存储 → 联网后自动同步
         ↓
     本地随时可用，离线无忧
```

### 3.2 违反的设计原则

| 原则 | 当前实现 | 问题 |
|------|----------|------|
| **本地优先** | 必须在线才能使用 | 离线时完全无法记录 |
| **离线可用** | 无离线存储支持 | 网络断开 = 功能丧失 |
| **随时记录** | 需要先配对设备 | 增加不必要的操作步骤 |
| **延迟同步** | 实时连接要求 | 不符合移动端网络特性 |

### 3.3 正确的架构应该是

```
┌─────────────────────────────────────────────────────────────────────┐
│                        ExoMind 消息架构                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                   本地消息队列                           │   │
│   │  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐ │   │
│   │  │ 输入框   │→ │ 本地存储 │→ │ 待发送列│→ │ 发送成功│ │   │
│   │  └─────────┘  └─────────┘  └─────────┘  └─────────┘ │   │
│   └─────────────────────────────────────────────────────────┘   │
│                              │                                     │
│                              ▼                                     │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                   同步管理器                             │   │
│   │  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐ │   │
│   │  │ 检测网络 │→ │ 尝试同步 │→ │ 解决冲突 │→ │ 确认送达│ │   │
│   │  └─────────┘  └─────────┘  └─────────┘  └─────────┘ │   │
│   └─────────────────────────────────────────────────────────┘   │
│                              │                                     │
│                              ▼                                     │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                   远程同步层                            │   │
│   │              WebSocket / HTTP / 推送                     │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.4 用户体验对比

| 场景 | 当前设计 | 正确设计 |
|------|----------|----------|
| **离线时打开 App** | 显示"离线模式"，无法使用 | 正常记录消息 |

#### 7.2.2 本地优先的消息Store

```typescript
// src/lib/stores/message-store.ts

interface MessageState {
  messages: ChatMessage[];
  pendingMessages: ChatMessage[];  // 待同步的消息
  isOnline: boolean;
}

export const useMessageStore = create<MessageState>((set, get) => ({
  messages: [],
  pendingMessages: [],
  isOnline: false,

  // 核心方法: 随时可发送
  sendMessage: async (content: string) => {
    const { pendingMessages, isOnline } = get();

    // 1. 创建消息
    const message = createMessage(content);

    // 2. 立即添加到本地（乐观更新）
    if (isOnline) {
      set((state) => ({
        messages: [...state.messages, message],
      }));
    } else {
      // 3. 离线时加入待发送队列
      set((state) => ({
        pendingMessages: [...state.pendingMessages, message],
      }));
    }

    // 4. 尝试发送
    await trySendMessage(message);

    // 5. 监听网络恢复
    window.addEventListener('online', () => {
      syncPendingMessages();
    });
  },

  // 同步待发送消息
  syncPendingMessages: async () => {
    const { pendingMessages } = get();

    for (const msg of pendingMessages) {
      try {
        await trySendMessage(msg);
        // 同步成功，从待发送队列移除
        set((state) => ({
          pendingMessages: state.pendingMessages.filter((m) => m.id !== msg.id),
          messages: [...state.messages, msg],
        }));
      } catch (error) {
        // 重试逻辑
        console.error('Failed to sync:', error);
      }
    }
  },
}));
```
