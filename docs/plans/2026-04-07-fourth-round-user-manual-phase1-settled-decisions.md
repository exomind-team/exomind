## 2. 本轮新增已定决策

对应既有 issue：

- [#865](https://github.com/exomind-team/exomind/issues/865)

对应既有种子文档：

- [src/docs/user-guide.md](../../src/docs/user-guide.md)

### 2.1 真相源与交付表面

Phase 1 默认采用：

- **仓库文档真相源**
- 应用内不是第一阶段主承接面
- 网站属于应用外内容表面

进一步收口后，当前默认关系是：

- 仓库中的 canonical 内容为真相源
- 网站镜像 canonical 内容
- Phase 1 不要求先把手册接进应用内帮助系统

用户还专门纠偏了一次：

- 虽然一度去组织仓库里检查过 `exomind-ts`
- 但当前应以 **本仓库的 `website/`** 作为网站承接面
- 不把 `exomind-ts` 作为本轮 Phase 1 的默认落点

### 2.2 内容组织方式

Phase 1 默认采用：

- **按任务流组织**

也就是说，文档不是按底层模块写，也不是先按用户成长阶段写，而是围绕用户要完成的事展开。

### 2.3 覆盖策略

Phase 1 默认采用：

- **已验证能力优先**

但用户进一步补充：

- 可以写实验功能
- 前提是要显式标出“实验特性”或类似不稳定标记

因此本轮实际收口为：

- 稳定能力是主链
- 实验能力允许进入手册
- 但必须在对应段落或章节显式标记

### 2.4 多端差异处理

Phase 1 默认采用：

- **共通主路径 + 差异注记**

不采用：

- 一开始就拆 Web / Desktop / Android 三套手册
- 只围绕单一平台写完整手册

### 2.5 完成条件

`#865` 的 Phase 1 完成条件默认采用：

- **关键用户叙事可验收**

也就是说：

- 不是只要写出一篇完整可读长文就算完成
- 而是要覆盖若干关键用户叙事，并能逐条验收

### 2.6 canonical 内容层的数据形态

本轮关键收口：

- **结构化 Markdown**

含义是：

- 正文仍然写成 Markdown
- 但章节、步骤块、实验标记等需要保持稳定、可解析的结构
- 网站阅读面与 Agent 阅读面都从这层内容出发生成

不采用：

- 一开始就改成纯 JSON / YAML schema-first 内容库
- 也不满足于只有松散 Markdown 约定、没有明确结构

### 2.7 人类 / Agent 共读方式

第一阶段默认采用：

- **同一份正文内容**
- 不同渲染方式分别面向人类与 Agent

用户补充的更明确表述是：

- 类似“开发日报”“开发航线”的工作流
- 内容统一
- 人类读的是通过模板引擎生成的网页
- Agent 读的是通过渲染引擎整理出的文本
- 数据（正文）统一，只是呈现方式不同

### 2.8 网站镜像方式

本轮默认采用：

- 网站镜像 canonical 内容
- 并且优先复用现有官网模板

用户补充：

- 最好使用统一模板
- 外心官网处已有现成模板可参考 / 复用

但后续再次收口后，网站结构不是“手册页”和“教程页”两棵独立树，而是：

- **同一棵混合章节树**

### 2.9 语言策略

Phase 1 默认采用：

- **中文 canonical，英文后补**

不要求：

- 第一阶段同时维护完整中英双镜像

### 2.10 “用户手册”与“使用教程”的关系

本轮中途一度收口到：

- 同一条 issue 内承接“用户手册”和“使用教程”两种产物

但随后进一步收口为：

- **第一阶段先不做独立教程树**
- “快速上手”作为用户手册中的一部分
- 不单独做“教程”和“手册”两套并行章节类型

用户原话要点：

- “大概就是『用户手册』包括一个『快速上手』，先不做独立的教程”

因此本轮最终落点是：

- `#865` 仍是一条 issue
- 但 Phase 1 的网站与 canonical 结构不按“手册 / 教程”分为两套内容树
- 而是在同一混合章节树中，让“快速上手”承担教程性内容

### 2.11 网站信息架构

最终收口为：

- **`/docs` 下收成 5 个入口**

当前初步入口为：

1. 3 分钟上手
2. 核心概念
3. 场景教程
4. 常见问题 / 排障
5. 进阶

这条结论的重点是：

- 官网 `/docs` 最终不是继续堆成一篇长文
- 而是收成一组明确入口
- 这些入口共同构成一棵混合文档树

与上一轮问答合并后的含义是：

- 当前仍然不单独做一棵完全独立的“教程树”
- 但网站入口层面要显式区分：
  - 快速上手
  - 核心概念
  - 场景教程
  - FAQ / 排障
  - 进阶

### 2.12 章节类型表达

最终收口为：

- **不做章节类型标记**

也就是说当前不要求在 canonical 章节上显式打：

- handbook
- tutorial
- shared

用户明确补充：

- 教程先包含在手册里更合适

### 2.13 网站发布门禁

Phase 1 默认采用：

- **章节先验收，再上站**

用户还补了一条重要优先级判断：

- 当前以**内容上线**为 P0
- 自动化排版、自动同步等能力可以后置

因此本轮实际收口为：

- 内容与章节是否成立，优先于自动化工作流是否完整
- 网站不能先于 canonical 已验收内容漂移

### 2.14 canonical 源文件拓扑

Phase 1 默认采用：

- **按叙事分章**

也就是说：

- 不继续只维护一篇超长单文件
- 也不先拆成过细的小内容块系统
- 而是按任务流章节拆开，再由组织层和模板层拼出网站与 Agent 阅读面

### 2.15 Phase 1 最小章节骨架

当前默认骨架为：

1. 上手
2. 文本 / 语音记录
3. 时间块
4. 回顾
5. 排障

并且用户又进一步收口了章节内部语义：

- 上手：**打开即记录**
- 概念解释：揉进各章节，不单开大段“ExoMind 是什么”导论
- 语音：与文本同章双路径
- 时间块：先写开始 / 结束 + 简短回顾
- 排障：先覆盖记录 / 时间块 / 权限问题

### 2.16 概念导论处理方式

默认采用：

- **概念揉进各章节**

用户补充：

- “概念导论放最后即可，软件以『能上手』为主”

这意味着：

- 当前不应以抽象概念开场压住用户
- 先让人上手
- 抽象解释可后置或穿插
- 而网站入口层面仍可保留一个单独的“核心概念”入口，承接这些被抽出的概念内容

### 2.17 记录章节结构

最终采用：

- **文本 + 语音同章双路径**

并且本轮关键修正是：

- 语音不是附加体验
- 语音属于核心体验之一

用户原话：

- “与其他 APP 形成区别，语音是核心体验之一”

### 2.18 时间块章节深度

Phase 1 默认采用：

- **开始 / 结束 + 简短回顾**

不进一步纳入：

- 任务关联
- Agent 总结 / 提案

用户还补充了一个参考方向：

- 这部分可参考类似教程网站的结构
- 例如 `learn.shareai.run`

### 2.19 排障范围

Phase 1 的“排障”章节当前最少覆盖：

- 记录问题
- 时间块问题
- 权限问题

当前不把以下内容纳入 Phase 1 必选排障主章节：

- 安装 / 更新问题
- 同步 / 配对问题

同步 / 配对没有进入核心排障的直接原因也已经被用户明确指出：

- **当前多端同步还不稳定**

### 2.20 基础记录流的验收边界

本轮最终收口为：

- 基础记录流是 Phase 1 必验收主线
- 多端同步不进入当前最小关键叙事
- Agent / 提案 / AI 协作不进入当前最小关键叙事

## 3. 本轮调查中的纠偏结论

### 3.1 关于参考网站

用户提供了：

- `https://learn.shareai.run/`
- 以及其 GitHub 仓库：
  - `https://github.com/shareAI-lab/learn-claude-code`

本轮对其进行了只读核查，得到的主要用途不是“照搬其信息架构”，而是：

- 作为教程网站风格与内容-渲染分离思路的参考近邻

### 3.2 关于官网承接仓库

本轮一度去组织仓库中检查了：

- `exomind-team/exomind-ts`

它看起来像网站 / 网页入口近邻，但用户随后明确纠偏：

- “刚调查过了 GitHub，我们真正的官网只在 `website/` 这个地方”

因此当前应明确记为：

- `#865` Phase 1 的网站承接目标是**当前仓库的 `website/`**
- 不把 `exomind-ts` 视为本轮默认官网落点

### 3.3 关于跨仓追踪

用户新增了一个后续值得追踪的问题：

- “官网库还没独立出去”

这意味着未来可能需要单独追踪：

- 官网是否独立仓库化
- 内容源仓与官网承接仓的关系

但这不是本轮 `#865` Phase 1 的既定前提。

## 5. 当前可直接视为 `#865` Phase 1 的一句话定义

`#865` Phase 1 当前已收口为：

- **仓库中以任务流分章的结构化 Markdown 作为 canonical 内容层**
- **中文主链、稳定能力优先、实验能力显式标记**
- **网站通过现有 `website/` 模板镜像已验收章节**
- **官网 `/docs` 收成 5 个入口，而不是一篇长文**
- **手册是一棵混合文档树，其中既有“快速上手”，也有“核心概念”“场景教程”等入口，但不另立一棵完全独立的教程树**
- **核心主线围绕“打开即记录 → 文本/语音记录 → 时间块 → 回顾 → 排障”展开**
