一、提案系统 (Proposal System)

8 项 API 验收，端点 http://127.0.0.1:1949，按顺序执行
#1创建提案

在终端执行以下 curl 命令创建一条测试提案：

curl -X POST http://127.0.0.1:1949/api/proposals \ -H "Content-Type: application/json" \ -d '{ "title": "测试提案：整理会议记录", "body": "验收测试", "action_type": "create_task", "action_params": { "title": "整理会议记录", "tags": ["测试"] }, "references": [{ "ref_type": "event", "id": "evt-test", "display_text": "测试事件引用" }], "publisher": { "publisher_type": "agent", "id": "test-agent", "name": "验收测试Agent" } }'

期望：返回 JSON 包含 id 字段（如 "id": 1），status 为 "pending"，title/body/action_type/references/publisher 与请求一致

#2列表查询

查询所有提案列表：

curl http://127.0.0.1:1949/api/proposals

期望：返回 JSON 数组，包含上一步创建的提案（title 为"测试提案：整理会议记录"）

#3状态过滤

使用 status 查询参数过滤提案：

curl 'http://127.0.0.1:1949/api/proposals?status=pending'

期望：返回数组，所有提案的 status 均为 "pending"，包含第 1 步创建的提案

#4添加评论

对提案 ID=1 添加一条评论：

curl -X POST http://127.0.0.1:1949/api/proposals/1/comments \ -H "Content-Type: application/json" \ -d '{ "content": "审阅通过", "author": { "publisher_type": "human", "id": "reviewer", "name": "审阅者" } }'

期望：返回更新后的提案 JSON，comments 数组包含新评论，评论含 content="审阅通过" 和 author 信息

#5批准执行（创建任务）

将提案 ID=1 的状态改为 approved：

curl -X PATCH http://127.0.0.1:1949/api/proposals/1 \ -H "Content-Type: application/json" \ -d '{"status": "approved"}'

期望：返回提案 JSON，status 变为 "approved"。后台应自动触发 action_type="create_task" 的任务创建

#6验证任务创建

查询任务列表，确认提案批准后自动创建了对应任务：

curl http://127.0.0.1:1949/tasks | jq '.[] | select(.title == "整理会议记录")'

期望：返回 title 为"整理会议记录"的任务对象，tags 包含"测试"

#7验证 EventLog 记录

查询事件日志，确认提案批准操作被记录：

curl http://127.0.0.1:1949/eventlog | jq '.[] | select(.tags[] == "agent-action")'

期望：返回包含"提案已批准"相关描述的事件记录，tags 包含 "agent-action"

#8终态保护

尝试对已 approved 的提案再次修改状态为 rejected（应被拒绝）：

curl -X PATCH http://127.0.0.1:1949/api/proposals/1 \ -H "Content-Type: application/json" \ -d '{"status": "rejected"}'

期望：返回 HTTP 4xx 错误（如 400 或 409），响应体包含错误信息说明已处于终态的提案不可再更改状态

二、Agent API (Agent Sessions)

2 项 API 验收，需要 LLM API Key 配置
#9触发 Agent 会话

发起一个 Agent 会话请求：

curl -X POST http://127.0.0.1:1949/agent-sessions \ -H "Content-Type: application/json" \ -d '{ "prompt": "列出最近的事件日志", "tools": ["get_recent_events"] }'

期望：返回 JSON 包含 session_id 和 content 字段。
备注：如果未配置 LLM API Key，应返回明确的错误信息（如 401 或包含配置提示的错误 JSON），而非 500 崩溃

#10查询会话结果

使用上一步返回的 session_id 查询会话记录（将 {session_id} 替换为实际值）：

curl http://127.0.0.1:1949/agent-sessions/{session_id}

期望：返回该会话的完整记录 JSON，包含 prompt、tools、content 等字段

三、UI 验收

5 项 UI 交互验收，需要在浏览器中操作 ExoMind 界面
#11请求箱导航

1. 在浏览器打开 ExoMind UI（http://127.0.0.1:5173）
2. 在侧边栏找到"请求箱"图标并点击

期望：页面跳转到 /proposals 路由，显示请求箱/提案列表页面

#12通知徽章

1. 使用 curl 创建一条新的 pending 提案（参考第 1 项的命令，修改 title 以区分）
2. 回到浏览器刷新 ExoMind UI 页面
3. 观察侧边栏导航中"请求箱"图标附近

期望：导航栏的"请求箱"图标旁显示待处理数量徽章（badge），数字与 pending 状态的提案数量一致

#13提案详情

1. 进入请求箱页面（/proposals）
2. 点击列表中的某个提案条目

期望：展开或跳转到提案详情视图，包含以下区域：
- 提案标题和理由（body）
- 引用列表（references）
- 操作参数编辑区（action_params）
- 评论区（comments）
- 操作按钮（批准/拒绝）

#14引用跳转

1. 在提案详情中找到引用列表（references）
2. 点击引用链接（如"测试事件引用"）

期望：页面跳转到对应的事件/任务/时间块详情页面，URL 路由与引用类型匹配

#15批准操作

1. 用 curl 先创建一条新的 pending 提案（action_type 为 create_task）
2. 在 UI 的请求箱中打开该提案
3. 点击"批准执行"按钮

期望： - 提案状态在 UI 中变为 approved
- 对应的任务被自动创建（可通过 curl http://127.0.0.1:1949/tasks 验证）
- 按钮变为不可操作状态或消失
