# 2026-04-06 独立集体记账系统第一阶段计划

> 状态：已收口子计划
>
> 目的：把“集体记账 / Labor Ledger”从外心主线中拆出，明确第一阶段先做一个独立系统，再讨论如何并入外心。

---

## 1. 计划摘要

`集体记账 / Labor Ledger` 近期不作为外心内的数据域推进，而先收口为：

- 一个**独立配套系统**
- 目标是**快速承接旧有记账功能**
- 后续并回外心时，优先保住**领域事件模型 + 本地 API** 这层稳定边界

这意味着第一阶段不讨论它如何直接嵌进档案 / 集体档案 / 信号网络，而先把独立系统本身做出来。

---

## 2. 第一阶段定位

### 2.1 不是当前外心主线内的数据域

第一阶段中，记账系统的定位是：

- **外部配套系统**

而不是：

- 立即并入外心主线
- 立即作为集体档案中的一个内建对象域

### 2.2 先独立开发，再讨论接入

当前阶段的顺序固定为：

1. 先把计划边界收稳
2. 尽快以**独立仓库**启动实现
3. 再讨论如何纳入外心系统

---

后续再补：

---

## 5. 数据与架构策略

### 5.1 交付形态

第一版交付形态固定为：

- **Rust 内核 + 简 Web UI**

### 5.2 数据策略

为满足“先承接旧功能、同时又不把第一阶段绑死在外心主仓身份模型上”，数据策略收口为：

- **独立优先，规范内核**

具体解释：

- 不要求导入旧表历史数据
- 但要尽可能实现旧表的数据结构与运作逻辑
- 对外工作面尽量贴近参考系统
- 内核提前整理为更适合后续并入外心的 Rust 域模型
- 第一阶段**不预留 `archive / member` 身份语义**
- 第一阶段只要求最小读写与审计归因，不把外心身份体系强塞进独立系统

### 5.3 权威账本形态

第一阶段的权威数据模型收口为：

- **事件账本 + 投影**

即：

- 原始层使用追加友好的文本格式
- 当前默认方向是 `JSONL`
- 账单表 / 平账表 / 统计视图是投影层，不是权威源

### 5.4 存储与同步策略

第一阶段不采用本地 `SQLite` 作为主存储，而收口为：

- 使用**能承载表格信息的文本文件**
- 通过 **GitHub 集体私有仓库** 做同步

这里的 Git 同步产品地位进一步收口为：

- **当前独立系统的可替换传输层**

也就是说：

- 它是第一阶段默认 transport
- 但后续并回外心时，不把它当成必须保留的领域核心语义

进一步收口为：

- 权威事件文件按**年-月**分区
- Git 仓库默认只保存：
  - 权威事件层
  - 少量必要元数据
- 投影结果默认作为：
  - 本地派生缓存
  - 不写回权威 Git 仓库

### 5.5 Git 协作语义

第一阶段默认采用：

- **一集体一私有仓库**
- 成员各自持有本地克隆

冲突处理默认顺序为：

1. 自动拉取
2. 自动重放 / 重试
3. 仍失败时再提示人工处理

也就是说：

- 先自动解决同步碰撞
- 不把人工冲突处理设成常态主路径

### 5.5.1 代码归属

第一阶段默认采用：

- **计划稳定后尽快拆到独立仓库**

不采用：

- 长期把实现压在 ExoMind 主仓里再说
- 先做完整原型后再决定是否拆仓

### 5.6 改账语义

第一阶段默认规则为：

- **未平账可改**
- **已平账只允许冲正 / 补记**

不采用：

- 全程自由改写
- 首版全程纯追加但不给草稿修正空间

### 5.7 UI / Agent 双入口

第一阶段保留双入口方向：

- 人类可在 UI 录入
- Agent 也可通过 API 协助录入

但边界固定为：

- Agent 默认只创建**入账草稿**
- 正式入账仍需人类确认

### 5.8 最小 API 面

第一阶段最小 API 面收口为：

- 查分类
- 建记录 / 建草稿
- 查余额 / 待平关系
- 记平账

API 默认信任边界为：

- 本机 UI
- 本机受信 Agent / 脚本

不进入首版：

- 公网多租户 API
- 复杂远程鉴权

### 5.9 最低审计字段

每条记账 / 改账记录至少带：

- 操作者文本
- 设备
- 时间

这里的“操作者”第一阶段明确收口为：

- 最小可读文本归因

而不是：

- 稳定成员 ID
- `archive / member` 式正式身份模型

---

## 6. 当前明确不做的内容

第一阶段明确不做：

- 把记账系统直接并入外心主线
- 先讨论劳动记录理论细则再开始实现
- 导入旧表历史数据
- 一开始就补齐全部统计 / 看盘面板
- 公网多租户 API

## 8. 一句话总结

近期的集体记账主题不再按“外心内置账本”推进，而是按“**先做一个 Rust 内核 + 简 Web UI 的独立集体记账系统，尽快以独立仓库推进实现，并把领域事件模型 + 本地 API 作为后续并回外心时真正要保住的稳定边界**”来推进。
