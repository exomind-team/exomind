## 四、工作流程原则 ⭐

### 4.1 修改即提交原则 ⭐

**每次修改文件后立即提交 Git commit**

| 原则               | 说明                              |
| ------------------ | --------------------------------- |
| **触发时机** | 任何文件修改后立即提交            |
| **提交粒度** | 按文件/功能，小步提交             |
| **提交信息** | `[类型]: [简短描述] [修改文件]` |
| **分支**     | 在 PR 分支上提交，不影响主分支    |

**示例**：

```bash
# 修改一个文件后
git add pm/memory.md
git commit -m "DOCS: 添加修改即提交原则 [pm/memory.md]"

# 修改多个相关文件
git add pm/memory.md pm/agent.md
git commit -m "DOCS: 记录工作流程原则 [pm/memory.md, pm/agent.md]"
```

**为什么？**

1. Git 成为 Agent 的完整历史
2. 每次变更可追溯、可回滚
3. 便于 code review 和审计
4. 小的提交更容易理解和调试

### 4.2 双终端工作模式 ⭐

**一个对话终端 + 一个编码终端**

| 终端               | 用途                 | 特点                |
| ------------------ | -------------------- | ------------------- |
| **对话终端** | 对话、思考、想法执行 | 即时响应，想到就做  |
| **编码终端** | 专注代码开发         | Ralph Loop 迭代开发 |

**工作流程**：

```
对话终端 ←→ pm/logs/YYYY-MM-DD.jsonl（记录想法）
     ↓
编码终端读取日志 → 执行编码任务 → Git 提交
```

**核心原则**：

- 对话终端负责"想到"，即时记录
- 编码终端负责"做到"，专注执行
- 两个终端共享 memory 系统

## 六、使用指南

### 6.1 添加新轮次记忆

1. 在 `pm/memory/` 创建 `RoundXX-YYYYMMDD-主题.md`
2. 更新 `pm/memory/INDEX.md` 添加索引
3. 本文件 `pm/memory.md` 自动索引（无需修改）

### 6.2 读取记忆流程

```
Agent 启动时：
1. 读取 pm/agent.md（身份 + 启动流程）
2. 读取 pm/memory.md（快速索引 + 核心概念）
3. 读取 pm/memory/INDEX.md（轮次列表）
4. 按需读取 pm/memory/Round*.md（具体轮次记忆）
```

### 6.3 写入规则

| 时机       | 写入内容    | 文件位置                     |
| ---------- | ----------- | ---------------------------- |
| 每轮完成后 | 决策 + 经验 | `pm/memory/Round*.md`      |
| 关键决策   | 设计决策    | `pm/memory.md` 第四部分    |
| 对话记录   | JSONL 日志  | `pm/logs/YYYY-MM-DD.jsonl` |
