# ExoMind Architecture Principles

> 架构层必读。用于命名、抽象边界、文案语义、测试描述和评审判断。

## 使用方式

只要任务涉及以下任一内容，就先回读本文件：

- 命名系统约束、行为语义、方法名、字段名
- 设计或审查“删除 / 回滚 / 取消 / 放弃 / 提案 / 承诺 / 时间推进”等动作
- 编写会影响产品语义的测试描述、Issue 文案或 UI 文案

## 双层原则命名规范

ExoMind 的每一条系统级约束都必须具备**双层表述**，缺一不可：

| 层次 | 面向 | 措辞风格 | 适用场景 |
|------|------|---------|---------|
| **架构不变量（invariant）** | 开发者 / 架构师 | 强硬，描述硬约束 | 架构文档、代码注释、评审规则 |
| **用户行为语义（affordance）** | 用户 / 产品 | 柔性，描述操作含义 | UI 文案、Issue、测试描述、方法名 |

判断标准：若一个约束只有不变量名而没有行为语义名，说明设计未完成。

## 当前核心原则

| 不变量（invariant） | 行为语义（affordance） | 对实现的含义 |
|------|------|------|
| **不可删除原则** | **删除 = 放弃** | 优先把“删除”设计成可追溯的放弃或撤销语义，而不是无痕消失 |
| **不可回滚原则** | **操作生效 = 留下痕迹** | 成功发生的动作应可追踪、可解释，避免假装从未发生 |
| **持续展开原则** | **任务在时间中推进** | 对象不只是静态状态，还要表达时间中的推进、阻塞、恢复与续接 |
| **呈现独立原则** | **隐藏视图 = 只改变显示** | 计时、同步、传输及共享状态观察由数据/运行所有者管理；隐藏、折叠、切页、最小化不得停止其他控制面所需的状态与操作 |
| **全状态显影原则** | **发生着的事都能看见；私有内容可遮蔽，状态不可消失** | 任何影响用户判断、控制、承诺、隐私或恢复的状态转换必须有可访问、可追溯的投影；只有受保护的正文、secret、token、邀请密钥与原始字节可以被脱敏或隐藏 |
| **无悬置等待原则** | **等待有回应，出错有下一步** | 每个等待、未知、拒绝、部分成功或错误状态都必须提供真实接管路径，或可复制的可追溯脱敏诊断；暂无可执行动作时须说明阻塞者、原因边界与复测条件 |

### 状态、沉浸与恢复边界（2026-11-21 用户确认）

状态投影分为默认、详情与诊断三层：默认层回答对象是什么、最后确认什么、是否需要处理与能做什么；详情层解释阶段、权威源与未知边界；诊断层提供已脱敏、可复制的技术材料。聚合与渐进披露可以控制噪声，不能删除状态存在本身。

强交互和沉浸感来自对象连续、直接操纵、真实反馈与可恢复控制。专注、游戏式或强表现视图不得隐藏状态、退出、取消、恢复或诊断；动画结束不是业务提交、连接建立或同步完成的判据。

### 呈现与运行的边界（2026-11-18 用户确认）

视图是软件本体的控制与展示接口，不是业务生命期的所有者。浮窗状态只依赖底层数据与应用服务，不依赖主窗口的控制器、心跳、档案选择或文档存在。主窗口与浮窗是对等的数据客户端；明确在浮窗打开某档案才改变其对象。视图可停止其无用绘制、相对时间排版、不可见预览或纯标签查询；不能一起停止业务服务、持久化与其他窗口依赖的权威状态读取。关闭档案、撤销授权、退出程序等领域动作仍由明确的所有者按原合同收束，不能用本原则取消资源生命周期。

Beta12 曾把时间块刷新放在专注视图的可见性 effect 中，浮窗却依赖同一控制器的快照，导致隐藏专注后两秒内时钟过期并禁用浮窗。精确 EXE 隔离复现确认 Host 仍在计时、桥仍就绪，而浮窗拿到过期快照。仅把刷新搬进主窗控制器还不充分；Beta13 将执行与草稿仲裁放到 Native 应用服务，并移除生产装配里的主窗票据执行接口。回归分别覆盖 UI 显隐、独立 Native 执行、共享草稿比较更新和主文档离场。入口见 [Native 工作区](../development/beta-native-workspace.md)。

## 生命判据

系统设计遵循 5 条工程否决式生命判据：

| 判据 | 含义 |
|------|------|
| **可存活区间** | 任何主体都处于资源与能量约束中，跌出区间会导致过程退化或中断 |
| **边界归因** | 任何动作都必须可归因到明确边界与责任主体 |
| **过程性存在** | 生命不是静态实体，而是时间中持续展开的过程 |
| **失败不可回滚** | 错误和后果不会因为一句“撤销”就从历史中蒸发 |
| **环境裁决** | 真正的硬约束由环境执行，而不是由主体自行宣布豁免 |

## 设计提醒

1. 不要把产品语义直接坍缩成 CRUD 语义。
2. 不要把用户行为文案和底层不变量混成一套词。
3. 若一个实现需要“删除”“回滚”“重置”“撤销”，先问它到底对应哪条 invariant / affordance。
4. 若一段逻辑会改变用户对“承诺、痕迹、推进、放弃”的理解，必须在设计和测试里显式说明。
