### 历史 Pin 模型的评估

在 2026-04-14 的人写 EDS 原文中，`Pinned` 表示对象的**使用意义依赖某个 RT**。例如，进程句柄只在原 RT 上有用，会话的完整存档却可以随资料搬走，再在另一端重绑。文档还提出字段级 Pin 和 `UniquePinned`，并明确指出断连会打断唯一性交接。冻结计划进一步区分 Unpinned、Pinned-To-One-RT、Runtime-Only、Hybrid 和缺少本地依赖时的显式残缺态。Rust 所有权提供了“谁能执行”的思考方式，Rust `Pin` 类型本身并不保证跨机唯一或撤销。这是可继承的设计材料，落地从现有 Beta Core/Host 的合同出发。[人写定义及边界](<../architecture/【人写】2026-04-14 - EDS中数据的可同步性，对应的Pinned属性以及样例.md>) · [EDS 冻结分类](2026-04-14-EDS-architecture-freeze-plan.md#四数据分类法与-pin-模型) · [历史研究的未决点](../architecture/pinned-unpinned-academic-analysis.md)

| 数据 | 可移植语义与实际持有 | β28 应落实的控制 |
|---|---|---|
| 已提交事件、时间块、默认自名 | 有权副本可复制共同含义，事件身份跨端稳定 | 各来源幂等接纳，默认自名可同步，本机特殊备注独立保留 |
| 原件与复本 | 文件内容可移植，实际字节按每端资格、长度、hash 和保留状态独立成立。消息已到但当前端缺图属于显式部分可用 | 将自动取件、大小/网络条件、持有端选择、离线保留、释放前证据设为独立策略；先保留这些可配置能力，通过实际设备场景收束推荐值。TLS pin 另指身份校验 |
| 草稿、私有路径、系统句柄 | 提交前内容归本地工作区，工作目录与系统能力绑定其 RT，进程句柄属运行期 | 可恢复草稿与档案往返分别验收。只传递可公开的引用或运行状态，重绑前重验能力 |
| Agent 授权 | 默认锚定签发 RT，私密材料默认留在本地。未来可以授权流转或公用，须为接受方建立可验证的新绑定／委托，记录用途、有效范围、撤销传播及离线未知 | 先验证本地唯一 RT、持久引用、最小用途与明确回执。多设备多 Agent 的委托是扩展研究，不把活凭据装进普通 Git/档案包。隔离依能力分配和持钥者建立 |

建议沿用 Pin 作语义分类，再把“哪端应保留几份”作为独立配置，把“此刻实际有哪些合格字节”作为可查询事实。这样文件可以搬走而本地路径仍归原 RT，设备备注可以留本端而档案身份仍可同步。唯一执行权遇到冲突应停在可辨认状态，不从副本数量推断权威。

## Agent 值守和授权基础设施

值守 Skill 负责冷启动自动取得授权引用、发现受信任 RT、有限重试、续页和去重提醒。外心 Host 负责当前 P/角色/能力及撤销执法，Core 负责本机提交结果。许可绑定稳定 RT 身份，endpoint/PID/runtime 代次只参与本次路由。普通 Agent 会话与定时运行共用状态语义；多台设备接入多个 Agent 时，按受信任 OS 主体、签发 RT、P、角色、用途及能力上限隔离。未来默认 pin 的授权可显式流转／委托，单独检验安全交接与撤销，受控的 Agent grant 和 peer membership 各自验权。**A15、A19**。[既有协议及存储研究](2026-11-25-beta28-architecture-decisions.md#9-agent-授权与外心访问的连续性)
