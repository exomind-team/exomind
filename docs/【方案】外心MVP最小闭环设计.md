## 1. 核心问题定位

### 1.1 当前困境

```
┌─────────────────────────────────────────────────────────────┐
│  问题：外心系统只有模板，没有信息通道                         │
├─────────────────────────────────────────────────────────────┤
│  模板层 ✅                                                   │
│  ├── 开机仪式（已完成，可执行）                              │
│  ├── 关机仪式（模板存在，未执行）                            │
│  ├── 任务管理（已完成）                                      │
│  ├── 周规划（已完成）                                        │
│  ├── 日记系统（已完成）                                      │
│  └── 小荷 Agent（已完成）                                    │
├─────────────────────────────────────────────────────────────┤
│  信息通道 ❌                                                 │
│  ├── 手机信息 → 电脑（无通道）                               │
│  ├── 语音输入 → 处理（无通道）                               │
│  ├── 图像处理 → 记账（无通道）                               │
│  └── 对话 → 任务（已有，但未正式定义）                       │
└─────────────────────────────────────────────────────────────┘
```

**关键洞察**：对话本身就是信息流，Happy Coder 是第一个信息入口。

### 1.2 MVP 目标

```
最小闭环 = 能跑通一个"观察→判断→执行→反馈"循环
├── 观察：获取外部信息（语音/图像/文字）
├── 判断：理解信息意图（任务/记账/聊天）
├── 执行：调用对应 Agent 处理
└── 反馈：返回结果给用户
```

### 2.2 移动端策略（关键决策）

**决策**：不做 Tasker，直接做轻量 Android APP

| 方案 | 问题 | 选择 |
|------|------|------|
| Termux + Claude | 需要 root，需要安装，不通用 | ❌ |
| Tasker | 需要学习配置，用户体验差 | ❌ |
| 轻量 APP | 需要开发，但简单、统一 | ✅ **直接做** |

**轻量 APP 设计原则**：
- 不依赖 Termux，面向普通 Android 用户
- 简单 UI：拍照、录音、文字输入三个按钮
- HTTP 客户端负责发送，不做复杂逻辑

## 3. 场景设计

### 3.1 场景一：语音/文字任务输入

```
流程：手机语音 → Tasker → HTTP(:2601) → 意图识别 → Agent 执行

示例对话：
用户（手机）: "整理 human 目录"
     ↓
Tasker 发送: {"type": "voice", "content": "整理 human 目录", "source": "mobile"}
     ↓
消息路由器 → 意图识别 → 任务类型
     ↓
调用任务规划师 Agent → 生成任务建议 → 更新 now.md
     ↓
返回: "已创建任务 T-2026-01-xxx，建议今天完成"
```

### 3.2 场景二：拍照记账

```
流程：手机拍照 → 发送图片路径 → 桌面 OCR → 财务 Agent 记账

┌─────────────────────────────────────────────────────────────┐
│  手机端（轻量）                                             │
│  ├── 拍照 / 选择图片                                        │
│  ├── 可选：本地 OCR（Google ML Kit）                        │
│  └── 发送：图片 Base64 / 路径 + 金额（用户输入）            │
├─────────────────────────────────────────────────────────────┤
│  桌面端（重量）                                             │
│  ├── 接收图片                                               │
│  ├── 调用云端 OCR API（阿里/腾讯/Google）                   │
│  ├── 识别金额/商家/品类                                     │
│  ├── 调用财务 Agent 记账                                    │
│  └── 返回结果                                               │
└─────────────────────────────────────────────────────────────┘
```

**关键设计决策**：
- 图像识别用云端 API（手机算力有限）
- 金额可能需要用户确认（OCR 不是 100% 准确）
- 记账联动财务 Agent，自动分类

### 3.3 场景三：日常聊天/灵感

```
流程：手机文字 → Tasker → HTTP → 小荷 Agent → 返回

这是最简单的场景，也是信息量最大的场景
小荷 Agent 可以直接处理，无需路由
```

## 4. MCP 验收接口

`★ Insight ─────────────────────────────────────`
**为什么需要 MCP 服务器作为验收接口？**
- 文件操作是"破坏性"的，接口可以验证、审计、幂等
- MCP 是标准化协议，后续换平台不用改逻辑
- 验收流程本身也是一种"信息流"，需要被记录和追踪
- Agent 不能直接改任务状态，需要人确认后才能生效
`─────────────────────────────────────────────────`

### 4.1 验收流程设计

```
┌─────────────────────────────────────────────────────────────┐
│  任务验收闭环                                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 任务创建（Agent）                                        │
│     Agent → MCP: create_task(description)                   │
│     MCP → 返回: task_id (状态: pending)                     │
│                                                             │
│  2. 任务执行（人）                                           │
│     人 → 完成任务 → 标记"待验收"                            │
│                                                             │
│  3. 任务验收（人）                                           │
│     人 → APP/MCP → confirm_task(task_id)                    │
│     MCP → 验证 → 更新状态: completed                        │
│     MCP → 触发: 任务完成事件 → 更新 now.md                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 MCP 接口定义

```typescript
// MCP 工具定义（简化版）
interface ExoMindMCP {
  // 任务相关
  create_task(description: string): { task_id: string; status: 'pending' }
  confirm_task(task_id: string): { status: 'completed' }

  // 记账相关
  create_expense(amount: number, category: string, image?: string): { expense_id: string }
  confirm_expense(expense_id: string): { status: 'recorded' }

  // 日记相关
  append_diary(content: string, context?: string): { entry_id: string }
}
```

### 4.3 验收状态机

```
┌─────────────────────────────────────────────────────────────┐
│  任务状态流转                                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  draft → pending → in_progress → pending_review → completed│
│            ↑                              |                  │
│            └──────────────────────────────┘                  │
│                       (拒绝验收)                             │
│                                                             │
│  pending:    任务已创建，等待开始                            │
│  in_progress: 任务执行中                                     │
│  pending_review: 待验收（人完成任务后手动标记）              │
│  completed:  已验收（人确认后自动更新）                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 6. 关机仪式设计

`★ Insight ─────────────────────────────────────`
**为什么先设计"关机仪式"？**
- 开机是"开始"，关机是"沉淀"——没有沉淀的循环是无效的
- 5分钟关机 = 今日回顾 + 一句话复盘 + 明日准备
- 关键是"自动化"：尽量让系统自动生成内容，人只做确认
`─────────────────────────────────────────────────`

### 5.1 最小关机仪式（5分钟）

```
┌─────────────────────────────────────────────────────────────┐
│  关机仪式流程（5分钟）                                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  步骤 1: 今日回顾（1分钟）                                  │
│  ├── 系统自动统计：完成任务数、时间消耗                     │
│  ├── 读取 now.md 完成状态                                   │
│  └── 用户确认/补充                                          │
│                                                             │
│  步骤 2: 一句话复盘（2分钟）                                │
│  ├── 系统生成：今日最有成就感的事                           │
│  ├── 系统生成：今日最大收获                                 │
│  ├── 用户确认/修改                                          │
│  └── 用户补充一句话感悟                                      │
│                                                             │
│  步骤 3: 明日准备（2分钟）                                  │
│  ├── 系统建议：明天的核心任务（来自 weekly.md）             │
│  ├── 用户确认/调整                                          │
│  └── 生成明日启动清单                                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

明日准备自动生成：

### 8.1 MVP 输入服务代码框架

```javascript
// mvp-input-server.js
const express = require('express');
const app = express();
const PORT = 2601;

app.use(express.json());

// 消息路由器
const router = {
  'task': routeToAgent('任务规划师'),
  'chat': routeToAgent('小荷'),
  'expense': routeToAgent('财务'),
  'default': routeToAgent('小荷')
};

// MCP 验收接口
app.post('/mcp/confirm_task', async (req, res) => {
  const { task_id } = req.body;
  // 验证 → 更新状态 → 触发事件
  await updateTaskStatus(task_id, 'completed');
  await triggerEvent('task_completed', { task_id });
  res.json({ status: 'ok' });
});

app.post('/capture', async (req, res) => {
  const { type, content, source } = req.body;
  console.log(`📥 [${source}] ${type}: ${content}`);

  const agent = router[type] || router['default'];
  const result = await callAgent(agent, content);

  res.json({ status: 'ok', response: result });
});

app.listen(PORT, () => {
  console.log(`🚀 外心 MVP 输入服务 :${PORT}`);
});
```
