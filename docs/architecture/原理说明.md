# ExoMind v4.0 架构原理

> 基于大模型 Agent 的认知生命科学原型

## 1. 架构全景

### 1.1 分层模型

ExoMind 采用 **四层自底向上** 的分层架构：

```
┌─────────────────────────────────────────────────────────────────┐
│                        L4 UI                                    │
│              React + zustand（只调 Service）                    │
├─────────────────────────────────────────────────────────────────┤
│                          │                                      │
│                  Service Interface                              │
│                      (L3 定义)                                  │
├─────────────────────────────────────────────────────────────────┤
│                        L3                                       │
│            Service / Actor / Agent（业务逻辑层）                  │
├─────────────────────────────────────────────────────────────────┤
│                          │                                      │
│                  ActorContext Interface                          │
│                      (L3 定义)                                  │
├─────────────────────────────────────────────────────────────────┤
│                        L2                                       │
│                    Environment                                  │
│              （共享物理世界）                                    │
│    · 持有 Port 实例（能力）                                     │
│    · 管理资源池（周期刷新 + 总额有限）                           │
│    · 消息缓冲（短期记忆）                                        │
│    · 独占资源管理                                               │
├─────────────────────────────────────────────────────────────────┤
│                          │                                      │
│                     Port Interface                               │
│                      (L2 定义)                                  │
├─────────────────────────────────────────────────────────────────┤
│                        L1                                       │
│                      Adapter                                    │
│              （具体实现，按运行时替换）                           │
│      Web: IndexedDB, fetch, Web Speech                          │
│      Tauri: SQLite, Rust HTTP, Native Shell                     │
└─────────────────────────────────────────────────────────────────┘
```

**核心洞察**：每一层都是**运行时实体**，不只是静态代码组织。

### 1.2 为什么这样分层？

传统 MVC 或三层架构的痛点：
- UI 直接依赖数据层，测试困难
- 更换实现（如从 HTTP 切换到 WebSocket）需要改大量代码
- 业务逻辑和基础设施紧耦合

ExoMind 的解法：
- **L1/L2 变化频繁**（今天用 OpenAI，明天可能用 Claude）
- **L3/L4 相对稳定**（业务逻辑、UI 不常变）
- **接口归稳定方所有**：谁变化少，谁定义接口

## 2. 核心概念

### 2.1 Port - 能力的抽象

**Port** 是对「外部能力」的抽象接口。

```
┌─────────────────────────────────────────────────────────────────┐
│  Port = 能力契约                                                  │
│  ─────────────────                                                │
│  1. 定义「能做什么」                                               │
│  2. 不关心「谁来做」「怎么做」                                    │
│  3. L2 定义，L1 实现                                             │
└─────────────────────────────────────────────────────────────────┘
```

**类比**：Port 就像电脑的 USB 接口
- 你不需要关心插入的是鼠标、键盘还是 U 盘
- 电脑只知道「这是 USB 设备，能传输数据」
- 更换设备时，电脑不用重启

### 2.2 Adapter - 具体实现

**Adapter** 是 Port 的具体实现，一个 Port 可以有多个 Adapter：

```
┌─────────────────────────────────────────────────────────────────┐
│                    IASRPort（语音识别接口）                       │
├─────────────────────┬─────────────────────┬───────────────────┤
│  MOSSASRAdapter     │  HTTPASRAdapter     │  WebSpeechAdapter  │
│  (MOSS 云服务)      │  (火山引擎 HTTP)     │  (浏览器原生)      │
│                     │                      │                    │
│  ✓ 准确率高        │  ✓ 稳定              │  ✓ 无需配置        │
│  ✗ 需要 API Key    │  ✗ 需要后端         │  ✗ 识别率较低      │
└─────────────────────┴─────────────────────┴───────────────────┘
```

### 2.3 Service - 业务逻辑封装

**Service** 组合多个 Port，完成具体的业务场景：

```
┌─────────────────────────────────────────────────────────────────┐
│                 VoiceChatService（语音聊天服务）                  │
├─────────────────────────────────────────────────────────────────┤
│  职责：                                                         │
│  · 协调 ASR（语音识别）和 LLM（大模型）                           │
│  · 管理录音状态（开始/停止/计时）                                 │
│  · 适配器选择（自动降级）                                         │
│                                                                  │
│  使用者：L4 UI（只调用 Service，不直接调 Adapter）               │
└─────────────────────────────────────────────────────────────────┘
```

### 2.4 Environment - 共享上下文

**Environment** 是「共享的物理世界」：

```
┌─────────────────────────────────────────────────────────────────┐
│                    ExoMindEnvironment                            │
├─────────────────────────────────────────────────────────────────┤
│  ┌───────────────────────────────────────────────────────────┐  │
│  │ Ports（持有实例）                                          │  │
│  │  - asr: IASRPort        → MOSSASRAdapter 实例            │  │
│  │  - storage: IStoragePort → WebStorageAdapter 实例        │  │
│  │  - llm: ILLMPort        → （待实现）                     │  │
│  │  - crypto: ICryptoPort   → CryptoAdapter 实例            │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │ 资源池（管理）                                             │  │
│  │  · 周期刷新型：API 限额（每5小时刷新）                     │  │
│  │  · 总额有限型：预付费余额（用完即止）                      │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │ 消息缓冲（短期记忆）                                       │  │
│  │  · 最近 5 分钟 或 500 条消息                              │  │
│  │  · 自动淘汰旧消息                                         │  │
│  └───────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 数据流转

### 3.1 典型流程：语音识别

```
用户 ──────────────────────────────────────────────────────────────
      │
      ▼
┌─────────────────────────────────────────────────────────────────┐
│ L4 VoiceInputButton（UI 组件）                                   │
│  · 渲染录音按钮                                                 │
│  · 显示录音状态                                                  │
│      │                                                         │
│      │ 调用 getVoiceChatService().startRecording()             │
│      ▼                                                         │
┌─────────────────────────────────────────────────────────────────┐
│ L3 VoiceChatService                                              │
│  · 检查适配器可用性（优先 MOSS，其次 HTTP）                      │
│  · 管理录音计时器                                                │
│      │                                                         │
│      │ env.asr.transcribe({ stream, lang: 'zh-CN' })          │
│      ▼                                                         │
┌─────────────────────────────────────────────────────────────────┐
│ L2 Environment                                                   │
│  · 持有 asr Port 实例                                           │
│  · 记录资源使用量                                                │
│      │                                                         │
│      │ delegate to this.asr                                    │
│      ▼                                                         │
┌─────────────────────────────────────────────────────────────────┐
│ L1 MOSSASRAdapter（或其他 Adapter）                             │
│  · 录制音频 → WAV 格式                                          │
│  · 调用 MOSS HTTP API                                           │
│  · 返回识别结果                                                  │
└─────────────────────────────────────────────────────────────────┘
      │                                                         │
      ▼ （反向）                                                  │
┌─────────────────────────────────────────────────────────────────┐
│ L3 Service → L4 UI                                              │
│  · 更新 lastResult 状态                                        │
│  · 触发 UI 重新渲染                                             │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 代码示例：完整的调用链

**Step 1: 定义 Port（接口在 L2）**

```typescript
// src/lib/environment/interfaces/asr.port.ts
export interface IASRPort {
  transcribe(input: { lang?: string; stream?: MediaStream }): Promise<ASRResult>;
  streamTranscribe?(input: ASRInput): AsyncIterable<ASRPartialResult>;
  isAvailable(): boolean;
}
```

**Step 2: 实现 Adapter（实现 Port 在 L1）**

```typescript
// src/lib/adapters/asr/moss-asr.ts
export class MOSSASRAdapter implements IASRPort {
  async transcribe(input: MOSSASRInput): Promise<MOSSASRResult> {
    // 1. 录制音频
    const audioData = await this.recordAudio(input.stream);
    // 2. 转换为 Base64
    const base64Audio = this.arrayBufferToBase64(audioData);
    // 3. 调用 MOSS API
    const response = await fetch(this.config.apiUrl!, { /* ... */ });
    // 4. 返回结果
    return this.parseMOSSResult(await response.json());
  }

  isAvailable(): boolean {
    return !!this.config.apiKey;  // 需要 API Key 才可用
  }
}
```

**Step 3: Service 组合 Port（业务逻辑在 L3）**

```typescript
// src/lib/services/voice-chat.service.ts
export class VoiceChatService implements IVoiceChatService {
  // 依赖注入（通过 Environment 获取 Port）
  private env = ExoMindEnvironment.getInstance();

  async startRecording(): Promise<void> {
    if (!this.env.asr.isAvailable()) {
      throw new Error('语音识别不可用');
    }

    // 获取麦克风权限
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true });

    // 调用 Port
    const result = await this.env.asr.transcribe({
      stream,
      lang: 'zh-CN'
    });

    // 更新状态
    this.lastResult = result;
    this.isRecording = true;
  }
}
```

**Step 4: UI 调用 Service（L4）**

```typescript
// src/components/VoiceInputButton.tsx
export function VoiceInputButton() {
  const service = getVoiceChatService();

  const handleClick = async () => {
    if (service.isRecording) {
      await service.stopRecording();
    } else {
      await service.startRecording();
    }
  };

  return (
    <Button onClick={handleClick}>
      {service.isRecording ? '停止' : '开始录音'}
    </Button>
  );
}
```

### 3.3 运行时适配：自动选择最佳 Adapter

```typescript
// VoiceChatService 中的适配器选择逻辑
private async checkAvailability(): Promise<void> {
  // 1. 优先使用 MOSS（最简单，无需后端）
  if (this.mossAdapter.isAvailable()) {
    this.adapterType = 'moss';
    console.log('[VoiceChatService] 使用 MOSS Adapter');
    return;
  }

  // 2. 其次 HTTP Adapter（通过 Bun 后端）
  if (await this.httpAdapter.isAvailable()) {
    this.adapterType = 'http';
    console.log('[VoiceChatService] 使用 HTTP Adapter');
    return;
  }

  // 3. 最后 WebSocket（可能不稳定）
  if (this.wsAdapter.isAvailable()) {
    this.adapterType = 'websocket';
    console.log('[VoiceChatService] 使用 WebSocket Adapter');
    return;
  }

  // 4. 全部不可用
  this.isAvailable = false;
}
```

## 4. 接口归属规则

### 4.1 三条核心规则

| 接缝 | 接口放在 | 原则 | 本质 |
|------|----------|------|------|
| L1 ↔ L2 | Port interface 放 L2 | 谁消费谁定义 | 类型契约 |
| L2 ↔ L3 | ActorContext 放 L3 | 谁消费谁定义 | 权限边界 |
| L3 ↔ L4 | Service interface 放 L3 | 谁提供谁定义 | API 暴露 |

### 4.2 为什么这样设计？

**Port interface 放 L2（消费方）**
- L2（Environment）持有 Port，是 Port 的消费者
- 消费者最清楚自己需要什么能力
- 实现方（L1 Adapter）只需要满足接口契约

```typescript
// ✅ 正确：接口放在 L2，由消费者定义
// src/lib/environment/interfaces/asr.port.ts
export interface IASRPort {
  transcribe(input: ASRInput): Promise<ASRResult>;
}

// L1 Adapter 实现接口
export class MOSSASRAdapter implements IASRPort { /* ... */ }
```

**Service interface 放 L3（提供方）**
- L3 Service 是能力的提供者
- 提供者最清楚暴露什么 API
- 调用方（L4 UI）只需要知道接口

```typescript
// ✅ 正确：接口放在 L3，由提供者定义
// src/lib/services/voice-chat.service.ts
export interface IVoiceChatService {
  isRecording: boolean;
  startRecording(): Promise<void>;
  stopRecording(): Promise<ASRResult | null>;
}

// L4 UI 使用接口
function VoiceInputButton({ service }: { service: IVoiceChatService }) {
  // 只依赖接口，不依赖具体实现
}
```

## 5. 与传统架构的对比

| 维度 | 传统 MVC | ExoMind v4.0 |
|------|----------|--------------|
| 依赖方向 | UI → Model → DB | L4 → L3 → L2 → L1 |
| 测试 | 需要 mock 数据库 | L3 可独立测试 |
| 更换实现 | 改大量代码 | 替换 Adapter 即可 |
| 可观测性 | 日志分散 | 统一的 Environment 资源管理 |
| 跨平台 | 条件编译 | 运行时 Adapter 替换 |

### 类比理解

```
┌─────────────────────────────────────────────────────────────────┐
│                    传统架构（紧耦合）                             │
│                                                                 │
│  UI ──────────→ Controller ──────────→ Model ──────────→ DB  │
│                                                                 │
│  问题：如果要换数据库，Model 层要重写，Controller 也可能受影响    │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                    ExoMind（松耦合）                             │
│                                                                 │
│  UI ──────────→ Service ─────┐                               │
│                              Port│                               │
│                                 ↓                                │
│  Adapter₁ ───┐                 Environment                      │
│  Adapter₂ ───┼──── Port 实例                                        │
│  Adapter₃ ───┘                                                    │
│                                                                 │
│  优点：换 Adapter 不影响 Service，换 Service 不影响 UI          │
└─────────────────────────────────────────────────────────────────┘
```

## 6. 扩展能力

### 6.1 添加新的 Port

1. 在 `src/environment/interfaces/` 定义接口
2. 在 `src/adapters/` 实现 Adapter
3. 在 `src/environment/environment.ts` 注册实例

```typescript
// 1. 定义接口
export interface IWebSearchPort {
  search(query: string): Promise<SearchResult[]>;
}

// 2. 实现 Adapter
export class GoogleSearchAdapter implements IWebSearchPort {
  async search(query: string): Promise<SearchResult[]> {
    // 调用 Google API
  }
}

// 3. 注册到 Environment
export class ExoMindEnvironment implements Environment {
  webSearch: IWebSearchPort;

  constructor() {
    this.webSearch = new GoogleSearchAdapter();
  }
}
```

### 6.2 切换运行时环境

```typescript
// bootstrap.ts - 根据环境选择 Adapter
export function createEnvironment(): Environment {
  if (isBrowser()) {
    return new BrowserEnvironment();  // 使用 WebStorageAdapter
  }

  if (isTauri()) {
    return new TauriEnvironment();    // 使用 SQLiteAdapter
  }

  if (isNode()) {
    return new NodeEnvironment();      // 使用 FileSystemAdapter
  }
}
```

## 7. 演进路线

| Phase | 目标 | 关键变化 |
|-------|------|----------|
| Phase 1 | 语音输入 → LLM → 事件日志 | Port 层、直接调用链 |
| Phase 2 | 解耦 Service 依赖 | EventBus 发布订阅 |
| Phase 3 | 资源管控 + 可观测性 | 资源池、消息缓冲 |
| Phase 4 | 多 Agent 并发协作 | Actor Model、Supervisor |
| Phase 5 | 高级生命特性 | Agent 生命周期，沙箱脚本 |

## 8. 总结

**v4.0 架构的核心价值**：

1. **可测试**：Service 可以脱离 UI 测试，Adapter 可以 mock
2. **可替换**：更换 LLM 提供商、存储方式，无需改业务代码
3. **可观测**：Environment 统一管理资源，资源使用一目了然
4. **可演进**：Phase 1 → Phase 5 渐进式增强，架构不僵化

**记住三个原则**：

- 接口归**稳定**的一方所有
- 每一层都是**运行时**实体
- 依赖**倒置**（高层不依赖低层，依赖抽象）
