# 评审流程规范

> 用于规范化执行文档/代码评审工作流

## 流程图

```
┌─────────────────────────────────────────────────────────────────────┐
│                     Review 流程规范                                  │
└─────────────────────────────────────────────────────────────────────┘

┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   输入阶段    │ ──→ │   评审阶段    │ ──→ │   输出阶段    │
└──────────────┘     └──────────────┘     └──────────────┘
       │                    │                    │
       ▼                    ▼                    ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 收集待评审文件 │     │ SubAgent 并行 │     │ 汇总问题报告  │
│ 确定评审维度   │     │ 执行 4 维评审 │     │ 生成 REVIEW   │
└──────────────┘     └──────────────┘     └──────────────┘
                                                  │
                                                  ▼
                                          ┌──────────────┐
                                          │ Git 提交      │
                                          │ 进入修复流程   │
                                          └──────────────┘
```

## 评审维度（4 SubAgent 并行）

| SubAgent | 评审维度 | 检查重点 |
|----------|----------|----------|
| SubAgent 1 | 引用一致性 | 文件路径、文件名引用的准确性 |
| SubAgent 2 | 流程逻辑矛盾 | Ralph Loop、Git 规范、测试覆盖率等 |
| SubAgent 3 | 内容完整性 | Frontmatter、必填字段、格式规范 |
| SubAgent 4 | 版本状态追踪 | 版本号、日期、里程碑状态 |

## 额外评审维度（扩展）

| SubAgent | 评审维度 | 检查重点 |
|----------|----------|----------|
| SubAgent 5 | 内容重复检查 | 跨文件内容重复、章节重叠 |
| SubAgent 6 | Agent 运行逻辑 | 流程可执行性、约束有效性、防幻觉 |
| SubAgent 7 | 精简优化 | 冗余内容、过度设计、可合并项 |

## 评审步骤

### Step 1: 输入阶段

1. **确定评审范围**：
   - 目录：`pm/`
   - 文件：全部 `.md` 文件

2. **收集文件列表**：
   ```bash
   ls pm/*.md
   ```

3. **设定评审重点**（根据需求调整）：
   - 基础检查：引用、格式、完整性
   - 扩展检查：重复、逻辑、精简

### Step 2: 评审阶段

启动 4-7 个 SubAgent 并行执行：

```
SubAgent 1: 引用一致性检查
SubAgent 2: 流程逻辑矛盾检查
SubAgent 3: 内容完整性检查
SubAgent 4: 版本状态追踪检查
SubAgent 5: 内容重复检查（扩展）
SubAgent 6: Agent 运行逻辑检查（扩展）
SubAgent 7: 精简优化检查（扩展）
```

### Step 3: 输出阶段

1. **汇总问题**：
   - 合并所有 SubAgent 报告
   - 按优先级分类（P0/P1/P2）

2. **生成 REVIEW.md**：
   - 格式：`agent-output/drafts/docs/REVIEW.md`
   - 包含：问题汇总、修复建议、优先级

3. **Git 提交**：
   ```bash
   git add agent-output/drafts/docs/REVIEW.md
   git commit -m "docs: 评审 [范围] 发现 X 个问题"
   ```

## 防幻觉约束设计

### 核心原则

**让错误无法隐藏，让遗漏被发现**

| 约束类型 | 约束方法 | 防幻觉机制 |
|----------|----------|------------|
| 引用验证 | 交叉引用检查 | 文件存在性 100% 验证 |
| 流程闭环 | 步骤首尾相连 | 起点=终点验证 |
| 数据完整 | Frontmatter 校验 | 必填字段清单 |
| 逻辑一致 | 版本号追踪 | 时间线一致性 |
| 重复检测 | 内容指纹 | 相似度 > 80% 报警 |

### 约束实现

```markdown
## 引用验证清单
- [ ] 每引用必存在
- [ ] 相对路径转换正确
- [ ] 文件名大小写匹配

## 流程闭环检查
- [ ] 流程步骤 N 的终点 = 步骤 1 的起点
- [ ] 无孤立步骤
- [ ] 无循环依赖

## Frontmatter 必填字段
- [ ] title
- [ ] version
- [ ] created
- [ ] updated
- [ ] author

## 逻辑一致性
- [ ] 版本号递增
- [ ] 日期顺序正确
- [ ] 里程碑状态与日期匹配
```

## 执行命令

```bash
# 启动评审
./review-workflow.sh pm/

# 参数：评审目录
# 输出：agent-output/drafts/docs/REVIEW.md
```

## 质量门禁

评审报告必须通过以下检查才能提交：

- [ ] 引用路径 100% 存在验证
- [ ] 版本号/日期无矛盾
- [ ] 问题按优先级分类
- [ ] 修复建议可执行
- [ ] 无"可能、大概、应该"等模糊表述
