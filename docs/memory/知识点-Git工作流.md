# 知识点：Git 工作流

> 双轨制 Git 工作流的核心原则与实践

---

## 场景：AI 自主开发如何引入人类审查

**问题**：AI 自转开发时，人类看不到进度，容易方向偏离，或者最后一次性审查大量代码难以发现问题。

**方案**：双轨制 - 小提交持续保存进度，PR 引入人类审查

```
小提交（本地） → 定期 Push → Draft PR（AI自转） → 正式 PR（人类审查） → 人工合并
```

---

## 核心原则

| 层级 | 操作 | 频率 | 可见性 | 目的 |
|------|------|------|--------|------|
| **小提交** | `git commit` | 每完成一个设计决策 | 本地（之后push） | 保存进度、方便回滚 |
| **推送** | `git push` | 每日/重要节点 | 远程分支 | 备份、让CI运行 |
| **Draft PR** | Create PR | 创建分支时 | 人类可见进度 | 不阻塞、可提前发现问题 |
| **正式 PR** | Ready for review | 功能完成 | 人类审查 | 请求合并、质量把关 |
| **人工合并** | `merge` | 审查通过后 | 进入主分支 | **只有人类能执行** |

---

## Draft PR vs 正式 PR

| 类型 | 创建时机 | 状态 | AI 权限 | 人类角色 |
|------|---------|------|---------|----------|
| **Draft PR** | 创建分支时 | WIP（进行中） | **自转**（继续开发） | 旁观进度、轻量反馈 |
| **正式 PR** | 功能完成后 | Ready for review | **等待**（修改请求） | **审查+批准**（LGTM） |

---

## 小提交粒度

**原则**：每个设计决策 → 一个 commit

```bash
# 架构设计完成
git commit -m "docs: 7层架构设计 [architecture/7-LAYER.md]"

# SPEC 设计完成
git commit -m "docs: SignalPool 规格 [specs/SPEC-201.md]"

# 单个函数实现
git commit -m "feat: 实现信号注册 [signal-pool.ts]"

# 测试用例
git commit -m "test: 信号池单元测试 100% 覆盖"
```

---

## 人类不响应的处理

| 阶段 | 策略 | 说明 |
|------|------|------|
| **Draft PR** | AI 自转继续开发 | 不阻塞，人类有空再看 |
| **正式 PR** | 等待 + 友好提醒 | 尊重人类时间，不自动合并 |
| **超时** | N 小时后提醒一次 | 不强制，人类掌握最终决策权 |

---

## 关键记忆点

1. **有功能就有 PR** - 创建分支即提 Draft PR
2. **人类掌握合并权** - 只有人类能点 merge，AI 只能请求
3. **Draft 自转，正式等待** - 区分两个阶段的行为模式
4. **小步提交，定期推送** - 保持进度可见，方便回滚
