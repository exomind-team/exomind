## 1. 用户需求

### 1.1 问题描述
用户首次使用 exomind 时，需要一个唯一身份标识用于设备间通讯和消息同步。

### 1.2 使用场景
- 场景1：用户首次安装应用，系统自动生成唯一身份
- 场景2：用户重装应用，需要恢复或重新生成身份

### 1.3 期望行为
- 自动生成唯一身份，无需手动注册
- 身份本地存储，重装可恢复
- 身份格式：16 字符十六进制字符串

---

## 2. 功能定义

### 2.1 输入

| 参数名 | 类型 | 必需 | 默认值 | 描述 |
|--------|------|------|--------|------|
| 无 | - | - | - | 自动生成，无需输入 |

### 2.2 输出

| 参数名 | 类型 | 描述 |
|--------|------|------|
| userId | string | 16 字符十六进制字符串 |

### 2.3 处理逻辑
```
用户首次启动
    ↓
检查本地存储是否有 userId
    ↓ 是 → 返回存储的 userId
    ↓ 否
生成随机 16 字节
    ↓
转换为 32 字符十六进制
    ↓
保存到本地存储
    ↓
返回 userId
```

## 7. 架构设计

### 7.1 类设计

```typescript
interface UserIdentity {
  /** 获取用户 ID，如果不存在则生成 */
  getUserId(): Promise<string>;

  /** 检查用户 ID 是否存在 */
  hasUserId(): Promise<boolean>;

  /** 生成新的用户 ID（会覆盖旧的） */
  generateNewId(): Promise<string>;

  /** 获取用户 ID 的可读格式 (XXXX-XXXX-XXXX-XXXX) */
  getFormattedId(): Promise<string>;
}
```

### 7.2 数据流

```
getUserId()
    ↓
读取本地存储
    ↓
存在 → 返回
不存在 → generateRandomId() → 保存 → 返回
```

### 7.3 状态变化

```
UNINITIALIZED → (首次启动) → STORED → (每次读取) → RETURNED
```
